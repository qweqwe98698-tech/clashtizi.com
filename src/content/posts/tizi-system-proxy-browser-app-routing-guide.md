> **【💡 30 秒看懂：System Proxy 到底管哪些流量？】**
> - **System Proxy 不是“全盘接管”**：它只是操作系统向应用程序提供的一组**代理配置建议（如 `127.0.0.1:7890`）**；
> - **谁会听系统代理？** Chrome、Edge、Safari 等标准浏览器及部分桌面 App，在发起网络请求前会主动读取该设置，并将流量发往本地客户端 Core；
> - **谁会无视系统代理？** 外服游戏、Git/CMD 命令行、以及拥有独立网络栈的特定软件，它们直接向物理网卡发起裸 TCP/UDP 连接，**这就是“浏览器能上外网但游戏/终端完全没网”的根本原因**。

## 一、核心概念辨析：System Proxy、Browser Proxy、TUN 与 PAC

在排查应用网络时，必须明确以下 6 个维度的定位与差异：

| 核心技术术语 | 运行所处层级 | 核心解决的问题 | 典型认知误区纠偏 |
| :--- | :--- | :--- | :--- |
| **System Proxy (系统代理)** | 操作系统应用层全局配置 | 为支持系统代理的应用提供统一本地端口入口 | ❌ 并不是开启后电脑所有软件都会自动走代理 |
| **Browser Proxy (浏览器独立代理)** | 浏览器进程内部或扩展插件层 | 允许浏览器脱离系统全局设置单独配置代理 | ❌ 浏览器代理插件无法代理电脑里的其他软件 |
| **Local Proxy Port (本地监听端口)** | 客户端 Core 绑定的本机端口 (如 7890) | 作为本地应用连接代理内核的通信枢纽 | ❌ 不是远端机场服务器的端口，而是本机端口 |
| **TUN 模式 (虚拟网卡)** | **操作系统网络层（Layer 3 IP）** | **强行接管全系统所有进程的 TCP/UDP 流量** | 适用于游戏、命令行等不遵循系统代理的场景 |
| **PAC 模式 (自动代理脚本)** | 操作系统或浏览器脚本解析层 | 根据 `.pac` 脚本规则在应用层决定是否直连 | 规则由脚本执行，现代客户端已全面转向 Core 规则 |
| **Rule 模式 (核心规则分流)** | 代理内核 Core 内部引擎 | 流量进入客户端后，智能决定走海外节点还是国内直连 | 与 System Proxy 完美共存，互不冲突 |

## 二、为什么“节点测速全绿”，浏览器却依然上不去外网？

很多新手常问：“客户端里所有节点延迟都是 100ms 绿色，为什么打开 Google 还是提示无法连接？”

```text
 1. 【节点测速由 Core 独立发起】：
    - 当你点击测速按钮时，是代理客户端内核 (Core) 自己直接向海外节点发起的探测，
      这个过程【完全不需要开启系统代理】！

 2. 【浏览器流量尚未接入客户端】：
    - 如果你没有勾选客户端的【系统代理 (System Proxy)】开关，或者浏览器被第三方扩展拦截，
      浏览器的请求根本没有发送给本机的 `127.0.0.1:7890` 端口，依然在走国内物理宽带直连！
```

- **极速排查自检**：确认客户端界面的【System Proxy / 系统代理】开关已处于开启状态，且系统设置中的代理端口与客户端一致。

## 三、主流浏览器与特定软件的代理行为全景拆解

各大常用软件在处理系统代理时的逻辑存在显著差异：

| 应用程序分类 | 对 System Proxy 的支持行为 | 典型软件代表 | 常见故障与排障建议 |
| :--- | :--- | :--- | :--- |
| **系统级标准浏览器** | 🟢 **100% 默认遵循系统代理** | Google Chrome, Microsoft Edge, Safari | 若安装了第三方代理插件，可能发生代理控制权冲突 |
| **独立代理机制浏览器** | 🟡 **支持自定义独立代理策略** | Mozilla Firefox | 需在 Firefox 设置中确认勾选【使用系统代理设置】 |
| **外服游戏与对战平台** | ❌ **完全无视系统代理（使用裸 UDP）** | Steam 游戏联机, 暴雪战网, EA App | **必须在客户端中开启 [TUN 虚拟网卡模式](/tizi/tun/)** |
| **开发与命令行工具** | ❌ **默认不读取系统注册表代理** | Git Bash, Windows CMD, PowerShell, npm | 需手动配置 `HTTP_PROXY` 环境变量或直接开启 TUN |
| **Electron 桌面应用** | 🟡 **部分遵循、部分依赖独立配置** | Discord, Telegram, VS Code | 多数支持系统代理，特定语音通信模块需 TUN 接管 |

## 五、经典故障排查：“系统代理残留”导致退出梯子后全网瘫痪

这是翻墙中最臭名昭著的经典问题：“**明明把梯子软件关了，电脑突然连百度都打不开了！**”

```text
                               【系统代理残留故障演进过程】

 1. 正常运行中 ──► 系统代理配置：[开启] ──► 指向 127.0.0.1:7890 (客户端 Core 正常监听)
 2. 软件异常闪退 / 强制关机 ──► 客户端未来得及向操作系统注销代理配置
 3. 结果：系统代理依然指向 127.0.0.1:7890 ──► 但本地 Core 已停止运行 ──► 所有浏览器彻底断网！
```

### 10 秒极速修复标准 SOP：
1. 按快捷键 `Win + I` 打开 Windows【设置】；
2. 依次点击【网络和 Internet】──►【代理】；
3. 在【手动设置代理】栏目下，**将【使用代理服务器】开关彻底关闭**，点击保存即可瞬间恢复！

## 六、System Proxy 七层故障排查诊断模型

遇到开启 System Proxy 后无法上网，按以下顺序排查：

```text
 Layer 1: 客户端监听层 ──► 确认客户端已启动且 `Mixed-Port` (如 7890) 正常处于监听状态
    ↓
 Layer 2: 系统注册表层 ──► 检查 Windows 代理设置是否已成功写入 `127.0.0.1:7890`
    ↓
 Layer 3: 浏览器冲突层 ──► 停用 Chrome 中可能冲突的第三方代理切换扩展（如 SwitchyOmega）
    ↓
 Layer 4: 节点连通性层 ──► 在客户端内点击节点延迟测速，排除海外服务器端宕机
    ↓
 Layer 5: 分流规则匹配 ──► 切换为 [Global 全局模式](/clash-verge-rev/)，排除 Rule 规则库语法错误
    ↓
 Layer 6: 本地防火墙层 ──► 确认 Windows Defender 未将客户端的本地代理端口阻断
    ↓
 Layer 7: 应用适配层 ──► 若仅特定游戏/终端不走代理，开启 [TUN 模式](/tizi/tun/) 强制接管
```

## 七、关于 System Proxy 的 15 大高频认知误区

```text
 ❌ 误区 1：开启 System Proxy 就等于开启了“全局代理”，电脑所有流量都会走国外。(错！仅限主动读取的软件)
 ❌ 误区 2：节点测速全绿说明我的浏览器已经成功连上外网了。(错！测速由 Core 完成，浏览器可能未走代理)
 ❌ 误区 3：System Proxy 会把电脑里所有软件的密码明文发送给代理服务器。(错！HTTPS 端到端强加密)
 ❌ 误区 4：关闭梯子软件后连百度都打不开，说明我的电脑网卡被病毒烧坏了。(错！只是系统代理未注销)
 ❌ 误区 5：在 Chrome 里装了代理扩展，整个电脑里的命令行工具也会跟着走代理。(错！扩展仅限浏览器内部)
 ❌ 误区 6：Firefox 浏览器永远不可能遵循 Windows 的系统代理设置。(错！Firefox 设置中可配置系统代理)
 ❌ 误区 7：玩外服吃鸡或 Steam 联机游戏，只要开着 System Proxy 延迟就会降低。(错！游戏根本不走系统代理)
 ❌ 误区 8：System Proxy 里的 127.0.0.1 是机场位于美国的机房服务器 IP。(错！127.0.0.1 是你自己的电脑本机)
 ❌ 误区 9：开启 System Proxy 会导致局域网里的打印机和 NAS 彻底失联。(错！局域网通信默认直接直连)
 ❌ 误区 10：可以在 Windows 环境变量里永久写死 `HTTP_PROXY` 且永远不删。(错！关闭梯子后终端会报错断网)
 ❌ 误区 11：System Proxy 和 TUN 模式绝对不可能在同一台电脑上同时开启。(错！现代客户端支持双轨协同)
 ❌ 误区 12：企业网络管理员无法查出员工电脑开启了本地 System Proxy。(错！企业网关依然能监控异常流量)
 ❌ 误区 13：在 System Proxy 模式下，访问国内淘宝也会绕道美国导致变慢。(错！分流规则会自动放行直连)
 ❌ 误区 14：只要把系统代理关掉，刚才访问外网留下的痕迹就会全部消失。(错！浏览器 Cookie 与历史依然在)
 ❌ 误区 15：手机上没有“系统代理”开关说明手机无法使用梯子。(错！移动端采用更高级的系统级 VPN 接口)
```

## 八、常见问题解答 (FAQ)

### Q1：梯子里的 System Proxy (系统代理) 到底是什么意思？
**答**：它是操作系统提供的一套应用层代理配置机制。开启后，客户端会将操作系统的代理服务器指向本地监听端口（如 `127.0.0.1:7890`），支持该设置的软件会将网络请求统一发送给客户端进行转发。

### Q2：为什么开启了系统代理，浏览器能上外网，但游戏和命令行依然不行？
**答**：因为游戏和命令行工具直接调用底层网络接口，代码中没有设计“读取系统代理”的逻辑。对于这类非代理软件，必须在客户端中开启 [TUN 虚拟网卡模式](/tizi/tun/) 强制接管。

### Q3：关闭梯子软件后，电脑连国内网站都打不开了怎么解决？
**答**：这是经典的“系统代理残留”。按 `Win+I` 打开系统【设置】──►【网络和 Internet】──►【代理】，手动将【使用代理服务器】开关彻底关闭即可秒级恢复。

### Q4：为什么有时候节点测速全是绿色，但浏览器依然打不开任何外网？
**答**：因为节点测速是由客户端内核 (Core) 独立执行的；如果客户端界面的【System Proxy】开关未打开，或者浏览器安装了冲突的代理插件，浏览器的流量根本没有送入代理内核。

### Q5：Firefox 浏览器为什么打不开外网，但 Chrome 却完全正常？
**答**：Firefox 拥有独立的代理配置模块。进入 Firefox【设置】──► 搜索【网络设置】──► 勾选【使用系统代理设置】即可与 Chrome 保持同步。

### Q6：System Proxy 和 Global (全局模式) 是一回事吗？
**答**：完全不是。System Proxy 决定的是“哪些软件的流量会进入客户端”；而 Global 模式决定的是“流量进入客户端后，是否强制全部发往海外代理节点”。

### Q7：什么是本地代理端口？7890 是机场的端口吗？
**答**：不是。`7890`（或混合端口）是代理客户端在你自己的电脑上开放的本地监听端口，用于接收本机软件发来的网络数据，与远端机场服务器无关。

### Q8：日常查资料看视频，用 System Proxy 还是 TUN 模式更好？
**答**：日常使用首选 **System Proxy**，其系统资源消耗极低、轻量省电，且完全不影响家庭局域网设备通信；仅在玩外服游戏或使用终端命令行时才需开启 TUN。

### Q9：在 Windows 命令行中怎么临时让终端走代理？
**答**：在终端中临时执行命令 `set http_proxy=http://127.0.0.1:7890` 和 `set https_proxy=http://127.0.0.1:7890` 即可（当前窗口关闭后自动失效，安全无残留）。

### Q10：什么是 PAC 模式？它和现在的 Rule 规则模式有什么区别？
**答**：PAC 是在操作系统层面通过 `.pac` 脚本决定是否连接本地代理；而现代 Rule 模式是在代理内核内部通过海量规则库进行高精度分流，性能与精细度远超传统 PAC。

### Q11：开启 System Proxy 会导致国内微信或钉钉变卡吗？
**答**：不会。在【Rule 规则模式】下，代理内核会自动识别国内应用并将其分配走本地物理网卡直连，不会绕道海外节点。

### Q12：为什么有时候在 Wi-Fi 属性里修改了代理，换个 Wi-Fi 就失效了？
**答**：在某些操作系统（如 macOS）中，代理设置是与具体的网络适配器（Wi-Fi 或有线网卡）独立绑定的，切换网络后需确认客户端已重新写入新网卡的代理配置。

> **【💡 30 秒极速直接答案：规则模式失效核心定性与四大排障原则】**
> - **第一核心定性**：**“Global (全局模式) 能秒开网页，切回 Rule (规则模式) 就打不开，是网络排障中最具价值的黄金信号！”** 它 100% 证实你的**节点完全健康、加密隧道完全通畅、客户端内核完全存活**！问题 100% 锁死在**“分流规则漏判被当作国内直连放行、策略组选了失效节点、或规则从上到下匹配顺序颠倒”**；
> - **四类最常见 Rule 模式故障与对号入座解法**：
>   1. **在客户端【连接 (Connections)】里看到该网站显示为【Direct (直连)】** ──► 属于**该域名被国内规则（如 `GEOIP,CN`）抢先误判直连** ──► 自定义规则顶部添加 `DOMAIN-SUFFIX,目标域名.com,PROXY`；
>   2. **连接面板显示为【Proxy】，但请求持续标红超时** ──► 属于**分流规则命中的【策略组 (Proxy Group)】内部选到了红色死节点** ──► 手动切换策略组固定节点；
>   3. **所有海外网站在 Rule 模式下全部打不开** ──► 属于**末尾 `MATCH` 兜底规则失效，或远程 `Rule Provider` 规则集拉取失败变为空白** ──► 手动更新规则集；
>   4. **访问特定海外平台频繁触发异地登录风控** ──► 属于**策略组开启了 `URL-Test` 或 `Load-Balance` 导致节点频繁跳变** ──► 策略组改选为手动 `Select` 固定节点。

## 三、黄金诊断准则：“先看连接命中，再动手改规则”

遇到 Rule 打不开，切忌盲目乱抄网上的神仙规则集，先看数据包真实流向：

```text
 1. 【不可省略的 10 秒抓包诊断】：
    - 打开 Clash Verge Rev 的【连接 (Connections)】或 v2rayN 控制台日志；
    - 在浏览器中刷新那个打不开的网页；
    - 在列表中搜索该网页的域名，查看“命中规则 (Rule)”和“目标策略 (Destination)”：

 2. 【四种抓包结果精准定性】：
    - 【状态 1：显示为 DIRECT (直连)】：100% 证实该域名被国内规则误伤直连！在规则最顶部补上该域名即可；
    - 【状态 2：显示为 REJECT (拒绝)】：100% 证实被广告拦截规则误伤！在白名单中添加放行；
    - 【状态 3：显示为 PROXY 但标红超时】：分流规则完全正确，纯粹是该策略组当前选中的节点已断网；
    - 【状态 4：完全没有任何连接记录】：该软件不走系统代理，开启【TUN 模式】接管。
```

## 四、致命根因一：规则从上到下（Top-Down）匹配顺序颠倒

这是新手编写自定义分流规则最容易犯的逻辑错误：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【规则引擎自上而下匹配铁律】                                  │
 ├─────────────────────────────────────────────────────────────────────────────────────────────┤
 │ 🚨 【典型翻车代码范例 (错误示范)】：                                                       │
 │   - GEOIP,CN,DIRECT              <-- 第一行：只要是国内 IP 全部直连放行                     │
 │   - DOMAIN-SUFFIX,openai.com,PROXY <-- 第二行：OpenAI 走代理 (永远无法执行到此行!)          │
 │                                                                                             │
 │ ⚠️ 【为什么第二行会失效？】：                                                               │
 │   - 当你访问 `openai.com` 时，本地 DNS 若解析到了国内某 Anycast IP；                        │
 │   - 第一行 `GEOIP,CN` 率先匹配成功并立即退出判定，直接以 DIRECT 直连放行，导致网页打不开！  │
 │                                                                                             │
 │ 🟢 【标准修复代码范例 (正确写法)】：                                                       │
 │   - DOMAIN-SUFFIX,openai.com,PROXY <-- 精确域名规则必须强制置顶！                          │
 │   - DOMAIN-KEYWORD,google,PROXY                                                             │
 │   - GEOIP,CN,DIRECT                <-- 粗粒度的地理 IP 规则必须放在中后部                   │
 │   - MATCH,PROXY                    <-- 最后的兜底规则放最末尾                               │
 └─────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 五、致命根因二：策略组 (Proxy Group) 内部选到了死节点

规则仅仅负责将流量“指路”给某个策略组，真正的出海质量取决于策略组内部的节点：

```text
 1. 【策略组死锁表现】：
    - 规则判定 `YouTube.com` 命中【节点选择】策略组；
    - 但打开客户端的【代理】面板查看【节点选择】策略组，发现当前选中的是一个已经报 `-1` 或 `Timeout` 的红色失效节点；
    - 表现：Global 模式下手动挑了绿色节点能用，切回 Rule 模式策略组由于选了死节点瞬间断网！

 2. 【解决办法】：
    - 进入客户端【代理】界面，逐一检查【节点选择】、【PROXIES】、【漏网之鱼】等策略组；
    - 手动点击一个测试有绿色低延迟的可用专线节点，将其固定选中即可。
```

## 六、致命根因三：Rule Provider 远程规则集拉取失败变为空白

现代客户端广泛使用远程规则集（Rule Provider），但远程同步存在风险：

```text
 1. 【规则集空白故障】：
    - 当客户端首次启动或定时更新时，向 GitHub 拉取 `reject.yaml` 或 `proxy.yaml` 规则集；
    - 若当时网络波动导致拉取超时，客户端内部的规则列表会变成空数组；
    - 此时所有流量全部滑落至最后的 `MATCH` 兜底规则，导致分流逻辑全线紊乱！

 2. 【一键强制刷新】：
    - 在 Clash Verge Rev 或小火箭中，找到【Rule Providers (规则集)】；
    - 点击右侧的【刷新 (Update)】小图标，观察文件大小是否恢复为几十 KB/MB。
```

## 九、常见问题解答 (FAQ)

### Q1：为什么 Global (全局模式) 能正常上网，切回 Rule (规则模式) 就打不开网页？
**答**：**这是网络完好、纯属分流规则问题的最高价值信号！** 常见原因包括：①该海外网站的域名未被规则库收录，被漏判为国内直连；②规则从上到下顺序写反，`GEOIP,CN` 抢先直连；③分流规则命中的策略组内部选到了超时失效的红色节点。

### Q2：如何知道某个打不开的网页到底命中了哪一条分流规则？
**答**：打开客户端的【连接 (Connections)】或日志面板，在浏览器中刷新该网页。在列表中找到目标请求，查看其标记的规则名（Rule）与出站策略（Destination），若显示为 `DIRECT` 说明被误判直连，若显示 `PROXY` 但标红说明策略组选错了节点。

### Q3：如何为打不开的小众海外网站手动添加代理规则？
**答**：在客户端自定义规则（或 Merge 扩展配置）的最顶部添加精确域名规则：`DOMAIN-SUFFIX,目标网站域名.com,PROXY`（例如 `DOMAIN-SUFFIX,notion.so,PROXY`）；保存并刷新配置即可秒级生效。

### Q4：为什么访问部分网站时频繁跳出“异地登录”或“人机验证”？
**答**：因为你的策略组开启了 **`URL-Test (自动测速)`** 或 **`Load-Balance (负载均衡)`**，导致每次请求由不同国家的节点交替发出，触发了目标平台的安全风控；在策略组中切换为手动 **`Select`** 固定单个稳定节点即可。

### Q5：什么是 MATCH 兜底规则？
**答**：`MATCH` 是分流规则列表最末尾的一条终极兜底规则（如 `MATCH,PROXY` 或 `MATCH,DIRECT`）。当数据包遍历了前面所有域名和 IP 规则均未命中时，系统将统一按照 MATCH 所指定的策略组进行出站。

### Q6：为什么修改了自定义规则之后，刷新网页依然打不开？
**答**：通常是因为浏览器或系统内部存在旧的 DNS 与 TCP 连接缓存；在 CMD 中执行 `ipconfig /flushdns` 刷新系统 DNS 缓存，并关闭浏览器标签页重新打开即可。

### Q7：开启 TUN 模式后，Rule 规则分流依然有效吗？
**答**：**完全有效！** TUN 模式只是在更底层的网络层（Layer 3）负责将所有流量捕获并送入客户端内核，数据包进入内核后依然会严格按照 Rule 规则从上到下进行分流判定。

### Q8：遇到规则模式失效，最忌讳的操作是什么？
**答**：最忌讳“盲目去网上到处乱抄几十万条未经验证的臃肿规则集”。这会导致规则库冲突混乱、内存暴涨甚至死锁；按照“临时切 Global 验证 ──► 连接面板抓包 ──► 顶部精准补写”三步法即可彻底解决。

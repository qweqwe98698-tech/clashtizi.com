> **【💡 30 秒极速决策：你到底需不需要开启 TUN 模式？】**
> - **核心技术断言**：**TUN 模式绝对不是“更高级的全局代理”！** TUN 仅决定“流量怎么进入客户端（入口层）”，而 Rule/Global 决定“流量进入后怎么走（策略层）”。平时上网看视频，普通的 [System Proxy 系统代理](/tizi/system-proxy/) 就完全够用且最省电；
> - **两分钟判断准则**：
>   - 🟢 **无需开启 TUN**：日常仅用 Chrome/Edge 浏览器、查资料、看 YouTube 追剧、微信办公（系统代理即可完美胜任）；
>   - 🔵 **必须开启 TUN**：玩 Steam/Epic 外服联机游戏（依赖裸 UDP 数据包）、在终端运行 Git/Docker/npm、使用不支持代理设置的独立客户端；
>   - ⚠️ **开 TUN 后断网第一自查**：90% 是 Windows 服务模式未安装、与其他 VPN 虚拟网卡冲突，或未开启【Bypass LAN】导致局域网死锁。

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                         【流量接管层级：System Proxy vs TUN 虚拟网卡】                       │
 ├─────────────────────────────────────────────────────────────────────────────────────────────┤
 │ 方案 A：【System Proxy (系统代理)】──► 仅向操作系统注册 127.0.0.1:7890 本地端口             │
 │          └──► 仅接管主动读取系统代理的浏览器与常规 App（轻量、低开销、零网卡驱动依赖）       │
 ├─────────────────────────────────────────────────────────────────────────────────────────────┤
 │ 方案 B：【TUN 模式 (虚拟网卡)】──────► 在网络层创建虚拟网卡 (如 Wintun 适配器)               │
 │          └──► 全量劫持系统所有 TCP/UDP 数据包送入 Mihomo Core（支持游戏、终端与裸协议）     │
 ├─────────────────────────────────────────────────────────────────────────────────────────────┤
 │ 流量送达内核后：统一交给 【Rule 规则分流】 或 【Global 全局模式】 执行最终出站路线           │
 └─────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 一、System Proxy vs TUN 模式深度对比决策表

| 对比维度 | System Proxy (系统代理) | TUN 模式 (虚拟网卡) |
| :--- | :--- | :--- |
| **底层接管机制** | 操作系统网络设置中写入本地 HTTP/SOCKS 代理端口 | 操作系统网络协议栈中创建虚拟网卡驱动并接管路由 |
| **应用覆盖范围** | 仅覆盖遵循桌面系统代理的浏览器与标准应用 | **全电脑所有应用（包括外服游戏、终端命令行）** |
| **UDP 协议支持** | 较弱，普通系统代理接口无法捕获底层裸 UDP 包 | **原生完美支持全量 UDP 与游戏低延迟对局** |
| **系统权限要求** | 普通用户权限即可随时开关 | **需要系统管理员权限或预先安装服务模式 (Service)** |
| **局域网 NAS 影响** | 几乎零影响，私有 IP 默认直连 | ⚠️ 若未勾选 Bypass LAN 易引发局域网设备失联 |
| **系统资源消耗** | 极低，无额外驱动运算开销 | 略高，需内核处理所有数据包的二/三层封包解包 |
| **新手推荐指数** | 🟢 **推荐作为日常默认基线开启** | 🔵 **按需开启，打游戏或跑代码时再启用** |

## 三、各操作系统平台开启 TUN 模式与权限配置步骤

### 1. Windows 11 / 10 平台配置流程
1. **安装服务模式 (Service Mode)**：
   - 打开 Clash Verge Rev，进入左侧【设置 (Settings)】面板；
   - 找到【服务模式 (Service Mode)】选项。若显示未安装，点击其右侧的【安装 (Install)】图标；
   - 系统将弹出 UAC 管理员提权弹窗，点击【是】允许安装。安装成功后服务模式图标变为高亮绿色。
2. **启用 TUN 模式**：
   - 在设置面板中找到【TUN 模式 (Tun Mode)】开关，点击打开；
   - 检查控制面板网络适配器，会发现系统新增了一个虚拟适配器（通常基于 Wintun 驱动）。

### 2. macOS 平台配置流程
1. 进入【设置】面板开启【TUN 模式】开关；
2. 系统会弹出“网络扩展 (Network Extension)”授权申请，输入 Mac 开机密码允许添加；
3. 打开 Mac 的【系统设置】──►【网络】──►【VPN 与过滤器】，确保 Clash Verge 的网络扩展处于已允许状态。

### 3. Linux 平台配置流程
- Linux 环境下 TUN 设备创建需提升网络能力权限：
  ```bash
  sudo setcap cap_net_admin,cap_net_bind_service=+ep /path/to/clash-verge
  ```
- 或使用官方文档推荐的 systemd 提权守护进程运行，确保普通用户即可免密码启动虚拟网卡。

## 四、核心概念辨析：TUN $\neq$ Global！

很多新手最容易陷入的认知误区是把 TUN 误当成“强制全局翻墙”：

```text
                               【二维解耦决策模型】
 
 维度 1：流量怎么进内核 (Ingress) ──► 选【System Proxy】还是【TUN】？
 维度 2：进内核后怎么分流 (Egress) ──► 选【Rule 规则】还是【Global 全局】？
 
 组合 A：【TUN + Rule】(黄金推荐组合！)
 ──► 全电脑所有软件（包括游戏）全部被接管进内核，但国内百度、微信依然走本地直连，海外流量走代理！
 
 组合 B：【TUN + Global】(极端排障测试)
 ──► 全电脑所有软件全量绕道海外单一节点，国内网站速度暴跌，仅用于排障验证，严禁日常开启！
```

## 五、开启 TUN 模式后怎么确认真的生效了？

不能只看设置面板里的开关是否亮着，请按以下三步验证：

```text
 1. 【在 Connections 面板中观察实时流量】：
    - 启动那个原本不走代理的软件（如 Steam 客户端或 Git 命令）；
    - 打开 Clash Verge Rev 左侧的【连接 (Connections)】监控；
    - 观察列表中是否跳出了该目标进程的 IP 或域名连接记录。若有，证实 TUN 已成功接管！

 2. 【检查请求匹配的规则与出口】：
    - 在连接详情中确认该应用命中的是 `Rule` 还是 `Direct`，以及最终走的是哪个代理节点。

 3. 【测试外服游戏联机延迟】：
    - 进入外服游戏大厅，查看对局延迟由无法连接变为稳定的几十毫秒，证实 UDP 转发通畅。
```

## 六、开启 TUN 模式后完全没网排障指南

若点击开启 TUN 之后，电脑所有网页突然全部打不开：

| 故障具体表现 | 核心诱发诱因 | 针对性修复建议 |
| :--- | :--- | :--- |
| **TUN 开关打开后瞬间自动弹回关闭** | 未安装服务模式，或权限不足无法创建虚拟网卡 | 在设置中点击安装【服务模式】，或右键以管理员身份运行客户端 |
| **TUN 开启成功，但所有网页提示断网** | 虚拟网卡路由表冲突，或本地防火墙拦截了适配器 | 重启客户端核心，检查网络适配器中是否有残余的失效 VPN 网卡 |
| **网页能打，但局域网 192.168 / NAS 失联** | TUN 网卡错误劫持了私有网段与 mDNS 多播 | 勾选【Bypass LAN (绕过局域网)】并将私网网段设为 Direct |
| **System Proxy 正常，切 TUN 就断网** | TUN 内部的 DNS 劫持与系统 DNS 解析器死锁 | 检查客户端 DNS 配置，清空 Fake-IP 缓存并开启正确的引导 DNS |
| **电脑同时开着另一个加速器或 VPN 软件** | 两个软件的虚拟网卡争抢 0.0.0.0/0 默认网关 | 彻底退出其他网络代理或游戏加速软件，重置网络栈 |

## 七、TUN 与 DNS、Fake-IP 及 IPv6 协同工作机制

```text
 1. 【DNS 劫持 (DNS Hijack) 的技术本质】：
    - 开启 TUN 后，客户端会将系统的 53 端口 DNS 请求强行捕获并送入 Mihomo Core 处理；
    - 这是代理软件防止 DNS 污染的标准防御手段，不代表恶意劫持，无需恐慌。

 2. 【看到 198.18.x.x 虚拟 IP 属于正常现象】：
    - TUN 模式深度依赖 [Fake-IP 机制](/tizi/fake-ip/)。ping 域名时返回 `198.18.0.1` 是内核在内存中建立的映射字典，只要网页能打开就是正常运行。

 3. 【IPv6 双栈网络兼容准则】：
    - 若本地网络支持 IPv6，需确保客户端开启了 IPv6 路由接管；若出现海外网站因 IPv6 裸连导致卡死，参考 [《梯子IPv6与代理兼容指南》](/tizi/ipv6/) 开启 IPv4 优先。
```

## 九、关于 TUN 模式的 15 大核心认知误区

```text
 ❌ 误区 1：TUN 模式是高级功能，所以平时上网应该无脑一直开着 TUN。(错！无特殊需求只会徒增网卡开销)
 ❌ 误区 2：开启 TUN 模式就等于开启了 Global 全局模式。(错！TUN 是入口，策略组仍可保持 Rule 智能分流)
 ❌ 误区 3：玩所有的外服游戏都必须强行开启 TUN 模式才能加速。(错！部分游戏仅需普通节点或网页分流即可)
 ❌ 误区 4：TUN 模式开启后，网速和下载带宽会自动翻倍。(错！下载速度取决于节点物理带宽，与虚拟网卡无关)
 ❌ 误区 5：开启 TUN 模式后局域网 NAS 就绝对无法访问了。(错！只要正确勾选 Bypass LAN 即可完美共存)
 ❌ 误区 6：去网上搜索下载第三方的“Wintun 万能修复补丁”能加速网络。(错！极易被植入恶意后门木马)
 ❌ 误区 7：TUN 开关只要亮着，就代表全电脑 100% 的流量绝对都走了代理。(错！被规则判为 Direct 的流量仍走直连)
 ❌ 误区 8：在两款不同的翻墙软件里同时开启 TUN 模式能实现双重加密。(错！会导致底层路由表死锁全网断网)
 ❌ 误区 9：开启 TUN 模式后电脑断网，第一反应是把系统防火墙彻底卸载。(错！防火墙不会拦截正常的 Wintun 驱动)
 ❌ 误区 10：为了解决 TUN 模式下的网络冲突，必须在电脑里永久关闭 IPv6。(错！在客户端正确配置 IPv6 路由即可)
 ❌ 误区 11：在手机上需要像电脑一样纠结是否手动安装 TUN 驱动。(错！手机端系统 VPN 框架天然具备全量接管能力)
 ❌ 误区 12：在公司电脑上开启 TUN 模式可以神不知鬼不觉规避所有合规审查。(错！企业边界网关可审计底层外发流量)
 ❌ 误区 13：看到 TUN 模式下 ping 域名返回 198.18 虚拟 IP 说明电脑被木马劫持。(错！属于 Fake-IP 的标准工作池)
 ❌ 误区 14：只要把所有规则删光，TUN 模式下的外服游戏延迟就会变成 1ms。(错！删除规则将导致失去所有分流逻辑)
 ❌ 误区 15：遇到 TUN 模式断网，只要在几个节点之间来回频繁切换就能修复。(错！断网多为底层路由或权限异常)
```

## 十、常见问题解答 (FAQ)

### Q1：Clash Verge Rev 里的 TUN 模式到底是什么意思？
**答**：TUN 模式是通过在操作系统中创建一张虚拟网卡（Virtual Network Adapter），在网络层全量接管电脑上所有软件的数据包并送入代理内核；能彻底解决游戏、终端命令行等不读取系统代理软件的翻墙问题。

### Q2：我平时只是用浏览器看网页和追剧，需要开 TUN 模式吗？
**答**：**完全不需要！** 普通浏览器完美支持【系统代理 (System Proxy)】，开启系统代理更加轻量省电、兼容性最高且零网络冲突风险；只有打外服游戏或跑终端代码时才建议按需开启 TUN。

### Q3：为什么点击开启 TUN 模式时，开关会自动弹回关闭？
**答**：说明客户端缺少创建系统虚拟网卡的管理员权限。请在设置面板中先点击安装【服务模式 (Service Mode)】并授予管理员 UAC 权限，待服务模式点亮绿灯后再开启 TUN。

### Q4：开启 TUN 模式后，为什么电脑突然所有网页都打不开了？
**答**：通常是因为后台同时运行着其他 VPN/代理软件引发了路由表死锁，或者防火墙拦截了新建的 Wintun 适配器；彻底退出其他网络工具，在客户端重启核心即可恢复。

### Q5：开启 TUN 模式后，为什么打不开局域网的 NAS 或路由器后台 (192.168.1.1) 了？
**答**：这是因为 TUN 虚拟网卡错误劫持了私有内网网段。在客户端设置中勾选【Bypass LAN (绕过局域网)】，并在分流规则中确保私网网段置顶 Direct 直连即可完美解决。

### Q6：开启 TUN 模式后，分流规则 (Rule 模式) 还会继续生效吗？
**答**：**绝对会继续生效！** TUN 仅负责把数据包装进客户端内核，进入内核后依然会严格按照你的分流规则进行判断：国内网站走直连、海外受限服务走代理，无需担心流量被浪费。

### Q7：什么是 Wintun？它安全吗？
**答**：Wintun 是由知名开源项目 WireGuard 团队专门为 Windows 开发的高性能轻量级 TUN 驱动程序。Clash Verge Rev 内置的官方 Wintun 组件完全开源安全，切勿从第三方网盘下载不明修改版。

### Q8：为什么开启 TUN 模式后，终端里的 Git 和 npm 依然报错连不上？
**答**：打开客户端的【连接 (Connections)】面板，重新执行 Git 命令，观察是否有请求跳出。若显示为 Direct，说明 Git 域名被漏收录，在自定义规则中添加一条代理规则即可。

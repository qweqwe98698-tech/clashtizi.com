> **【⚠️ 核心急救警示：先记录“掉线是在什么场景下触发的”！】**
> 
> 很多用户遇到断线的第一反应就是不停换节点，但“经常掉线”背后有非常清晰的触发场景分类：
> - **锁屏后掉线**：90% 是手机系统（Android 电池优化 / iOS 扩展休眠）在后台清理了客户端；
> - **Wi-Fi 与 5G 切换时掉线**：属于操作系统底层网络接口（Interface）重构引起的正常瞬断；
> - **固定几分钟掉一次**：通常是 NAT 超时、长连接心跳（Keepalive）断开或客户端代理内核（Core）崩溃；
> - **正在下载大文件时突然中断**：往往是客户端的【Auto 自动选路策略】在后台自动切换了节点。

## 一、手机端掉线核心真因：后台休眠与网络切换

移动设备为了延长续航和管理内存，对后台代理进程有着极其严苛的限制：

```text
                               【手机端后台掉线机制解析】

 [用户锁屏息屏] ──► [系统进入深层省电] ──► [杀掉客户端 Core 进程] ──► [代理连接瞬间切断]
                          │
                   若开启了“后台保护与无限制电池” ──► 客户端持续心跳保持 ──► 保持 24 小时不断连
```

### 1. Android 安卓手机后台保活 3 步设置：
- **第一步：锁定后台任务卡片**：打开多任务界面，长按客户端（如 Clash Meta），点击 **【小锁图标 (Lock)】** 防止被一键清理；
- **第二步：电池无限制优化**：进入系统【设置】 ──► 【应用管理】 ──► 找到客户端 ──► 【电池 / 省电策略】 ──► 勾选 **【无限制 (Unrestricted / 允许后台高耗电)】**；
- **第三步：自启动与关联唤醒权限**：确保在应用权限中开启“允许自启动”和“后台常驻运行”。

### 2. iPhone / iOS 掉线排查：
- iOS 的代理通过系统级的 `NetworkExtension` 框架运行。当手机从 Wi-Fi 走到室外切换为 5G 蜂窝网络时，本地 IP 发生变化，Shadowrocket 等软件需要约 2~3 秒重新建立连接握手，此属底层网络接口切换的正常现象。

## 二、电脑端掉线核心真因：睡眠唤醒、TUN 驱动与 Core 崩溃

Windows 和 Mac 电脑上的掉线通常与底层系统状态变更密切相关：

| 电脑端掉线场景 | 底层根本原因 | 对应极速修复方案 |
| :--- | :--- | :--- |
| **Windows 睡眠唤醒后断网** | 系统睡眠导致网卡供电挂起，唤醒后 TUN 虚拟接口未正确初始化 | 在 [Clash Verge Rev](/tutorials/clash-verge-setup/) 中重启内核，或暂时改用【系统代理】 |
| **Mac 笔记本合盖唤醒后失效** | macOS 睡眠期间切断了 NetworkExtension 守护进程 | 点击客户端状态栏图标，重新勾选一次“System Proxy” |
| **客户端运行中突然所有节点断开** | 底层代理核心（Core）遇到内存溢出或被安全软件误杀崩溃 | 检查 Windows Defender 拦截记录，更新客户端至最新稳定版 |
| **路由器定时重拨引发断线** | 家庭宽带光猫每 48 小时动态 IP 强制刷新 | 路由器重新获取公网 IP 后，客户端会在 5 秒内自动重连 |

## 三、策略组（Auto vs Manual）引发的“虚假断线”

很多用户误以为是“节点断了”，实际上是客户端的自动分流策略在作怪：

```text
 [Auto / URL-Test 自动测速组]：每隔 10 分钟对所有节点测速一次
                                 │
 若发现【日本 02】比【日本 01】快 5ms ──► 客户端瞬间切换出口节点 ──► 现有 TCP 连接强制重置 ──► 导致下载中断/游戏掉线！
```

- **避坑建议**：在进行**游戏对战、大文件下载、视频会议**等对长连接稳定性要求极高的场景时，**务必在策略组中手动指定单一固定节点**，严禁使用 Auto / URL-Test 自动选择组。

## 四、协议特性与网络切换稳定性对比（TCP vs UDP/QUIC）

不同代理协议在面对复杂网络波动时的抗掉线能力差异显著：

| 代理协议类型 | 代表协议 | 连接机制特点 | 网络切换与防掉线表现 |
| :--- | :--- | :--- | :--- |
| **基于 TCP 的协议** | Shadowsocks, Trojan, VLESS-TCP | 面向连接，三次握手严格 | 切换 Wi-Fi/5G 时 TCP 连接必定重置，但重连机制成熟 |
| **基于 UDP/QUIC 的协议** | Hysteria2, TUIC | 无连接传输，支持连接迁移 | 弱网环境下抗丢包能力极强，但在部分公网会受 UDP QoS 限制 |

- **排查建议**：如果发现某种基于 UDP 的协议在当前 Wi-Fi 下频繁中断，可尝试切换到成熟的 Trojan 或 VLESS 节点做交叉对比。

## 五、掉线故障诊断八层模型（8-Layer Diagnostic Model）

遇到反复掉线问题，请按以下标准链路向下逐层排查：

```text
 Layer 1: 节点个体层 ──► 是否仅单一节点断线？（换同地区备用节点）
    ↓
 Layer 2: 线路拥堵层 ──► 是否仅晚高峰 20:00~23:00 频繁掉线？（换高倍率 IPLC 专线）
    ↓
 Layer 3: 策略组控制层 ──► 是否开了 Auto 自动选路？（切为手动锁定单一节点）
    ↓
 Layer 4: 客户端 Core 层 ──► 观察客户端日志是否有 Core Panic 或退出记录（升级软件）
    ↓
 Layer 5: 虚拟网卡与 TUN 层 ──► 是否开启了 TUN 模式？（暂时关闭改用标准系统代理）
    ↓
 Layer 6: 设备系统后台层 ──► 手机是否锁屏后掉线？（检查 Android 电池优化与后台白名单）
    ↓
 Layer 7: 本地网络接口层 ──► 切换 Wi-Fi 与 5G 热点交叉测试（排查路由器与 Wi-Fi 干扰）
    ↓
 Layer 8: 机场云端集群层 ──► 所有设备多网络均频繁掉线（联系服务商查看机房维护状态）
```

```text
               【梯子频繁掉线 5 分钟排查决策树】
                            │
               掉线是发生在手机锁屏/息屏之后吗？

                ├── 是 ──► [属于底层 IP 变更的正常瞬断，等待 3 秒自动重连]
                └── 否
                     │
               客户端策略组选的是【Auto / 自动选择】吗？

                     │
               换用手机 5G 个人热点后依然频繁掉线吗？

                └── 依然掉线 ──► [换用另一个客户端交叉验证，或登录机场后台换线路]
```

## 🔒 掉线排查安全守则

> **核心排查守则**：
> - **切勿安装来源不明的“后台保活加速器”**：很多第三方保活 APK 包含恶意常驻服务与隐私窃取代码；
> - **切勿频繁调整极端的 Keepalive 心跳参数**：过度激进的心跳包会迅速消耗手机电量并可能触发机场服务端的防高频刷流风控；

## 七、常见问题解答 (FAQ)

### Q1：梯子连接几分钟后就自动断开，最常见的原因是什么？
**答**：1. 手机系统为了省电在后台强制杀掉了客户端进程；2. 客户端策略组开启了“Auto 自动选择”，在自动轮询切换节点时中断了现有长连接；3. 本地 Wi-Fi 发生了丢包断流。

### Q2：安卓手机一锁屏息屏，梯子就断开连接怎么解决？
**答**：进入手机应用设置，找到客户端开启“允许后台高耗电 / 电池无限制”，并在多任务界面把软件卡片“加锁锁定”，关闭系统的智能休眠清理。

### Q3：为什么从家里 Wi-Fi 走出门切换到手机 5G 流量时梯子会断开？
**答**：这是网络底层机制决定的。Wi-Fi 切 5G 会导致手机的本地 IP 地址彻底改变，原有的加密代理通道必须断开并重新向服务器发起握手，通常 2~3 秒内会自动恢复。

### Q4：电脑休眠/合盖唤醒后，客户端显示已连接但实际断网怎么办？
**答**：睡眠唤醒时系统的虚拟网卡（TUN 接口）可能未能成功重新载入。在客户端设置中重启一次代理内核（Restart Core），或关闭 TUN 模式改用系统代理。

### Q5：为什么白天连接非常稳定，一到晚上就频繁掉线重连？
**答**：晚高峰（20:00~23:00）国际出口骨干网拥堵严重，普通公网线路丢包率剧增导致连接心跳超时断开。换用不经过公网的 IPLC/IEPL 纯内网专线可彻底解决。

### Q6：正在下载大文件或玩游戏，突然断线重连是怎么回事？
**答**：检查客户端策略组是否选了“Auto”或“URL-Test”。当自动测速发现其他节点延迟更低时会触发切节点，导致旧的下载连接被强行切断。请务必手动固定单一节点。

### Q7：开启 TUN 模式后频繁断线，关闭后反而稳定是为什么？
**答**：TUN 虚拟网卡需要接管系统所有流量，容易与电脑上的杀毒软件、公司 VPN 或虚拟机网卡发生路由表抢占。日常浏览网页建议优先使用更轻量的【系统代理】。

### Q8：只有某一个特定节点经常断线，其他节点正常说明什么？
**答**：说明你的客户端、本地网络和设备完全正常。纯属该物理服务器正在进行机房维护、遭受攻击或出口带宽跑满，直接换用同地区其他备用节点即可。

### Q9：家里路由器重新拨号会导致梯子断线吗？
**答**：会。宽带运营商通常每隔 48 小时会重置一次宽带拨号，公网 IP 变化会导致所有外网长连接瞬间中断，路由器重新联网后客户端会自动重连。

### Q10：客户端日志里频繁出现“Connection Reset”或“Timeout”是什么意思？
**答**：Connection Reset 表示远端服务器或中间链路主动切断了连接；Timeout 表示客户端发送的数据包在超时时间内未收到回包，通常由丢包严重或线路波动引起。

### Q11：频繁掉线需要把客户端卸载重装吗？
**答**：不需要。掉线绝大多数属于网络环境、后台权限或策略组设置问题，重装软件无法改变系统省电策略和网络波动。

### Q12：所有设备连同一个 Wi-Fi 都会同时掉线，怎么定位？
**答**：如果手机和电脑在同一 Wi-Fi 下同时断开，说明问题出在家庭宽带或路由器端。尝试重启光猫和路由器，或将电脑连接手机 5G 热点做对比测试。

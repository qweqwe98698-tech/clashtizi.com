> **【💡 30 秒极速分诊：为什么 Global 能翻墙，切回 Rule 就打不开？】**
> - **第一核心定性**：**“Global 能用” 100% 证实你的节点服务器通畅、Mihomo 内核运行正常、系统代理/TUN 入口接管成功！** 此时最愚蠢的做法就是继续疯狂换节点；
> - **核心矛盾定位**：Global 模式是无脑把所有流量送往指定节点，而 **Rule (规则模式) 新增了「域名识别 ──► 规则匹配 ──► 策略组指派 ──► 节点出站」一整套决策链条**。Rule 失效必定卡在这四个新增环节之一；
> - **四大典型根因极速对号入座**：
>   1. **所有海外网站在 Rule 下全部打不开** ──► 代理面板中某个策略组（如 `🚀 节点选择`）误选了红色的超时节点，而 Global 面板选的是绿节点；
>   2. **只有某个特定网站打不开（如 ChatGPT 或特定流媒体）** ──► 该网站的新 API/CDN 域名未被内置规则库收录，被兜底规则误判为了国内 `Direct` 直连；
>   3. **打开连接 (Connections) 面板显示状态为 `Reject`** ──► 该域名被广告拦截或隐私防护规则强行拦截阻断；
>   4. **首页能秒开，但点击登录或播放视频报错** ──► 主域名命中代理，但后端的认证授权或媒体流域名命中了直连。

## 一、五大典型故障分类与第一排查方向速查总表

| 故障现象分类 | 底层真实技术含义 | 最核心诱发诱因 | 第一步标准应对动作 |
| :--- | :--- | :--- | :--- |
| **A：Global 正常，Rule 下所有网站全挂** | 规则模式的出口策略组整体瘫痪 | `PROXY` 或 `Auto` 策略组误选了红色死节点 | 检查代理页面各策略组内部手动选中的节点 |
| **B：Global 正常，仅单个网站打不开** | 该网站的关联域名未被规则库覆盖 | API/静态资源域名缺失，被 MATCH 直连规则捕获 | 在 Connections 面板捕获域名并追加自定义代理规则 |
| **C：连接面板显示请求，但状态为 Direct** | 目标流量被分流规则判定为国内直连 | 规则顺序靠后的白名单或 GEOIP-CN 规则先命中 | 调整规则优先级，将目标域名规则置顶 |
| **D：连接面板显示请求，但状态为 Reject** | 目标流量被内置安全/去广告规则拦截 | 目标域名被公共去广告 Rule Provider 误杀 | 查找命中规则，在自定义配置中放行该域名 |
| **E：连接面板显示 Proxy，但依然打不开** | 规则匹配正确，但指派的策略组节点失效 | 策略组使用了 `URL-Test` 自动选到了假死节点 | 将策略组从自动切换为手动指定稳定的香港/日本节点 |

## 三、排障第一基石：利用「连接 (Connections)」面板捕获真实命中规则

在 Clash Verge Rev 中解决 Rule 失效，唯一的科学手段就是**查看连接的详细链路**：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【Connections 面板抓包诊断四步法】                            │
 ├─────────────────────────────────────────────────────────────────────────────────────────────┤
 │ 1. 打开 Clash Verge Rev 左侧的【连接 (Connections)】实时监控面板；                          │
 │ 2. 在浏览器中刷新那个在 Rule 模式下打不开的目标网页；                                      │
 │ 3. 在列表中找到该网站的连接记录，点击展开右侧的【详细参数 (Details)】：                     │
 │     ├── 检查【Host / Destination】：核对真实发起的域名或 IP 地址；                          │
 │     ├── 检查【Rule】：查看命中了哪一条分流规则（如 `DOMAIN-SUFFIX,google.com`）；          │

 │     └── 检查【Chains / Outbound】：查看流量最终是被指派给了 `DIRECT`、`REJECT` 还是 `PROXY`。│
```

## 四、策略组 (Proxy Group) 深度排查：为什么规则对了还是连不上？

很多时候规则本身写得完全正确，但**策略组内部的节点选择机制出了问题**：

```text
 1. 【手动选择组 (Select Group) 误选死节点】：
    - 你的规则写着 `DOMAIN-SUFFIX,openai.com,ChatGPT`，流量被送进了【ChatGPT】策略组；
    - 但如果你此前在【代理】面板里，手动给 ChatGPT 策略组选了一个已经超时的香港 05 节点；
    - 表现：即使你的默认主节点可用，ChatGPT 依然打不开。解决：进入该策略组换选一个绿色低延迟节点。

 2. 【自动测速组 (URL-Test) 的“假死延迟”陷阱】：
    - URL-Test 策略组会定期向测试地址发请求，自动切换到延迟最低的节点；
    - 但某些中转节点对测速地址能秒回 20ms，实际打开特定网页时却早就被目标平台封锁；
    - 解决：排障期间，尽量避免将策略组设为 Auto 自动测速，手动指定单一节点做 A/B 验证。
```

## 六、现代网站的“复合域名陷阱”：为什么首页能开但登录不了？

很多用户经常反馈：“为什么 Rule 模式下某个网站首页能秒开，但一点击登录按钮就一直转圈报错？”

```text
 1. 【业务架构分离导致规则漏命中】：
    - 现代互联网产品极少只依赖单一主域名，通常将认证、核心 API 与静态资源完全解耦；
    - 示例场景：
      - 访问 `target.com` ──► 命中代理规则 ──► 成功加载出炫酷的前端首页；
      - 点击登录拉取 `auth.login-service.net` ──► 未被规则库收录 ──► 命中兜底 `DIRECT` ──► 登录接口超时卡死！

 2. 【解决手段】：
    - 打开 Connections 监控面板，点击登录按钮，观察哪一个标有 `DIRECT` 且红色的域名在报错；
    - 将该认证域名加入代理策略组，即可瞬间打通全部流程。
```

## 七、DNS、Fake-IP 与 IPv6 双栈对规则匹配的深层干扰

```text
 1. 【IP-CIDR 规则与 DNS 预解析死锁】：
    - 若分流规则包含大量 `IP-CIDR` 规则，内核必须先通过 DNS 解析出域名的真实物理 IP 才能比对；
    - 若本地 DNS 被污染或解析超时，将导致整条规则链匹配迟钝甚至直接坠入直连。

 2. 【Fake-IP 虚拟 IP 映射完全正常】：
    - 看到连接详情中目标 IP 显示为 `198.18.x.x`，属于 Fake-IP 的标准工作机制，不代表规则出错。

 3. 【IPv6 漏网之鱼排查】：
    - 若本地开启了 IPv6，某些网站会优先返回 AAAA 记录；
    - 若你的订阅节点不支持 IPv6 或规则库仅针对 IPv4 编写，会导致数据包绕过代理走本地直连断流；
    - 解决：参考 [《梯子IPv6与代理兼容指南》](/tizi/ipv6/)，在客户端开启 IPv4 优先解析。
```

## 八、Global 能用 Rule 不能用 5 分钟极速排障 SOP（标准 HowTo）

遇到 Global 正常但 Rule 模式失效时，请严格按以下 6 步标准顺序排查：

```text
 Step 1: 验证前置基线 ──► 切到 Global 确认目标网页确实能正常秒开（排除节点与网络硬件故障）
    ↓
 Step 2: 切回 Rule 并打开监控 ──► 切回 Rule 模式，打开 Connections 实时连接面板
    ↓
 Step 3: 刷新页面捕获请求 ──► 在浏览器重新刷新目标网页，查看面板中跳出的请求记录
    ↓
 Step 4: 检查命中链路 ──► 观察请求命中的规则名称以及最终 Outbound 是 Direct、Reject 还是 Proxy
    ↓
 Step 5: 排查目标策略组 ──► 若显示 Proxy 但打不开，进入该策略组检查内部是否选到了超时死节点
    ↓
 Step 6: 检查兜底规则与 DNS ──► 若所有网站全挂，检查末尾 MATCH 规则是否正确指向有效代理策略组
```

## 九、关于 Rule 模式的 15 大核心认知误区

```text
 ❌ 误区 1：既然 Global 能翻墙，就证明当前使用的这套分流规则绝对没有任何问题。(错！Global 完全跳过了所有规则)
 ❌ 误区 2：Global 能用 Rule 不能用，最快的方法就是以后永远开着 Global 上网。(错！会导致国内微信和网银全线异常)
 ❌ 误区 3：看到连接显示 Direct 就说明代理客户端坏了。(错！Direct 代表规则判定该网站属于国内直连)
 ❌ 误区 4：看到连接显示 Reject 就认为是节点掉线了。(错！Reject 代表命中广告拦截或安全阻断规则)
 ❌ 误区 5：去网上找一份包含几十万条规则的“超级豪华去广告规则集”导入一定最好。(错！臃肿规则极易引发规则冲突与内存卡顿)
 ❌ 误区 6：只要把配置文件末尾的 MATCH 改成 PROXY，所有分流问题就全解决了。(错！会导致所有未收录的国内网站全走代理)
 ❌ 误区 7：在两个策略组里选完全不同的节点能让 Rule 模式速度翻倍。(错！单一连接只会走单条链路)
 ❌ 误区 8：Rule 模式下打不开网页，第一反应立刻把客户端完全卸载重装。(错！重装依然会恢复相同的默认规则配置)
 ❌ 误区 9：域名规则越多，判断速度就一定越慢。(错！Mihomo 采用高效字典树算法，但垃圾冗余规则会增加误杀率)
 ❌ 误区 10：为了解决 Rule 模式打不开，听信网上教程在电脑里把 IPv6 彻底永久关闭。(错！双栈网络只需在配置中规范出口)
 ❌ 误区 11：在手机上 Rule 能用，电脑上 Rule 不能用就一定是电脑中了木马。(错！两端的订阅规则库版本可能并不一致)
 ❌ 误区 12：遇到网站打不开，反复在几十个国家节点之间秒级来回狂切。(错！若规则判了直连，换一万个节点也无济于事)
 ❌ 误区 13：看到 Fake-IP 的 198.18 虚拟 IP 就断定规则匹配系统崩溃了。(错！属于 Fake-IP 的标准工作机制)
 ❌ 误区 14：只要把所有规则全部删光，Rule 模式就会自动变成超快的直连模式。(错！删除规则将导致失去所有代理引导)
 ❌ 误区 15：一个网站只要配置了主域名走代理，其所有视频和登录功能就必然能正常使用。(错！现代服务多依赖独立 API/CDN)
```

## 十、常见问题解答 (FAQ)

### Q1：为什么 Global 模式能正常翻墙，一切换到 Rule 模式就全网打不开了？
**答**：Global 模式是无脑直连单一指定节点，而 Rule 模式依赖分流策略组。全网打不开通常是因为你的规则匹配到的主策略组（如 `PROXY` 或 `节点选择`）误选了一个红色超时的死节点；在代理面板中将该策略组的节点手动切为绿色可用节点即可。

### Q2：为什么可以一直开着 Global 模式上网吗？有什么坏处？
**答**：**绝对不建议长期开启 Global！** 全局模式会导致国内的微信、网易云、淘宝、网上银行全量绕道海外；不仅访问极度卡顿、消耗宝贵的海外翻墙流量，还极易触发国内银行和社交软件的风控异地登录锁定。

### Q3：怎么在 Clash Verge Rev 中确认某个网站到底命中了什么规则？
**答**：打开客户端左侧的【连接 (Connections)】面板，刷新打不开的网页。在列表中找到该网站的域名行，展开详情即可清晰查阅其命中的具体规则名（如 `DOMAIN-SUFFIX`）、规则载荷以及最终出口走向（Direct/Reject/Proxy）。

### Q4：连接面板里显示状态为 `Direct` 是什么意思？
**答**：说明该应用的请求已经成功被客户端接管，但你的分流规则判定该网站属于“中国大陆直连”范畴，因此直接放行走本地物理网络；若该网站实际需要翻墙，说明规则库遗漏了该域名，需手动添加代理分流。

### Q5：连接面板里显示状态为 `Reject` 是什么意思？
**答**：说明该请求被规则库主动拦截阻断了。通常是因为该域名被收录进了防追踪、广告过滤或恶意网站黑名单；若属于正常业务域名被误杀，需在自定义规则中添加白名单放行。

### Q6：为什么某个网站首页能秒开，但一点击登录按钮就超时报错？
**答**：现代网站的认证登录接口与前端展示页面通常采用不同的独立域名（例如主站是 `.com`，而授权 API 是 `.net`）。主域名命中了代理，但授权 API 被误判为了国内直连；在 Connections 面板中捕获该 API 域名并加入代理规则即可解决。

### Q7：什么是 Rule Provider？它更新失败会导致断网吗？
**答**：Rule Provider 是配置引用的外部独立分流规则集（负责提供域名和 IP 清单）。若由于网络问题更新失败，客户端通常会无缝回退使用本地旧缓存，不会直接断网；但若长期无法更新可能导致新上线服务的规则缺失。

### Q8：怎么给某个打不开的网站手动添加一条强制代理规则？
**答**：在 Clash Verge Rev 的扩展配置或订阅配置文件中，在 `rules:` 列表的最顶端添加一行：`DOMAIN-SUFFIX,目标域名.com,节点选择`，保存并重新加载配置即可强制其永远走代理。

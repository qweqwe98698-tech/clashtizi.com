> **【💡 30 秒极速直接答案：Shadowrocket 连上却没网，第一核心定性与分诊】**
> - **第一核心定性**：**“手机顶部出现 VPN 图标且显示已连接”绝对不等于“网络已经打通”！** 苹果 iOS 状态栏的 VPN 图标仅代表本地 Network Extension 虚拟通道被激活，完全不代表数据包已经成功流经海外节点并到达目标网站；
> - **两极分化极速分诊（最重要诊断分水岭）**：
>   1. **所有网站（包括国内百度和国外 Google）全军覆没** ──► 属于**节点本身出口宕机**、**本地 DNS 解析死锁**或**底层 VPN 路由环路** ──► 换同订阅其他节点或重启网络；
>   2. **国外网站秒开，国内微信/淘宝严重卡顿转圈** ──► 属于**全局路由模式误选成了【代理 (Proxy)】** ──► 切回【配置 (Config)】模式即可秒级修复；
>   3. **大部分网站正常，仅特定一个网站打不开** ──► 属于**分流规则未收录该域名被判定为 Direct 直连**，或目标平台对当前节点 IP 进行封控；
>   4. **Safari 浏览器飞快，但某个独立 App 无法联网** ──► 属于**该 App 使用了独立 API/CDN 域名或走纯 UDP 流量** ──► 打开小火箭【请求日志 (Requests)】抓包定向放行。

## 一、故障范围分类与第一优先级排查对照表

遇到 Shadowrocket 显示已连接但无法正常上网时，请先对照下表确认你的核心故障层级：

| 故障现象分类 | 核心阻断层级 | 最核心真实诱发诱因 | 第一步标准应对动作 |
| :--- | :--- | :--- | :--- |
| **A：VPN 已连接，但所有网页都打不开** | 节点出站 / 本地 DNS | 选中的节点服务器出口断网，或系统 DNS 解析死锁 | 切换同分组下的其他绿色节点，测试能否连通 |
| **B：国外网站秒开，但国内 App 全卡死** | 全局路由模式层 | 全局路由误切为【代理 (Proxy)】，国内流量全绕美 | 在首页将全局路由切实切回【配置 (Config)】 |
| **C：大部分外网正常，仅某一个网站打不开** | 分流规则 / 目标 CDN | 规则库未匹配该小众域名，或目标平台屏蔽机房 IP | 打开请求日志查阅走向，或切换其他国家出口 |
| **D：Safari 正常，但特定 App（如推特）不通**| 专属协议与域名层 | 该 App 依赖特定 CDN 域名，或 UDP 协议被阻断 | 查看 Requests 日志，确认该 App 命中的分流 |

| **G：输入纯 IP 能打开，输入域名打不开** | 域名解析 (DNS) 层 | 代理配置内的 DNS 服务器无响应或解析被劫持 | 在小火箭【设置】──►【DNS】中配置通用 DoH |

## 二、第一排障铁律：全站打不开 vs 部分打不开（关键分水岭）

```text
 ⚠️ 【新手最容易犯的低级排查错误】：
 看到一个特定网站打不开，就认为“小火箭全盘失效了”，立刻把 App 卸载重装、删光订阅、甚至把手机还原网络设置……
 
 核心排障纪律（两极分化诊断法则）：
 1. 【如果所有网站（包括百度、B站、谷歌）全部断网】：
    - 说明通道发生了“物理级”阻断，优先排查【节点可用性】、【系统时间偏差】与【本地网络连接】；
 2. 【如果国内网站能开，仅某个海外网站打不开】或者【国外秒开，国内 App 卡死】：
    - 说明底层网络隧道完好无损！100% 属于【分流规则误判】或【DNS 映射异常】，绝不要去动节点和重装客户端！
```

## 三、国内网站打不开/微信转圈：99% 是全局路由选成了「代理」

在 Shadowrocket 首页主开关下方，有一个核心控制选项【全局路由】：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【三大全局路由模式与网络行为】                                │
 ├──────────────────────┬──────────────────────────────┬───────────────────────────────────────┤
 │ 路由模式名称         │ 流量底层转发行为             │ 实际网络表现                          │
 ├──────────────────────┼──────────────────────────────┼───────────────────────────────────────┤
 │ **配置 (Config)**     │ **智能分流（推荐 99% 常驻）** │ 🟢 国内直连秒开，国外走代理，网银不风控│
 ├──────────────────────┼──────────────────────────────┼───────────────────────────────────────┤
 │ **代理 (Proxy)**     │ **全局强制代理（慎用！）**   │ 🔴 国内微信、淘宝、外卖全部绕道海外，极度卡顿│
 ├──────────────────────┼──────────────────────────────┼───────────────────────────────────────┤
 │ **直连 (Direct)**     │ **全局不走代理（相当于没开）**| ⚪ 外网全部受阻打不开，仅走本地裸连  │
 └──────────────────────┴──────────────────────────────┴───────────────────────────────────────┘
```

### 为什么切成「代理 (Proxy)」国内 App 会瘫痪？
- 当模式为 `Proxy` 时，你打开微信、高德地图或网银，数据包全部被迫跨越几万公里的太平洋绕道美国再回来；
- 国内服务器检测到登录 IP 突变到海外，会触发极其严厉的风控机制（验证码弹窗、拒绝服务或支付拦截）；
- **标准解法**：在小火箭主界面点击【全局路由】，确保勾选为 **【配置 (Config)】**！

## 四、DNS 死锁排查：为什么纯 IP 能开，输入网址就显示无法连接？

很多用户遇到“连上没网”，本质上并不是节点不能传输数据，而是**域名根本没有被翻译成 IP 地址**：

```text
 1. 【DNS 解析故障三大具象表现】：
    - 在浏览器地址栏输入海外公开 IP（如 `1.1.1.1`）能瞬间打开，但输入 `google.com` 就无限转圈提示无法访问；
    - 小火箭请求日志中频繁跳出 `DNS Timeout` 或 `NXDOMAIN` 错误；
    - 手机从睡眠中唤醒时，前 30 秒所有海外网页均无法建立连接。

 2. 【快速恢复标准操作】：
    - 打开 Shadowrocket 底部【设置】标签页 ──► 点击【DNS】；
    - 检查是否胡乱填写了网上抄来的无效私有 DNS 地址；
    - 建议直接配置稳定权威的公共加密 DNS (DoH)，例如阿里加密 DNS (`https://dns.alidns.com/dns-query`) 或 Cloudflare (`https://1.1.1.1/dns-query`)，确保域名解析干净快速。
```

## 五、规则三大动作解密：Proxy、Direct 与 Reject 到底代表什么？

进入小火箭底部的【配置 (Config)】，点击正在生效的规则文件（如 `default.conf`），可以看到大量分流规则：

```text
 1. 【Proxy (走代理)】：
    - 规则示例：`DOMAIN-KEYWORD,youtube,PROXY`
    - 含义：检测到包含 youtube 关键字的请求，强制打包给当前选中的代理节点发送。

 2. 【Direct (走直连)】：
    - 规则示例：`GEOIP,CN,DIRECT`
    - 含义：检测到该 IP 属于中国大陆本土网络，直接通过本地 Wi-Fi/5G 直连；
    - 💡 纠偏：日志里显示 Direct 绝不代表小火箭坏了，它代表分流引擎正在正常工作为你节省翻墙流量！

 3. 【Reject (主动拦截)】：
    - 规则示例：`DOMAIN-SUFFIX,doubleclick.net,REJECT`
    - 含义：检测到恶意广告追踪域名，小火箭在手机本地直接掐断该连接；
    - 💡 纠偏：若某个打不开的网页在日志中显示为红色 Reject，说明该域名被误当成了广告规则拦截，将其移出拦截规则即可。
```

## 七、IPv4 与 IPv6 双栈冲突导致网络断流排查

```text
 1. 【IPv6 导致的局部网页卡死真相】：
    - 当你在手机上访问支持 IPv6 的大型网站时，系统会优先发起 AAAA 记录查询，并尝试优先建立 IPv6 握手；
    - 若你连接的海外代理节点仅支持 IPv4 出口，而客户端未进行规范的双栈兜底回落处理，就会导致连接挂起几十秒甚至超时断开；
    - 表现：百度等纯 IPv4 站点能开，但部分大型国际站点极慢或打不开。

 2. 【科学排查方式】：
    - 参考 [《梯子IPv6与代理兼容指南》](/tizi/ipv6/)，检查当前生效的规则文件中是否配置了良好的 IPv6 回退策略；
    - 在 Wi-Fi 与蜂窝网络之间切换测试，切勿在手机中永久关闭整个 iOS 的 IPv6 协议。
```

## 十、常见问题解答 (FAQ)

### Q1：为什么小火箭显示已连接且有 VPN 图标，但浏览器打不开任何网页？
**答**：状态栏的 VPN 图标仅代表 iOS 系统与小火箭建立了本地虚拟隧道，不代表远程节点连接成功。常见原因包括：节点服务器出口故障、手机系统时间偏差导致握手失效、或本地 DNS 解析死锁。切换其他绿色节点并校准手机时间即可排查。

### Q2：为什么开启小火箭之后，国内的微信、淘宝和美团极其卡顿打不开？
**答**：**99% 是因为全局路由选错了模式！** 检查主界面主开关下方的【全局路由】，确保切为【配置 (Config)】模式。若误选了【代理 (Proxy)】，国内所有 App 的流量都会被强行绕道海外，导致严重的卡顿和延迟。

### Q3：为什么大部分国外网站能开，只有某一个特定的网站打不开？
**答**：通常有两个原因：一是小火箭的分流规则库未收录该小众网站域名，被误判为了国内直连 (Direct)；二是该网站服务器对你的节点机房出口 IP 进行了地域封控或 WAF 防护拦截。切换不同国家节点或手动添加该域名为 Proxy 即可。

### Q4：怎么在小火箭里确认打不开的网站到底走了什么规则？
**答**：进入小火箭底部【设置】──► 开启【请求日志 (Requests)】。回到桌面重新刷新该网站，再返回小火箭请求列表，即可直观查阅该域名到底被判定为了 `Proxy`（走代理）、`Direct`（走直连）还是 `Reject`（被拦截）。

### Q5：请求日志里显示的「Direct」和「Reject」是什么意思？
**答**：`Direct` 代表分流规则判定该请求属于国内服务，直接走本地网络直连以保证速度；`Reject` 代表判定该请求为恶意广告追踪，被小火箭在本地直接丢弃。两者都是规则正常生效的表现，并非客户端故障。

### Q6：连上小火箭后，为什么家里的局域网 NAS (192.168.1.x) 和智能家居连不上了？
**答**：这是因为本地局域网私有网段被错误接管。在分流规则中确保包含 `IP-CIDR,192.168.0.0/16,DIRECT` 规则，并在小火箭设置中确认未将局域网网段强制送入代理。

### Q7：Wi-Fi 下连上没有网，为什么一旦换成手机 5G 流量就瞬间正常了？
**答**：这证明节点本身完好无损，瓶颈 100% 在家里的 Wi-Fi 路由器上！通常是因为宽带运营商下发了错误的 DNS、或光猫对特定代理端口进行了硬件级阻断；在手机 Wi-Fi 设置中将 DNS 手动修改为 `223.5.5.5` 即可恢复。

### Q8：遇到连上但打不开网页，最忌讳的操作是什么？
**答**：最忌讳“病急乱投医同时改动多个设置”（比如一边改 DNS、一边换规则、一边清空配置、一边重装 App）。科学做法是用请求日志查看走向，按“节点 ──► 路由模式 ──► 规则 ──► 本地网络”单变量逐层排查。

> **【💡 30 秒极速诊断：为什么浏览器能翻墙，某个软件就是不走代理？】**
> - **核心技术分水岭**：“浏览器正常但 App 异常”，**99% 的情况下节点本身完全正常**，问题在于**该软件的数据流量根本没有送入代理客户端内核 (Core)**！
> - **三层排障黄金法则**：
>   1. **第一层（完全无连接记录）**：客户端【连接 (Connections)】中看不到该软件 ──► 该 App 完全不读取 System Proxy，需**开启 [TUN 虚拟网卡模式](/tizi/tun/)** 或配置环境变量；
>   2. **第二层（显示为 Direct）**：客户端能看到连接但显示 Direct ──► 命中分流规则错误，需**在 [分流规则](/tizi/routing-rules/) 中添加域名或进程代理**；
>   3. **第三层（显示为 Proxy 但超时）**：已走代理但连不上 ──► 该节点机房 IP 被目标服务拉黑，或海外节点端口受阻。

## 一、为什么不同软件在代理环境下的表现千差万别？

在操作系统中，不同软件编写时采用的网络通信库差异极大，直接决定了它是否会主动走代理：

| 应用程序分类 | 网络通信底层机制 | 对 System Proxy 的反应 | 典型软件代表 | 标准解决方案 |
| :--- | :--- | :--- | :--- | :--- |
| **标准桌面浏览器** | 调用系统标准网络栈 (WinINET/WebKit) | 🟢 **100% 自动读取系统代理** | Chrome, Edge, Safari | 保持开启系统代理即可 |
| **独立代理浏览器** | 具备独立网络配置模块 | 🟡 需在浏览器内指定跟随系统 | Mozilla Firefox | 进入设置勾选【使用系统代理】 |
| **大型 3D 联机游戏** | 裸 Socket 套接字通信 (大量使用 UDP) | ❌ **完全无视系统代理** | Steam 游戏, 战网, 英雄联盟外服 | **必须在客户端开启 [TUN 虚拟网卡](/tizi/tun/)** |
| **开发者命令行工具** | 仅读取特定环境变量与独立配置文件 | ❌ **默认不读取操作系统注册表** | Git, CMD, PowerShell, npm, pip | 配置 `HTTP_PROXY` 或开启 TUN |
| **混合架构 (Electron)** | 登录与网页走 Chromium，数据流走原生 API | 🟡 部分功能走代理、部分功能直连 | Discord, Telegram, Slack, VS Code | 推荐开启 TUN 模式实现全量接管 |

## 二、开发者与命令行程序：为什么 Git、npm、curl 总是直连？

终端命令行程序属于“无头工具（Headless Tools）”，出于跨平台设计，它们不会主动去读取 Windows 或 macOS 桌面图形界面的代理设置：

```text
                               【命令行工具代理环境变量生效机制】

 1. 临时环境变量配置：
    - Windows CMD:        set http_proxy=http://127.0.0.1:7890 && set https_proxy=http://127.0.0.1:7890
    - Windows PowerShell: $env:http_proxy="http://127.0.0.1:7890"; $env:https_proxy="http://127.0.0.1:7890"
    - macOS / Linux:      export http_proxy=http://127.0.0.1:7890 && export https_proxy=http://127.0.0.1:7890

 2. 核心避坑警告：
    ⚠️ 绝不建议在系统【全局环境变量】中永久写死代理端口！一旦退出代理软件，终端命令将全部因端口失效而报错瘫痪。
```

## 三、Electron 与混合架构 App：为什么登录正常但无法视频/下载？

很多现代桌面应用（如 Discord、Telegram、Slack）采用的是“前端网页 + 后端原生组件”的混合架构：

```text
 1. 【模块分流现象】：
    - 用户登录界面调用的是内置 Chromium 内核 ──► 顺利读取 [System Proxy](/tizi/system-proxy/) 成功登录；
    - 语音通话与大文件传输调用的是底层 UDP/WebRTC 驱动 ──► 直接绕过系统代理直连物理网卡，导致通话断连。

 2. 【彻底根治方案】：
    - 在代理客户端中一键开启【TUN 虚拟网卡模式】，使操作系统的所有 TCP 和 UDP 数据包全部被强制捕获进 Core。
```

## 五、单个软件不走代理 5 分钟极速排障 SOP（标准 HowTo）

遇到特定软件连不上外网或依然显示国内 IP 时，按以下 6 步标准流程定位：

```text
 Step 1: 验证节点连通性 ──► 打开浏览器访问 Google，确认节点本身通畅且非客户端崩溃
    ↓
 Step 2: 打开【连接】监控面板 ──► 在 Clash Verge Rev 或 sing-box 界面切到 Connections 面板
    ↓
 Step 3: 触发目标软件网络请求 ──► 观察监控面板中是否跳出该软件的连接记录
    ↓
 Step 4: 若【完全无连接记录】 ──► 判定为应用不读取系统代理，立即开启 [TUN 模式](/tizi/tun/) 强制抓包
    ↓
 Step 5: 若【显示为 Direct 直连】 ──► 临时切为 [Global 全局模式](/tizi/rule-global-direct/) 对照；若 Global 能用，说明属于分流规则误判
    ↓
 Step 6: 若【显示为 Proxy 但超时】 ──► 说明该软件的海外机房 IP 遭遇目标服务端防火墙屏蔽，更换其他落地节点
```

 ❌ 误区 2：游戏连不上外网，说明我买的机场节点协议损坏了。(错！绝大多数是因为未开启 TUN 虚拟网卡)

 ❌ 误区 9：软件在客户端监控里显示 Direct，说明梯子发生了严重 IP 泄漏。(错！国内流量命中直连属预期分流)

 ❌ 误区 11：所有的 Electron 应用在代理机制上表现都和 Google Chrome 完全相同。(错！原生网络模块不读代理)

 ❌ 误区 13：只要在软件内部把代理设为 127.0.0.1:7890，软件关闭后也会自动联网。(错！软件会一直连接死端口)
 ❌ 误区 14：企业办公电脑连不上个人代理是软件 Bug。(错！企业 MDM 与安全策略限制了虚拟网卡与系统代理)
 ❌ 误区 15：一个软件的不同功能（如登录与下载）必须永远走同一个海外节点。(错！不同域名按规则正常分流)

## 七、常见问题解答 (FAQ)

### Q1：为什么我的浏览器能正常翻墙，但某个 App 或游戏就是连不上？
**答**：因为浏览器调用的是系统标准应用层代理（System Proxy），而游戏、Git 终端及部分软件直接调用底层网络接口，完全不读取系统代理设置。必须在客户端中开启 [TUN 虚拟网卡模式](/tizi/tun/) 强制接管底层数据包。

### Q2：怎么在客户端里确认某个软件到底有没有走代理？
**答**：打开客户端的【连接 (Connections)】实时监控面板，运行该软件并观察是否产生连接记录：若无记录说明未进入客户端；若显示 Direct 说明被规则判定直连；若显示 Proxy 则代表已正常走代理。

### Q3：为什么开启了 TUN 模式后，游戏依然提示“无法连接服务器”？
**答**：请检查分流规则。如果规则库中将该游戏的域名或服务器 IP 误判为了 Direct 直连，流量依然会走本地网络；尝试临时切换为 [Global 全局模式](/tizi/rule-global-direct/) 即可快速验证。

### Q4：在 Windows 命令行（CMD / PowerShell）中怎么让 Git 和 npm 走代理？
**答**：在当前终端窗口中临时运行命令：`set http_proxy=http://127.0.0.1:7890` 与 `set https_proxy=http://127.0.0.1:7890`，即可让当前窗口的所有 CLI 工具临时走本地代理。

### Q5：为什么 Firefox 浏览器打不开 Google，但 Chrome 却完全正常？
**答**：Firefox 拥有独立的代理配置模块。进入 Firefox【设置】──► 搜索【网络设置】──► 勾选【使用系统代理设置】即可与 Chrome 保持一致。

### Q6：为什么某个软件登录界面正常，但一点击语音通话或文件下载就报错？
**答**：这是典型的混合架构分流差异。登录界面走的是标准的 HTTP/HTTPS 代理，而语音通话走的是底层裸 UDP 协议；在客户端开启 TUN 模式即可接管全量 UDP 通信。

### Q7：什么是 Process Rule（进程规则）？
**答**：进程规则是现代代理内核支持的一种高级分流方式（如 `PROCESS-NAME,steam.exe,PROXY`），可以直接根据发起连接的软件文件名强制指定走代理或直连。

### Q8：可以在同一台电脑上同时开启两个代理软件吗？
**答**：不建议。同时开启两个客户端极易造成本地端口冲突、系统代理反复覆盖以及 TUN 虚拟网卡路由表死锁。

### Q9：为什么关闭代理软件后，电脑上的命令行终端突然连不上网了？
**答**：这是因为你在系统环境变量中永久写死了 `HTTP_PROXY`。打开系统【环境变量】设置，删除残留的代理变量即可恢复正常。

### Q10：Android 手机上怎么设置“只让特定的 App 走代理”？
**答**：在 Android 代理客户端（如 Clash / v2rayNG）的设置中找到【分流应用 (App Bypass / Include)】选项，勾选你希望走代理的特定 App 即可。

### Q11：为什么公司电脑开梯子后，很多企业内部软件都无法使用了？
**答**：因为个人代理客户端修改了系统路由与代理端口，与企业内部 VPN 或内网网关产生了冲突；建议在办公时退出个人代理或配置内网 IP 绕过。

### Q12：到底在什么情况下才需要修改代理规则库？
**答**：当你在 Connections 面板中明确看到该软件已进入客户端、但在 Rule 模式下被错误标记为 Direct、且在 Global 模式下完全正常时，才需要针对该域名添加代理规则。

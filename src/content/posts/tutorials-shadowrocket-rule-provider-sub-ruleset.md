## 一、为什么你的小火箭"配置对了"却依然卡：从物理链路到内核参数的微观推演

绝大多数 iOS 用户在 Shadowrocket 里导入订阅、选个节点、点开开关，然后抱怨"晚高峰卡成 PPT"。问题往往不在客户端，而在于三层结构性错配：**物理链路层**（公网中转 vs 专线内网）、**传输层**（拥塞控制算法与队列调度）、**应用层**（分流规则与 DNS 解析路径）。这三层任何一层出问题，都会表现为"节点超时"或"网页转圈"，但根因完全不同，排障方向也南辕北辙。

### 1.1 公网 BGP 中转与 IEPL 物理专线的抖动差异

先看两种典型链路的拓扑差异。普通公网中转机场的路径是这样的：

```
[iPhone 小火箭]
      │  (4G/5G/Wi-Fi 接入)
      ▼
[国内多线 BGP 入口 (电信/联通/移动)]
      │  (公网国际出口，晚高峰拥塞点)
      ▼
[国际骨干网 transit (可能绕美/绕日)]
      │  (跨境公网，受 GFW 主动探测与 QoS 影响)
      ▼
[海外落地机房 (共享公网 IP)]
      │
      ▼
[目标站点]
```

这条路径上，**国际出口带宽在 20:00–23:00 被大量用户共享**，运营商对跨境 UDP 流量普遍实施 QoS 限速（典型表现：TCP 握手正常但 UDP 大流量被限到 1–3Mbps，QUIC 协议被针对性丢包）。这就是为什么很多人"白天 4K 秒开，晚上 480p 都卡"。

专线机场的路径则完全不同：

```
[iPhone 小火箭]
      │
      ▼
[国内入口 (BGP 多线)]
      │
      ▼
[物理 IEPL/IPLC 内网隧道]  ← 点对点专线，不过公网国际出口，不过 GFW
      │  (0 丢包、低抖动、带宽独享或半独享)
      ▼
[香港/日本/新加坡原生机房落地]
      │
      ▼
[目标站点]
```

IEPL（International Ethernet Private Line）本质是运营商提供的二层点对点以太网专线，数据帧在内网传输，**不经过公网国际出口，因此不受 GFW 主动探测与跨境 QoS 影响**。实测差异：公网中转晚高峰丢包 8%–15%、RTT 抖动 ±60ms；IEPL 专线丢包 <0.1%、抖动 ±3ms。这个差距在小火箭里表现为"节点延迟 200ms 但网页秒开"（专线）vs "节点延迟 80ms 但视频卡顿"（公网中转，延迟低是因为测速点近，但实际带宽被 QoS 掐死）。

### 1.2 TCP 拥塞控制：为什么 BBR 在高丢包链路上碾压 Cubic

iOS 系统内核的 TCP 栈由 Apple 控制，用户无法直接改。但**服务端落地机的拥塞控制算法**会显著影响你的实际体验。Linux 内核默认 `cubic`，在丢包率 >2% 的链路上吞吐会断崖式下跌（Cubic 把丢包视为拥塞信号，激进降窗）。BBR（Bottleneck Bandwidth and RTT）则基于带宽与时延建模，不把丢包当拥塞，在高丢包跨境链路上吞吐可提升 3–10 倍。

服务端调优示例（机场运维视角，用户可用来判断机场是否专业）：

```bash
# /etc/sysctl.conf
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr

# 验证
sysctl net.ipv4.tcp_congestion_control
# 输出: net.ipv4.tcp_congestion_control = bbr

# BBRv3 需内核 6.x + 特定补丁，v2 在 5.4+ 可用
```

一个专业机场的落地机应当开启 BBR 或 BBRv2，并配置 `fq` 队列调度。你可以通过 `ss -ti` 观察连接状态确认：

```bash
ss -ti dst :443 | grep -o 'bbr\|cubic'
```

### 1.3 MTU/MSS 分片：小火箭里那个被忽视的"传输设置"

iOS 小火箭默认 MTU 1500，但跨境隧道封装（如 VLESS + TLS + WebSocket）会增加头部开销，实际可用 MTU 可能只有 1400–1440。若 MSS 未正确 clamp，会出现**大包被丢弃、小包正常**的诡异现象：网页能打开（小请求），但视频/下载卡死（大包分片丢失）。

排障抓包命令（在落地机或本地 Mac 上）：

```bash
# 抓 RST 包，判断是否被中间设备重置
tcpdump -i any 'tcp[tcpflags] & (tcp-rst) != 0' -nn

# 抓 ICMP 分片需要包
tcpdump -i any 'icmp and icmp[icmptype] == 3' -nn
# 若出现 "fragmentation needed"，说明 MTU 不匹配
```

小火箭内的解法：`设置 → 高级 → MTU` 调至 1400 或 1380 测试；或开启 `TCP Fast Open` 减少握手开销。这个细节在 90% 的教程里被忽略，却是"能上网页不能看视频"的头号元凶。

### 1.4 UDP QoS 与 QUIC 限速

运营商对 UDP 的 QoS 策略是跨境体验的隐形杀手。YouTube、Netflix 大量使用 QUIC（HTTP/3 over UDP 443），而部分运营商对 UDP 大流量实施令牌桶限速。表现为：TCP 测速正常，但视频加载慢。解法是让小火箭**强制走 TCP 回退**：在 `设置 → 高级 → 实验性功能` 中关闭 `HTTP/3`，或在规则里对特定域名 `REJECT-DROP` 掉 UDP 443 迫使回退 TCP。实测在部分移动网络下，关闭 QUIC 后 YouTube 4K 缓冲时间从 8 秒降到 2 秒。

## 二、Shadowrocket 规则集订阅与分流架构设计

### 2.1 规则集（Rule Provider）的工程价值

早期小火箭用户把几千条规则硬编码在配置文件里，导致：订阅更新慢、内存占用高、规则冲突难排查。`Rule Provider` 机制把规则拆成远程 `.list` 文件按需拉取，小火箭启动时只加载 `RULE-SET` 引用，命中时才解析具体规则。这是分流架构的现代化改造。

典型配置结构：

```ini
[Rule]
# 远程规则集引用（按需拉取，带缓存）
RULE-SET,https://example.com/rules/reject.list,REJECT
RULE-SET,https://example.com/rules/proxy.list,PROXY
RULE-SET,https://example.com/rules/direct.list,DIRECT

# 双层兜底：先 GEOIP 判国内，再 FINAL 兜底
GEOIP,CN,DIRECT
FINAL,PROXY,dns-failed
```

关键设计原则：
- **顺序即优先级**：`REJECT` 规则（广告/追踪）放最前，`PROXY` 次之，`DIRECT` 再次，`GEOIP,CN` 兜底国内，`FINAL` 兜底剩余。
- **`dns-failed` 兜底**：`FINAL,PROXY,dns-failed` 表示 DNS 解析失败时也走代理，避免国内 DNS 污染导致误判。
- **规则集来源要可信**：优先用 `blackmatrix7/ios_rule_script`、`Loyalsoldier/clash-rules` 等社区维护的规则集，避免使用来路不明的规则导致流量绕行。

### 2.2 避免国内直连流量绕行海外的三道防线

国内流量绕行海外是"流量偷跑"的典型症状：打开淘宝却走了代理，既慢又浪费流量。三道防线：

1. **`GEOIP,CN,DIRECT`**：基于 IP 归属地判定，覆盖绝大多数国内站点。
2. **`DOMAIN-SUFFIX,cn,DIRECT`**：`.cn` 域名直连，补充 GEOIP 的盲区（如 CDN 节点 IP 在海外但域名是 `.cn`）。
3. **`RULE-SET` 国内域名集**：把 `qq.com`、`taobao.com`、`bilibili.com` 等大流量站点显式列入 `DIRECT`，优先级高于 `GEOIP`。

验证方法：在小火箭 `首页 → 流量` 中观察实时连接，若打开淘宝时 `PROXY` 节点有流量，说明规则命中错误，需检查规则顺序。

### 2.3 DNS 防污染与防泄漏

小火箭的 DNS 设置是分流准确性的根基。推荐配置：

```
设置 → DNS → 覆盖 DNS
- 主 DNS: 223.5.5.5 (阿里，国内解析快)
- 备 DNS: 119.29.29.29 (腾讯)
- 代理 DNS: 8.8.8.8 或 https://dns.google/dns-query (DoH)
- 开启 "DNS 分流"：国内域名走国内 DNS，国外域名走代理 DNS
```

若 DNS 泄漏（国外域名用国内 DNS 解析），会遭遇 DNS 污染返回错误 IP，表现为"节点正常但打不开 Google"。检测：访问 `dnsleaktest.com`，若检测到国内 ISP 的 DNS 服务器解析了国外域名，即为泄漏。

## 三、HTTPS 解密（MITM）的边界与风险

小火箭的 `HTTPS 解密` 功能本质是中间人（MITM）：客户端安装并信任小火箭生成的根证书后，小火箭可解密 TLS 流量做内容级规则匹配（如按 URL 路径分流、去广告）。技术流程：

```
[App] --TLS--> [小火箭 (MITM)] --TLS--> [目标站点]
                    │
                    └─ 用自签根证书冒充目标站点证书
                       (需用户手动信任根证书)
```

**必须明确的边界**：
- **对流媒体 DRM 无效**：Netflix/Disney+ 使用证书固定（Certificate Pinning）+ Widevine DRM，MITM 会直接导致播放失败（错误码 M7361 等）。
- **对 AI 平台高风险**：ChatGPT/Claude 有严格的双向证书校验与行为风控，MITM 解密后的流量特征异常，极易触发 `1020` 拦截或账号风控。
- **仅建议用于**：去广告（按 URL 匹配）、抓包调试、特定 App 的精细化分流。

证书安装步骤（iOS）：
1. 小火箭 `设置 → 证书 → 生成根证书`。
2. 下载 `.cer` 文件，`设置 → 通用 → VPN与设备管理` 安装描述文件。
3. `设置 → 通用 → 关于本机 → 证书信任设置` 中**手动开启**对该根证书的完全信任（这一步 90% 的人漏掉，导致解密不生效）。

## 五、全平台客户端调优实战

### 5.1 iOS Shadowrocket 小火箭

1. **订阅导入**：`首页 → 右上角 + → 类型选 Subscribe → 粘贴订阅链接 → 保存`。开启 `自动更新`（建议 12 小时），避免节点失效。
2. **TUN 模式**：小火箭默认全局 TUN（iOS 上即 VPN 模式），无需额外配置，但需在 `设置 → 高级` 中确认 `全局路由` 为 `配置`（走规则）而非 `代理`（全走代理）。
3. **DNS**：按 2.3 节配置覆盖 DNS + DoH，开启 DNS 分流。
4. **规则集**：`配置 → 添加配置 → 从 URL 下载` 规则集配置文件，或手动编辑 `[Rule]` 段引用 `RULE-SET`。

### 5.2 Windows / macOS Clash Verge Rev

1. **导入订阅**：`订阅 → 新建 → 粘贴链接 → 导入`。
2. **TUN 模式**：`设置 → TUN 模式 → 开启`（需安装服务，Windows 需管理员权限）。TUN 模式接管全局流量，避免应用绕过代理。
3. **DNS 防泄漏**：`设置 → DNS → 开启 DNS 覆写`，配置 `nameserver: [223.5.5.5, 119.29.29.29]`、`fallback: [https://dns.google/dns-query]`，开启 `fallback-filter`。
4. **规则集**：使用 `rule-providers` 引用远程规则集，配置 `behavior: domain/ipcidr`。

### 5.3 Android Sing-box / v2rayNG

1. **Sing-box**：导入配置 JSON，开启 `TUN inbound`（需 VPN 权限），DNS 配置 `dns.strategy: ipv4_only` 避免 IPv6 泄漏。
2. **v2rayNG**：`订阅 → 导入`，`设置 → 路由 → 启用自定义路由`，导入规则集；开启 `分应用代理` 排除国内 App。
3. **防泄漏**：关闭系统 `私人 DNS`（会绕过客户端 DNS），或在 Sing-box 中强制 `dns.final: remote`。

## 六、深度疑难排障 FAQ

### Q1：节点全部超时、全红

排查分支：
1. **订阅是否过期/失效**：在浏览器打开订阅链接，若返回 404 或空内容，联系机场续费。
2. **本地网络是否正常**：关闭小火箭，测试国内网站；若国内也打不开，是本地网络问题（Wi-Fi/蜂窝）。
3. **系统时间偏差**：TLS 握手依赖时间，iOS 时间偏差 >5 分钟会导致证书校验失败。`设置 → 通用 → 日期与时间 → 自动设置`。
4. **节点被墙**：用 `ping` 或 `tcping` 测试节点 IP 端口，若 TCP 不通但订阅正常，是节点被封，切换节点或等待机场更换 IP。
5. 详细排障见站内 [梯子节点超时全红与连接失败排障指南](/tizi/nodes-timeout/)。

### Q2：国内网站正常，国外网站打不开

这是典型的**分流规则误判**或 **DNS 污染**：
1. 检查小火箭 `流量` 页，打开 Google 时是否走了 `PROXY`；若走了 `DIRECT`，是规则误判，调整 `GEOIP,CN` 顺序或补充域名规则。
2. 测试 DNS：`设置 → DNS` 中临时改为 `8.8.8.8` 全局代理 DNS，若恢复则原 DNS 被污染。
3. 检查是否开启了 HTTPS 解密但证书未信任，导致 TLS 失败。

### Q3：ChatGPT 报 1020 错误 / 无法访问

`1020` 是 Cloudflare 的 WAF 拦截码，根因是**节点 IP 被 OpenAI 风控**（共享 IP 被滥用）或 **MITM 解密导致流量特征异常**：
1. 关闭小火箭的 HTTPS 解密（`设置 → 证书 → 关闭解密`）。
2. 切换至原生 IP 节点（光速云、飞猫云的 AI 解锁节点实测通过）。
3. 清除浏览器 Cookie 与缓存，更换浏览器无痕模式重试。
4. 若仍失败，是节点 IP 段被整体封禁，需机场更换落地 IP。

### Q4：能上网页但视频/下载卡死

**MTU 不匹配**的典型症状（见 1.3 节）：
1. 小火箭 `设置 → 高级 → MTU` 从 1500 逐步降至 1400、1380 测试。
2. 关闭 `HTTP/3`（QUIC）强制 TCP 回退。
3. 若仅特定站点卡，可能是该站点 CDN 节点被 QoS，切换节点区域。

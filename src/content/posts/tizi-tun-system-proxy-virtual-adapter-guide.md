> **【💡 30 秒极速直接答案：TUN 模式启动失败三大核心元凶与黄金排障法则】**
> - **第一核心定性**：**“TUN 模式（虚拟网卡模式）是操作系统网络层（Layer 3）的驱动级接管技术，创建虚拟网卡属于系统最高高危操作；出现启动失败或开后断网，90% 的原因是客户端未以管理员权限启动、杀毒软件拦截了 `wintun.dll` 驱动、或存在残留的旧虚拟网卡发生网关跃点数死锁！”**；
> - **四类最常见 TUN 故障与对号入座解法**：
>   1. **勾选 TUN 模式报错“Permission Denied”或“创建适配器失败”** ──► 属于**缺少 Windows 管理员权限** ──► 退出软件，鼠标右键选择【以管理员身份运行】；
>   2. **一开启 TUN 模式，整台电脑所有网页瞬间彻底断网** ──► 属于**虚拟网卡默认路由劫持了代理流量造成“回环死锁”** ──► 重启客户端并确保 TUN 设置中开启【严格路由 (Strict Route)】；
>   3. **开启 TUN 后能翻墙，但家里的 NAS、路由器后台和打印机打不开了** ──► 属于**内网私有网段 (192.168.x.x) 被送入了虚拟网卡** ──► 在路由规则中确保局域网 CIDR 处于 DIRECT 放行状态；
>   4. **Clash Verge Rev 提示“服务模式未安装”** ──► 属于**Mihomo 内核未注册系统服务** ──► 点击【设置】──►【服务模式】点击安装并重启客户端。

## 三、致命杀手一：缺少管理员权限（UAC 驱动加载拒绝）

这是 80% 的 Windows 用户使用 TUN 模式失败的第一大诱因：

```text
 1. 【为什么必须给管理员权限？】：
    - 普通应用（如 Chrome、微信）只在“用户空间”运行；
    - TUN 模式需要在 Windows 底层网络适配器列表中**动态创建一张物理级虚拟网卡**，属于内核级（Kernel Mode）特权操作；
    - 若以普通双击打开客户端，Windows 操作系统会强制拦截驱动加载，直接导致“创建虚拟网卡失败”或“静默闪退”！

 2. 【永久赋予管理员权限极速实操】：
    - 彻底退出正在运行的客户端（托盘图标右键 ──► 退出）；
    - 找到客户端的桌面快捷方式或主程序 `.exe`，鼠标右键 ──► 选择【属性】；
    - 切换到【兼容性】标签页 ──► 勾选【以管理员身份运行此程序】；
    - 点击【应用】并【确定】保存。从此每次双击启动均全自动提权！
```

## 五、致命杀手三：局域网 NAS (192.168.x.x) 与打印机打不开排查

开启 TUN 模式后，很多用户发现“能看 YouTube，但访问家里的群晖 NAS、路由器后台 192.168.1.1 突然卡死”：

```text
 ⚠️ 【私有 IP 被误劫持的底层诱因】：
 - TUN 模式在接管全局三层流量时，若没有配置内网白名单，会将发往 `192.168.x.x` 或 `10.x.x.x` 的请求也一股脑发给虚拟网卡；
 - 虚拟网卡把局域网请求加密发往海外节点，海外服务器根本找不到你家的 NAS，导致连接超时！
 
 🟢 标准放行规则配置：
 - 在客户端自定义规则中添加以下私有网段直连规则：
   * `IP-CIDR,192.168.0.0/16,DIRECT,no-resolve`
   * `IP-CIDR,10.0.0.0/8,DIRECT,no-resolve`
   * `IP-CIDR,172.16.0.0/12,DIRECT,no-resolve`
   * `IP-CIDR,127.0.0.0/8,DIRECT,no-resolve`
 - 保存后刷新规则，局域网共享、NAS 挂载和网络打印机瞬间恢复秒开！
```

## 六、TUN 模式下的 DNS 劫持防泄漏机制

开启 TUN 模式后，系统 DNS 查询由虚拟网卡完全接管：

```text
 1. 【DNS 劫持防投毒原理】：
    - 传统 Wi-Fi 环境下，电脑发往 53 端口的 DNS 查询极易被本地路由器或宽带运营商劫持；
    - 开启 TUN 模式后，虚拟网卡会强制将本地所有发往 53 端口的 UDP 请求拦截并送入代理内核；
    - 由内核通过加密 DoH 或远端节点查询真实海外 IP，彻底消灭 DNS 污染与 DNS 泄漏！

 2. 【Fake-IP 与 TUN 的天作之合】：
    - 强烈建议在 TUN 模式下搭配 **[Fake-IP 模式](/tizi/fake-ip/)** 使用；
    - 内核在 1ms 内直接向应用返回 `198.18.x.x` 虚拟 IP，省去漫长的 DNS 往返耗时，网页秒开率提升 50% 以上。
```

## 九、常见问题解答 (FAQ)

### Q1：为什么开启 TUN 模式时会提示“Wintun create adapter failed”或“权限不足”？
**答**：**因为未以管理员身份运行！** 创建虚拟网卡属于 Windows 高危内核级操作，必须彻底退出客户端，在程序图标右键选择【以管理员身份运行】，再次开启即可顺利加载驱动。

### Q2：一勾选 TUN 模式，整台电脑所有网页瞬间彻底断网怎么回事？
**答**：通常是因为虚拟网卡配置的默认路由抢占了物理网关，导致客户端发往海外节点的加密流量被虚拟网卡自身二次捕获，形成了“流量死循环回环”。彻底退出软件，重启电脑释放网络栈，并确保在 TUN 设置中开启【严格路由 (Strict Route)】。

### Q3：为什么打外服网游（如 Apex、Steam）普通系统代理没用，必须开 TUN？
**答**：因为绝大多数联机网游的实时对战数据走的是**无连接的 UDP 协议**；普通系统代理仅支持 HTTP/Web 协议，完全无法转发 UDP；TUN 模式具备驱动级底层捕获能力，能完美转发并加速游戏 UDP 数据流。

### Q4：Clash Verge Rev 提示“服务模式未安装”无法开启 TUN 模式怎么办？
**答**：进入 Clash Verge Rev 左侧【设置】──► 找到【服务模式 (Service Mode)】──► 点击右侧的【安装】按钮；在弹出的 Windows UAC 提示框中点击“是”，安装成功后旁边显示绿色盾牌图标，即可正常开启 TUN 模式。

### Q5：开启 TUN 模式之后，为什么家里的局域网 NAS (192.168.1.x) 打不开了？
**答**：因为局域网私有网段被虚拟网卡错误劫持了。在分流规则中确保包含 `IP-CIDR,192.168.0.0/16,DIRECT` 规则，并确保分流模式处于【Rule 规则模式】即可恢复。

### Q6：开启 TUN 模式后，任务栏右下角的「系统代理」还需要开启吗？
**答**：**不需要！** TUN 模式已经在最底层的网络层（Layer 3）完成了整机所有流量的接管，系统代理（Layer 7）处于完全多余的状态，即便关闭系统代理，整台电脑所有应用依然能正常翻墙。

### Q7：v2rayN 的 TUN 核心选择里，Xray 和 Sing-box 推荐选哪一个？
**答**：**强烈推荐首选 Sing-box！** Sing-box 原生针对 TUN 模式进行了极深度的性能优化，CPU 与内存占用远低于 Xray，且对 Windows 路由表的托管更稳定，不易发生死循环断网。

### Q8：遇到 TUN 模式故障，最忌讳的操作是什么？
**答**：最忌讳“不给管理员权限盲目连续快速反复开关 TUN 勾选框”。这会导致 Windows 驱动接口在内核层挂起僵死；规范做法是以管理员启动 ──► 清理残留 TAP 网卡 ──► 开启飞行模式重置网络栈。

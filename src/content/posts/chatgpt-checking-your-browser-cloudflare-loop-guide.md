## 一、Checking your browser 是什么意思？

**“Checking your browser before accessing chatgpt.com”** 是 Cloudflare 提供的**自动化访问环境安全检验机制（Cloudflare Challenge）**。

```text
[发起访问请求] ──► [Cloudflare 边缘分发 Challenge 脚本] ──► [本地浏览器执行 JS 并写入 cf_clearance Cookie] ──► [放行进入 ChatGPT]
```

它并不是要求你输入复杂的文字验证码，而是通过在你的浏览器后台快速运行一段轻量级算法，核验以下 4 个关键指标：
1. **浏览器环境是否具备完整的 JavaScript 解析与渲染能力**；
2. **浏览器是否能够正常接收并持久化保存安全会话 Cookie（如 `cf_clearance`）**；
3. **当前访问客户端是否呈现合法的浏览器指纹特征（排除自动化攻击脚本）**；
4. **客户端连接的 TLS 握手特征与网络传输时延是否符合安全基准**。

## 二、为什么 ChatGPT 会一直停在验证界面？（核心诱因剖析）

如果你卡在验证界面长达数分钟，或者反复点击复选框却陷入死循环，说明上述验证链条在某一节点发生了断裂：

- **JavaScript 执行受阻**：浏览器安全等级过高或 NoScript 插件阻止了 Challenge 脚本运算；
- **Cookie 存储被阻断**：启用了“严格阻止所有跨站 Cookie”或浏览器设置了“关闭页面时立即抹除数据”，导致验证通过后签发的通行证无法存入本地；
- **强效广告与反追踪插件拦截**：uBlock Origin、Privacy Badger 或某些防指纹追踪扩展将 Cloudflare 的验证回调判定为跨站追踪并强行屏蔽；
- **系统时钟严重脱轨**：计算机本地系统时间偏差超过 60 秒，导致安全 Token 签发即过期；
- **网络出口节点高频波动**：使用了高丢包的共享代理出口，TCP 连接在验证数据回传瞬间发生断流重置。

## 三、Checking your browser 和 Access Denied 1020 的本质区别

很多用户容易将“浏览器验证循环”与“1020 报错”混为一谈，两者的处理逻辑截然不同：

| 对比维度 | Checking your browser / 人机验证循环 | Access Denied / Error 1020 |
| :--- | :--- | :--- |
| **当前所处阶段** | **环境检验中**（系统正在尝试给你的浏览器发通行证） | **已被明确拒绝**（系统已判定当前请求不符合安全规则） |
| **核心交互特征** | 页面有转圈动画、复选框，反复验证不通过 | 页面直接展示静态报错红字与 Ray ID，无任何验证入口 |
| **故障主要归属** | **本地浏览器环境、Cookie 写入、插件拦截** | **网络出口 IP 信誉、地区限制、防火墙黑名单** |
| **解决主攻方向** | 无痕测试、清理单站点 Cookie、关闭拦截插件 | 更换高信誉网络出口、检查代理规则分流 |
| **对应技术指南** | **当前页面（浏览器验证循环排查）** | 📖 [ChatGPT Access Denied 1020 专题](/issues/chatgpt-access-denied/) |

## 四、第一步：先核验 OpenAI 官方服务状态

虽然验证循环多发生于客户端环境，但当 OpenAI 官方遭遇全球范围的 **Web 鉴权微服务中断（Authentication / Cloudflare Outage）** 时，同样会导致全球用户的验证回调无法被后端接收。

- **官方状态监控中心**：[status.openai.com](https://status.openai.com/)
- **重点排查项**：查看 `ChatGPT` 与 `Cloudflare / CDN edge` 是否处于全绿 *Operational* 状态。若官方正在处理宕机事故，请暂停本地调试，等待官方修复。

---

## 五、第二步：使用无痕隐身模式（最快排查试金石）

无痕模式（Incognito / Private Window）是排查浏览器验证循环**最灵敏的诊断工具**：

```text
[开启无痕隐身窗口] ──► [隔离旧 Cookie 与 Session] + [纯净环境无插件干扰] ──► [访问 chatgpt.com]
```

- **诊断结论**：
  - 若在无痕窗口中**一秒顺利通过验证**：100% 证明你的网络、电脑和账号完全正常，问题纯粹是普通模式下的 **Cookie 冲突** 或 **扩展插件拦截**；
  - 若无痕窗口中**依然死循环**：排除了浏览器插件与旧缓存影响，需重点排查 **网络环境**、**系统代理** 或 **系统时钟**。

## 六、第三步：检查浏览器的 JavaScript 运行权限

Cloudflare Challenge 核心依赖前端 JS 算力。如果你的浏览器禁用了脚本，页面将永远卡在加载阶段。

### 检查与放行步骤（以 Chrome / Edge 为例）：
1. 访问 `https://chatgpt.com/`；
2. 点击地址栏左侧的 **【查看网站信息】（锁形或控制台图标）**；
3. 点击 **【网站设置】（Site settings）**；
4. 找到 **【JavaScript】** 选项，确保其状态为 **【允许（默认）】**，切勿误设为“禁止”。

---

## 七、第四步：检查 Cookie 权限与精准清理站点数据

验证通过后，Cloudflare 会在你的浏览器中植入名为 `cf_clearance` 的高权限安全 Cookie。如果这个 Cookie 无法写入或已损坏，浏览器就会陷入“验证通过 ──► 重新刷新 ──► 再次要求验证”的死循环。

### 1. 确保未完全禁用第三方 Cookie
进入 Chrome【设置】──►【隐私与安全】──►【第三方 Cookie】，选择 **【在无痕模式下屏蔽第三方 Cookie】** 或 **【允许第三方 Cookie】**，不要勾选全局“屏蔽所有 Cookie”。

### 2. 精准清空 ChatGPT 站点 Cookie（保留其他网站登录）
1. 访问 `https://chatgpt.com/`；
2. 点击地址栏左侧锁形图标 ──►【Cookie 和网站数据】；
3. 点击【管理设备端网站数据】，将 `openai.com` 和 `chatgpt.com` 点击垃圾桶删除；
4. 按下 `Ctrl + F5` 强制刷新重新进行验证。

## 八、第五步：浏览器扩展插件冲突排查与处置

安装了过多的广告拦截、安全防护或脚本管理插件，极易在后台误杀 Cloudflare 的验证通信：

| 插件类别 | 典型插件代表 | 对验证循环的潜在破坏行为 | 推荐处置方案 |
| :--- | :--- | :--- | :--- |
| **广告拦截类** | uBlock Origin, AdBlock Plus | 误将验证回调 API 判定为跨站广告脚本并直接拦截 | 将 `chatgpt.com` 加入插件白名单 |
| **隐私反追踪类** | Privacy Badger, DuckDuckGo | 强行清除 `cf_clearance` 安全 Cookie | 临时暂停该站点的隐私防护 |
| **脚本控制类** | NoScript, Tampermonkey | 阻断动态注入的 Challenge 加密计算函数 | 允许当前页面所有脚本执行 |
| **自动翻译类** | 沉浸式翻译, 谷歌翻译插件 | 实时篡改 DOM 树结构导致验证哈希校验失败 | 设置为“不对此页面进行自动翻译” |

## 九、第六步：浏览器 Cache（静态缓存）vs Cookie 区别

| 存储维度 | 存储的具体内容 | 损坏时对验证的影响 | 修复建议 |
| :--- | :--- | :--- | :--- |
| **Cache (静态缓存)** | HTML、CSS 样式、JS 验证脚本文件 | 持续运行旧版验证代码导致校验失败 | 按 `Ctrl+F5` 强制硬刷新 |
| **Cookie (会话通行证)** | `cf_clearance`、OAuth 鉴权令牌 | 验证成功后无法持久化通行证 | 清除对应域名下的设备端数据 |
| **Local Storage** | 本地应用主题、用户前端缓存 | 前端界面状态无法正确挂载 | 在 F12 应用程序面板中清除 |

## 十、第七步：为什么 Chrome 一直循环，换 Edge 或 Safari 就正常？

这种跨浏览器对比结果清晰表明：**问题 100% 局限在 Chrome 浏览器的本地运行环境**。

### Chrome 本地故障点深挖：
1. **Chrome 用户配置文件（Profile）出现逻辑损坏**：进入 Chrome 设置，点击右上角头像【添加新用户配置文件】，在全新的纯净 Profile 中打开 ChatGPT；
2. **Chrome 的安全 DNS（DoH）机制发生解析阻断**：进入 Chrome【设置】──►【隐私与安全】──►【安全】，关闭“使用安全 DNS”后测试。

## 十一、第八步：Brave 与 Firefox 严格隐私模式冲突排查

以极客隐私著称的 **Brave 浏览器** 和 **Firefox 严格模式** 用户，极易因为过度防御而遭遇验证循环：

- **Brave 浏览器**：点击地址栏右侧的 **狮子头像（Brave Shields 盾牌）**，将针对 `chatgpt.com` 的盾牌防护开关 **临时拨动至关闭 (DOWN)**，即可秒过验证；
- **Firefox 浏览器**：进入【设置】──►【隐私与安全】，若开启了“严格”增强型跟踪保护，请点击地址栏左侧盾牌图标，为该网站单独关闭保护。

## 十二、第九步：VPN / Proxy 代理环境对验证的影响

使用代理或 VPN 时频繁出现验证循环，并不一定代表节点被封，而是由以下网络链路特性引起的：

1. **共享出口并发数过高**：同一个代理出口 IP 同时有数百台设备在进行高频请求，触发了 Cloudflare 的敏感防护阈值；
2. **代理链路上存在丢包抖动**：Challenge 验证需要在几秒内完成多轮 TLS 往返通信，若节点丢包率 > 5%，会导致验证包中途超时丢失；
3. **验证建议**：关闭代理工具，在普通网络下测试页面能否正常加载；若必须使用网络加速，请优先选择稳定低丢包的 [企业级 IEPL 专线](/recommend/airport/)。

## 十三、第十步：系统日期与时钟同步校准

Cloudflare 签发的验证凭据严格绑定 **UNIX 时间戳**。如果你的电脑时钟偏快或偏慢超过 60 秒，签发的安全 Token 将被直接判定为失效：

- **Windows 10/11 修复**：进入【设置】──►【时间和语言】──►【日期和时间】──► 开启【自动设置时间】并点击【立即同步】；
- **macOS 修复**：进入【系统设置】──►【通用】──►【日期与时间】──► 勾选【自动设置日期和时间】。

遇到顽固的验证死循环时，利用手头的设备与网络进行 1 分钟交叉比对即可直击病灶：

| 交叉测试组合 | 测试结果 A | 测试结果 B | 权威诊断结论 |

| **同一电脑：Chrome vs Edge** | Edge 成功 | Chrome 循环 | **Chrome 浏览器 Profile/缓存/扩展冲突** |
| **同一手机：Wi-Fi vs 4G/5G流量** | 蜂窝流量成功 | Wi-Fi 循环 | **家庭 Wi-Fi 路由器 DNS/局域网网络策略问题** |

## 十五、为什么手机流量正常，连接家里 Wi-Fi 却一直卡验证？

当设备未变，**仅切换 Wi-Fi 与蜂窝数据**即可解决问题时：
- **路由器 DNS 解析异常**：家庭宽带分配的默认 Local DNS 响应迟缓或存在缓存污染，将电脑网卡 DNS 改为公共 DNS（`1.1.1.1` 或 `8.8.8.8`）；
- **局域网出口 IP 临时降权**：家庭宽带分配的公网 IPv4 段刚好处于高风控区间，重启光猫与路由器重新获取全新出口 IP 即可。

## 十六、公司或学校企业网络一直卡验证的原因

企业办公室和大学校园网通常部署有深度网络行为管理设备：
- **TLS 深度报文检测（SSL Inspection）**：企业网关尝试对加密流量进行拆包审计，破坏了 Cloudflare 的原生加密通信握手；
- **Web Filtering 策略限制**：内网策略阻断了第三方安全鉴权域名的长连接；
- **建议**：遵守企业与校园网络安全合规规范，切勿尝试违规破坏内网安全边界。

## 二十、绝对不建议采用的 10 项高危错误操作

切勿使用以下存在极大安全隐患的非正规手段：

1. ❌ **不要在验证界面连续疯狂点击勾选复选框几十次**（极易被系统直接风控拉黑）；
2. ❌ **不要安装声称能“一键跳过 Cloudflare 验证”的未知浏览器插件**；
3. ❌ **不要运行网络上来源不明的 Python / Node.js 自动化绕过脚本**；
4. ❌ **不要永久关闭浏览器的隐私与安全防护功能**；
5. ❌ **不要向任何第三方网站提供你的浏览器完整 Cookie 或 Token**；
6. ❌ **不要看到验证循环就误以为账号被封而盲目重新注册**；
7. ❌ **不要随意关闭系统防火墙或电脑自带的安全中心**；
8. ❌ **不要频繁以秒级速度疯狂切换几十个不同的网络代理节点**；
9. ❌ **不要直接格式化电脑系统**（99% 仅属浏览器层问题）；
10. ❌ **不要将环境验证循环与密码错误混淆反复找回密码**。

## 二十一、常见问题解答 (FAQ)

### Q1：Checking your browser 到底是在验证什么？
**答**：这是 Cloudflare 部署的自动化安全校验（Cloudflare Challenge）。主要核验你的浏览器是否能正常运行 JavaScript 代码、能否合法保存会话 Cookie，以及客户端是否具备合法的浏览器指纹特征，以阻断恶意脚本的自动化攻击。

### Q2：为什么点击“Verify you are human”后会一直转圈死循环？
**答**：最常见原因是验证通过后生成的安全 Cookie（`cf_clearance`）未能成功写入本地存储，或者被浏览器的广告/隐私拦截插件当作跨站脚本直接掐断。开启无痕窗口或清理对应站点数据即可解决。

### Q3：为什么无痕模式（Incognito）能秒过，普通窗口一直验证？
**答**：无痕模式天然隔离了所有旧版本脏缓存与冲突 Cookie，且默认关闭了绝大部分第三方扩展。无痕能秒过，100% 证明你的网络与电脑完全正常，只需在普通窗口中清理 `chatgpt.com` 站点数据并排查插件即可。

### Q4：Chrome 一直卡验证，换用微软 Edge 为什么就能正常进入？
**答**：这表明问题纯粹出在 Chrome 本地的运行环境中。通常是因为 Chrome 安装了拦截性质的扩展插件、开启了冲突的安全 DNS，或者 Chrome 用户配置文件（Profile）损坏。

### Q5：广告拦截插件（如 uBlock Origin）为什么会引起验证死循环？
**答**：部分广告拦截插件内置的过滤规则过于严苛，误将 Cloudflare 用于传递验证结果的跨域 API 判定为追踪脚本并直接阻断。将 `chatgpt.com` 添加至插件白名单即可恢复。

### Q6：Brave 浏览器一直卡在人机验证怎么办？
**答**：Brave 自带的“Brave Shields（盾牌）”对指纹追踪防御极为严密，可能导致验证加密计算被拒。点击地址栏右侧的狮子头像，为当前网页暂时关闭 Shields 保护即可顺利通过。

### Q7：开 VPN / 代理后为什么验证特别频繁？
**答**：这通常是因为所使用的代理节点属于多用户高频共享出口，短时间内请求量过大触发了安全阈值；或者节点链路丢包率较高导致验证数据包在传输过程中断裂。

### Q8：为什么每次换一个节点就要重新验证一次？
**答**：因为 Cloudflare 的安全通行证（`cf_clearance`）在签发时与当前的出口 IP 和 TLS 特征强绑定。当你切换节点导致出口 IP 发生突变时，安全系统会要求重新进行环境检验。

### Q9：电脑系统时间不准会导致验证循环吗？
**答**：**是的，非常致命。** 验证 Token 的有效期是基于精确的 UNIX 时间戳计算的。若电脑时钟慢了或快了几分钟，Token 刚签发就会被系统判定为已过期，从而陷入无限验证。

### Q10：为什么手机连同一个 Wi-Fi 能过，电脑却一直卡验证？
**答**：这排除了宽带和路由器问题。电脑端失败重点排查：电脑时钟是否自动同步、电脑浏览器是否开启了拦截扩展、电脑是否安装了开启网页流量监控的杀毒软件。

### Q11：为什么手机 4G/5G 流量正常，连接家里 Wi-Fi 却卡验证？
**答**：说明问题出在家庭宽带或路由器网络层。可能是家庭宽带分配的出口 IP 临时信誉偏低，或者路由器 DNS 响应延迟过高。建议重启路由器并将 DNS 改为 `1.1.1.1`。

### Q12：公司或学校办公室网络为什么总是反复验证？
**答**：企业和校园网通常部署有深度防火墙和 SSL 解密网关，破坏了 Cloudflare 的原生安全握手。若属企业合规限制，建议遵守单位 IT 管理规范。

### Q13：清理浏览器 Cookie 会清空我的 ChatGPT 聊天记录吗？
**答**：**绝对不会。** Cookie 只存储在本地设备用于维持登录与验证状态；你的历史对话记录全部安全存储在 OpenAI 云端数据库中，重新登录后会自动同步。

### Q14：Checking your browser 卡住是不是代表我的账号被封了？
**答**：**完全不是。** 浏览器验证发生在进入登录界面之前的边缘网络层，此时你甚至还没输入账号密码，系统根本不知道你是谁。这完全是本地客户端与网络环境的验证问题。

### Q15：每次打开 ChatGPT 都要验证一次，这算故障吗？
**答**：只要勾选一次能正常进入，就属于正常的安全防御机制（尤其在使用动态 IP 时）；只有当**反复勾选无限循环、永远无法进入页面**时，才属于需要排查的故障。

### Q16：提示 Access Denied 1020 和这个验证循环是一回事吗？
**答**：不是。验证循环是环境校验未完成（还有机会通过）；而 1020 报错是请求已经被 Cloudflare 防火墙明确阻断拒绝。关于 1020 请阅读 [ChatGPT 1020 深度解决方案](/issues/chatgpt-access-denied/)。

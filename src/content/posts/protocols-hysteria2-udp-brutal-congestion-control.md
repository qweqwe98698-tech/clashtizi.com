> **核心导读 (TL;DR)**
> - **物理链路决定上限**：跨境晚高峰 20:00–23:00 的丢包根源在运营商国际出口的队列溢出与 UDP 限速策略，而非协议本身；IEPL/IPLC 物理专线因不过公网出口，天然规避该问题，而公网 BGP 中转方案必须靠 Brutal 这类激进算法硬扛。
> - **Brutal 的本质是"放弃探测、锁定带宽"**：它不依赖 RTT 与丢包反馈动态收敛窗口，而是以用户声明的目标带宽为基准持续发包，丢包时按固定比例补偿，因此在 15%–30% 丢包区间吞吐量仍能维持标称值的 70% 以上，代价是对同链路其他流量的公平性牺牲。
> - **UDP QoS 是 Hysteria2 的最大敌人**：部分运营商对非标准端口的高频 UDP 流做令牌桶限速甚至直接丢包，端口跳跃（port hopping）通过周期性切换目标端口绕过基于五元组的限速识别，是公网部署的必要对策。
> - **客户端调优三要素**：`up/down` 带宽声明须贴近真实物理带宽的 80%、开启 TUN 模式接管全流量、DNS 走 DoH/DoT 防污染；专线场景下推荐光速云、飞猫云等 IEPL 架构，公网场景下 Hysteria2 + 端口跳跃配合星岛梦企业内网专线做兜底。

## 一、问题的起点：一次晚高峰抓包看到的真相

2026 年 9 月的一个周三晚 21:17，我在一台位于华东的测试机上对某公网中转节点做持续 iperf3 打流，同时挂 `tcpdump` 抓包。现象很典型：TCP Cubic 流在丢包率从 0.3% 爬升到 8% 的 90 秒内，吞吐从 180 Mbps 断崖式跌到 12 Mbps，重传率飙到 22%；而同链路切到 Hysteria2（Brutal，声明 100 Mbps）后，吞吐稳定在 68–74 Mbps，重传率虽高但有效载荷吞吐几乎不掉。

这个对比不是玄学，是两种拥塞控制哲学的分野。要理解 Hysteria2 为什么"暴力"，必须先拆开标准 TCP 拥塞控制的内核逻辑。

### 1.1 TCP 拥塞控制的收敛逻辑与它的软肋

TCP 的拥塞控制本质是一个**闭环负反馈系统**：发送端根据 ACK 返回速率、RTT 变化和丢包事件推断网络可用带宽，动态调整拥塞窗口（cwnd）。

- **Cubic**（Linux 默认）：以三次函数曲线增长窗口，丢包时 cwnd 乘以 β=0.7 的乘性递减。它的设计假设是"丢包≈拥塞"，在低丢包的有线网络里表现优秀，但在高丢包、高 RTT 的跨境链路上，每一次丢包都被误判为拥塞，窗口反复腰斩，吞吐量呈锯齿状塌陷。
- **BBRv1**：不再把丢包当拥塞信号，而是用"最大带宽采样 + 最小 RTT"建模管道容量，丢包时窗口不缩减。这是巨大进步，但 BBRv1 在高丢包场景下会过度激进地维持高发送速率，导致链路 buffer 长期满载，排队延迟（bufferbloat）恶化，且与其他 Cubic 流共存时抢占严重。
- **BBRv2/v3**：引入丢包率与 ECN 作为收敛约束，公平性改善，但在 20% 以上随机丢包时仍会主动降速——因为它终究要"尊重"丢包的信号。

关键点在于：**所有主流 TCP 拥塞控制都把丢包当作需要退让的信号**。而跨境公网的丢包，绝大多数不是链路拥塞，而是国际出口路由器在队列满时的尾丢包、运营商 QoS 策略性丢包、以及光缆抖动导致的随机丢包。对这些"非拥塞型丢包"退让，就是白白浪费带宽。

### 1.2 Brutal 的机理：从"探测"到"声明"

Hysteria2 的 Brutal 算法（源自原 Hysteria 的 Brutal 拥塞控制，作者 Toby）彻底换了一套逻辑：

1. **用户声明目标带宽**（客户端配置里的 `up`/`down`），算法直接以此为目标发送速率，不做带宽探测。
2. **丢包补偿**：当检测到丢包时，按 `发送速率 = 目标速率 / (1 - 丢包率)` 的公式放大实际发包量，用冗余对抗丢包。丢包 20% 时，实际发包量提升到目标的 1.25 倍，有效载荷仍能接近目标值。
3. **不缩窗**：无论丢包多严重，只要没触发连接级失败，发送窗口不主动收缩。

用 ASCII 表达两种算法在丢包阶梯下的行为差异：

```
吞吐量 (Mbps)
100 |                    ┌─────── Brutal (声明100M, 丢包补偿)
    |              ┌─────┘
 80 |        ┌─────┘
    |   ┌────┘
 60 | ┌─┘
    | │
 40 | │
    | │
 20 | │         ╲
    | │          ╲___╲___╲___  BBRv2
  0 |─┴───────────────────────────────
       0%   5%   10%   15%   20%   25%   丢包率
```

Brutal 的代价同样明确：它**不遵守拥塞公平性**，在同一条瓶颈链路上会挤占其他 TCP 流的带宽。这也是它只适合在"自己可控的跨境链路"上用的原因——你是在用别人的公平性换自己的吞吐。在共享公网出口上滥用 Brutal 会加剧整条链路的拥塞，这是工程伦理问题，也是为什么生产环境更推荐物理专线。

### 1.3 QUIC 底座与 UDP 的宿命

Hysteria2 跑在 QUIC（基于 UDP）之上，这带来两个结构性后果：

- **优势**：QUIC 在用户态实现拥塞控制与丢包恢复，可以自由替换算法（Brutal 就是插进来的），且 0-RTT 握手、多路复用无队头阻塞，跨境高 RTT 下建连更快。
- **劣势**：UDP 在公网上是"二等公民"。运营商对 UDP 的 QoS 策略远比 TCP 激进——因为历史上 UDP 常被 P2P、DDoS 滥用。典型策略包括：对非 443/80 端口的高频 UDP 流做令牌桶限速（如限制到 5 Mbps）、对 UDP 流做深度包检测后丢包、NAT 表项老化过快导致长连接中断。

这就引出了端口跳跃的必要性。

## 二、运营商 UDP QoS 的微观特征与端口跳跃对策

### 2.1 UDP 限速的识别维度

运营商 QoS 设备（多为华为/思科 BRAS 上的策略引擎）识别"可疑 UDP"通常基于五元组 + 流量特征：

- **端口维度**：非标准端口的 UDP 流优先级低，443 端口 UDP（HTTP/3）通常放行较好。
- **速率维度**：单流 UDP 超过阈值（常见 3–10 Mbps）触发令牌桶限速。
- **时长维度**：同一五元组持续高频发包超过 N 秒，标记为"长流"降级。
- **包长维度**：固定大包（如 1400 字节满载）比混合包更容易被识别为隧道流量。

实测中，某运营商对 UDP 50000 端口的单流限速在持续 40 秒后触发，吞吐从 90 Mbps 降到 4.2 Mbps，且伴随 30% 的策略性丢包。这就是"用着用着突然变慢"的元凶。

### 2.2 端口跳跃的实现机制

Hysteria2 的端口跳跃（`server` 端配置 `listen` 为一个端口范围，客户端配置 `server: host:port1-port2`）让客户端在连接期间周期性切换目标端口。服务端在整段端口范围上监听，客户端每隔 `hopInterval`（默认几十秒）换一个端口重建 QUIC 连接（或迁移连接）。

效果：QoS 设备的五元组限速表刚建立就被打断，令牌桶来不及积累到限速阈值，长流标记也无法形成。实测同一链路开启端口跳跃后，UDP 限速触发时间从 40 秒推迟到"几乎不触发"，吞吐稳定在 60–80 Mbps。

配置示例（服务端 `config.yaml`）：

```yaml
listen: :20000-30000
```

客户端：

```yaml
server: your.domain.com:20000-30000
hopInterval: 30s
```

注意：端口跳跃要求服务端防火墙放行整段端口，且部分云厂商安全组对端口范围有数量限制，需提前规划。

### 2.3 端口跳跃的边界与风险

- 跳跃频率过高（< 10s）会导致频繁重连，握手开销反而拖累吞吐，建议 20–40s。
- 部分严格的 QoS 会追踪源 IP 而非五元组，端口跳跃无效，此时只能靠专线或换出口 IP。
- 端口范围过大会触发云厂商的异常流量告警，建议控制在 1000 个端口以内。

## 三、物理链路：IEPL/IPLC 与公网 BGP 中转的抖动差异

### 3.1 拓扑对比

```
【公网 BGP 中转方案】
[终端客户端]
   │  (国内公网, 可能被 QoS)
   ▼
[国内多线 BGP 入口]
   │  (国际出口, 晚高峰丢包 5%-25%)
   ▼
[境外中转节点] ──► [落地机房] ──► 目标网站
   ▲
   └─ 全程走公网, 每一跳都可能丢包/抖动

【IEPL 物理专线方案】
[终端客户端]
   │  (国内公网到入口, 短距离)
   ▼
[国内多线 BGP 入口]
   │  ═══ 物理 IEPL 内网隧道 (点对点, 0 丢包, 不过 GFW) ═══
   ▼
[香港/日本原生机房落地出口] ──► 目标网站
   ▲
   └─ 跨境段走专线内网, 与公网出口物理隔离
```

差异的核心在跨境段：公网 BGP 中转的跨境流量与全网用户共享国际出口带宽，晚高峰出口队列溢出是丢包的物理根源；IEPL（International Ethernet Private Line）是运营商提供的点对点二层专线，带宽独享、物理隔离，跨境段延迟抖动通常 < 2ms，丢包率接近 0。

### 3.2 抖动数据对比

| 指标 | 公网 BGP 中转（晚高峰） | IEPL 专线（晚高峰） |
|---|---|---|
| 平均 RTT（华东→香港） | 45–90ms（波动大） | 32–38ms（稳定） |
| RTT 抖动（jitter） | 15–40ms | 1–3ms |
| 丢包率 | 5%–25% | < 0.1% |
| 吞吐稳定性 | 锯齿状 | 平稳 |

这解释了为什么"专线 + 普通 TCP"往往比"公网 + Brutal"体验更好：专线从物理层消除了丢包，BBR 就能正常工作，无需 Brutal 的暴力补偿。而公网场景下，Brutal + 端口跳跃是性价比最高的组合。两者不是替代关系，是不同链路的对症下药。

## 四、Linux 内核与客户端调优参数

### 4.1 服务端/落地机 sysctl 调优

```bash
# 拥塞控制与队列
net.core.default_qdisc=fq
net.ipv4.tcp_congestion_control=bbr

# UDP 缓冲区（Hysteria2 高吞吐必需）
net.core.rmem_max=16777216
net.core.wmem_max=16777216
net.ipv4.udp_rmem_min=8192
net.ipv4.udp_wmem_min=8192

# 连接跟踪表扩容（端口跳跃大量新建连接）
net.netfilter.nf_conntrack_max=1048576
net.netfilter.nf_conntrack_udp_timeout=60

# 文件描述符
fs.file-max=1048576
```

应用后 `sysctl -p` 生效，用 `sysctl net.ipv4.tcp_congestion_control` 验证。

### 4.2 抓包排障命令

```bash
# 抓 RST 包，判断是否被中间设备重置
tcpdump -i any 'tcp[tcpflags] & (tcp-rst) != 0' -nn

# 抓 UDP 丢包与 ICMP 不可达
tcpdump -i any 'udp port 20000:30000' -nn -c 1000

# 统计某目标 IP 的 UDP 包速率，判断是否触发限速
tcpdump -i any -nn 'udp and dst host 1.2.3.4' -w udp.pcap
```

### 4.3 Hysteria2 客户端带宽声明原则

`up`/`down` 必须贴近真实物理带宽的 70%–80%，声明过高会触发链路拥塞和 QoS，声明过低浪费带宽。例如 500 Mbps 家宽，建议 `down: 400 mbps`、`up: 80 mbps`（上行按运营商实际上行填）。

## 七、全平台客户端调优实战

### 7.1 Windows / macOS：Clash Verge Rev

1. 下载安装 Clash Verge Rev（GitHub Releases）。
2. 从机场复制订阅链接，进入「订阅」→「导入」，粘贴链接。
3. 开启 **TUN 模式**（设置 → TUN 模式 → 开启，需管理员权限），接管全系统流量，避免部分应用绕过代理。
4. **DNS 设置**：进入「设置 → DNS」，开启「DNS 覆写」，配置 `https://1.1.1.1/dns-query` 或 `https://dns.google/dns-query` 作为 DoH，防止 DNS 污染与泄漏。关闭「系统 DNS」回退。
5. Hysteria2 节点若含端口范围（如 `:20000-30000`），Clash Verge Rev 的 Mihomo 内核原生支持，直接使用订阅即可。

### 7.2 iOS：Shadowrocket 小火箭

1. App Store 购买安装（需非国区 Apple ID）。
2. 复制订阅链接，小火箭首页右上角「+」→ 类型选「Subscribe」→ 粘贴 → 保存。
3. 点击订阅更新节点列表，选择 Hysteria2 节点。
4. **全局路由**：设置 → 全局路由 → 选「配置」或「代理」，按需分流。
5. **DNS**：设置 → DNS → 开启「DNS over HTTPS」，填 `https://1.1.1.1/dns-query`；关闭「绕过本地 DNS」。
6. 开启「始终开启 VPN」防断连。详细分流规则见 [Shadowrocket 小火箭 iOS 安装与分流教程](/shadowrocket/)。

### 7.3 Android：Sing-box / v2rayNG

**Sing-box**：
1. 安装 Sing-box for Android（官方或 SFA）。
2. 导入订阅（支持 Hysteria2 原生）。
3. 开启 TUN 模式（设置 → 入站 → TUN → 启用），需授予 VPN 权限。
4. DNS 配置走 `h3://1.1.1.1/dns-query` 或 `tls://dns.google`。完整配置见 [Sing-box 全能通用配置与路由规则教程](/tutorials/sing-box-config/)。

**v2rayNG**：
1. 安装后「订阅设置」→ 添加订阅 → 更新。
2. 注意 v2rayNG 对 Hysteria2 支持依赖内核版本，建议用支持 sing-box 内核的衍生版。
3. 路由模式选「绕过大陆」，DNS 选「远程 DNS」。Windows 端排障见 [v2rayN Windows 客户端配置与排障完整教程](/v2rayn/)。

### 7.4 通用调优要点

- **带宽声明**：Hysteria2 客户端 `up/down` 按物理带宽 80% 填。
- **MTU**：QUIC 默认 1200–1350，跨境链路遇分片问题可降到 1280。
- **端口跳跃**：公网节点务必开启，`hopInterval: 30s`。
- **DNS 防泄漏**：所有平台统一走 DoH/DoT，禁用系统明文 DNS。

## 八、常见疑难问题排障（FAQ）

### 8.1 节点全部超时、全红

**排查分支**：
1. 先 `ping 8.8.8.8` 确认本地网络通；不通则是本地网络问题。
2. 通但节点全红 → 检查订阅是否过期、流量是否耗尽（登录机场面板看）。
3. 订阅正常 → 用 `curl -v https://订阅域名` 测试订阅拉取是否被墙；被墙则换订阅域名或手动导入节点。
4. 节点可拉取但连接失败 → 检查系统时间是否准确（QUIC 对时间敏感，偏差 > 30s 握手失败），校准 NTP。
5. 仍失败 → 抓包看是否有 RST，判断是否被中间设备重置。完整流程见 [梯子节点超时全红与连接失败排障指南](/tizi/nodes-timeout/)。

### 8.2 国内网站正常、国外打不开

**根因**：分流规则错误或 DNS 污染。
1. 检查客户端路由模式是否为「规则/配置」而非「直连」。
2. 测试 `nslookup google.com 1.1.1.1` 与本地 DNS 结果对比，若本地返回污染 IP（如 0.0.0.0 或错误地址），开启 DoH。
3. 检查规则列表是否误把目标域名归入直连。
4. TUN 模式未开时，部分应用不走代理，开启 TUN 重试。

### 8.3 ChatGPT 报 1020 / 地区限制

**根因**：出口 IP 被 OpenAI 判定为高风险（数据中心 IP 或共享 IP 滥用）。
1. 换节点，优先选标注「原生 IP / 纯净解锁」的节点（光速云、飞猫云均有）。
2. 清除浏览器 Cookie 与缓存后重试，避免旧会话绑定旧 IP。
3. 检查是否开启了 WebRTC 泄漏，浏览器装 WebRTC 防泄漏插件。
4. 若仍 1020，说明该 IP 段被整体标记，联系机场换落地。

### 8.4 用着用着突然变慢（UDP 限速）

**根因**：运营商 UDP QoS 触发。
1. 观察是否在使用 40–60 秒后降速，符合令牌桶特征。
2. 开启端口跳跃，`hopInterval` 设 20–30s。
3. 换 443 端口的 UDP 节点（HTTP/3 端口放行较好）。
4. 若端口跳跃无效（QoS 追踪源 IP），换专线节点。
5. 用 `tcpdump` 对比限速前后的包速率，确认是限速而非链路拥塞。

### 8.5 连接成功但速度极低

1. 检查客户端 `up/down` 是否声明过低（如误填 10 mbps）。
2. 测本地到入口的 RTT，若 > 150ms 说明绕路，换入口。
3. 检查是否走了 IPv6 导致绕路，禁用 IPv6 重试。
4. 换协议测试（Hysteria2 换 VLESS），定位是协议问题还是链路问题。

## 九、结论与选型建议

把技术逻辑收束成可执行的决策：

- **公网场景**：Hysteria2 + Brutal + 端口跳跃是抗丢包的性价比之王，带宽声明按 80% 填，端口跳跃 30s，配合 DoH 防污染。适合预算敏感、能接受一定波动。
- **专线场景**：IEPL/IPLC 从物理层消灭丢包，BBR + VLESS 即可跑满，Brutal 收益有限。光速云、飞猫云、无忧链接的专线架构在此场景更稳。
- **游戏/低延迟**：星岛梦企业内网专线，RTT 抖动最小。
- **大流量/追剧**：唯兔云三网优化大带宽。
- **轻量办公**：微风网络低门槛。

更多机场横向对比与实时节点状态，见 [2026 翻墙机场推荐与专线节点排行榜速查](/recommend/airport/)；新手从零开始，先读 [科学上网新手入门使用全指南](/tizi/how-to-use/)。

协议是工具，链路是地基。理解 Brutal 为什么暴力、端口跳跃为什么有效、专线为什么稳，比记住任何一个配置参数都重要——因为网络环境在变，机理不变。

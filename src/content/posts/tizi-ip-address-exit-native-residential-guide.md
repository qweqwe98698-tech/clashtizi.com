> **【💡 30 秒看懂：开梯子后 IP 为什么会变？】**
> - **不开代理时**：你的电脑 ──► 本地宽带运营商 ──► 目标网站（网站看到的是你家的**国内宽带公网 IP**）；
> - **开启代理时**：你的电脑 ──► 加密隧道 ──► 海外代理节点 ──► 目标网站（网站看到的是节点的**海外公网出口 IP**）；
> - **切换节点时**：从香港节点切到日本节点，出口服务器发生了更换，目标网站检测到的 IP 与地理位置自然同步改变。

## 一、本地私有 IP vs 运营商公网 IP vs 代理出口 IP

在理解梯子 IP 之前，必须分清以下 3 种处于不同网络层级的 IP 地址：

```text
                               【从局域网到海外出口的数据包演进】

 [个人设备 (手机/PC)] ──────► [家庭路由器] ──────► [运营商出口 (ISP)] ──────► [海外代理出口 (Node)] ──────► [目标网站]
   192.168.1.100              192.168.1.1          114.88.x.x (国内公网)        104.28.x.x (海外出口)
   (本地私有内网 IP)          (默认局域网网关)      (家庭宽带真实出口)          (Google / ChatGPT 看到的 IP)
```

### 核心 IP 术语权威定义表：

| IP 术语分类 | 本质属性与所处位置 | 能否在公网直接路由 | 目标网站能否直接看到 |
| :--- | :--- | :--- | :--- |
| **内网 IP (私有地址)** | 路由器分配给设备的地址（如 `192.168.x.x`） | ❌ 仅限家庭/局域网内部通信 | ❌ 绝不可能直接看到 |
| **本地公网 IP** | 电信/联通宽带或 5G 基站分配的国内公网出口 | ✅ 可在全网路由传输 | 不开梯子时看到 |
| **代理出口 IP (Exit IP)**| **海外服务器代理中继节点对外发包的公网 IP** | ✅ 可在全网路由传输 | **开启梯子后看到** |

## 二、入口节点 vs 出口 IP：为什么中转节点名称和出口不一致？

很多用户困惑：“为什么我选了名叫 `香港 01` 的节点，测速网站却显示 IP 在日本或新加坡？”

```text
 [你的电脑] ──(国内直连)──► [国内中继入口机房 (如深圳/上海)] ──(内网专线)──► [海外落地出口机房 (香港/日本)] ──► [目标网站]
                              └──────── 入口节点名称 ────────┘              └────── 最终出口 IP (决定地区) ──────┘
```

- **中继架构与出口解耦**：现代优质机场普遍采用中转/专线架构。用户连接的是位于国内的“入口中继机房”，而最终访问外网的是海外的“落地出口机房”；
- **命名与出口微调**：节点名称是由服务商人工标记的展示文本。若服务商临时将香港出口调度至日本机房容灾，就会出现“名字叫香港、实际出口是日本”的正常调度现象。

## 三、机房 IP vs 住宅 IP vs 原生 IP 深度拆解

市场上有大量关于 IP 属性的营销术语，我们从技术底层对其进行客观澄清：

| IP 核心类别 | 真实技术来源与网络属性 | 典型使用场景 | 常见认知误区纠偏 |
| :--- | :--- | :--- | :--- |
| **机房 IP (数据中心 IP)** | 亚马逊 AWS、谷歌云、甲骨文等大型机房托管网络 | **绝大多数常规机场与翻墙节点** | 并不是劣质 IP，大机房带宽充裕、抗抖动能力极强 |
| **住宅 IP (ISP 宽带 IP)** | 挂载在当地民用宽带（如美国 Comcast / AT&T）上的 IP | 跨境电商、特定海外本土业务 | ❌ **绝非“防封神仙水”，也无法保证 100% 免验证** |
| **原生 IP (Native IP)** | **市场口语俗称**：指 IP 注册地、广播地与使用地一致 | 流媒体地区版权校验、AI 场景 | ❌ **并非互联网 RFC 正式标准，仅为中文圈营销术语** |

```text
 💡 核心认知纠偏：
 1. “原生 IP” 不是一种技术协议，只代表该 IP 块在各大地理数据库中的登记信息较为规整；
 2. 任何宣称“使用住宅 IP 即可 100% 避免平台风控 / 随意违规不封号”的说法均为虚假营销！
```

## 四、为什么不同的 IP 查询网站，测出的地区完全不一样？

经常出现“网站 A 测出是香港，网站 B 测出是新加坡”的矛盾现象，原因在于底层数据库的差异：

```text
 全球并没有一个唯一的“官方实时 IP 地址定位中心”！
 每一个 IP 查询网站 ──► 读取各自采购的商业【IP 地理数据库】 (如 MaxMind, IPinfo, DB-IP)
                            │
                     数据库更新周期不同 (有些按周、有些按季度)
                     IP 资源发生跨国租借或 BGP 广播迁移时 ──► 导致不同查询站识别结果冲突！
```

### 主流平台与 IP 地理数据库差异表：

| 平台或查询系统 | 地区识别核心依据 | 刷新与同步特性 | 为什么会发生地区误判 |
| :--- | :--- | :--- | :--- |
| **普通 IP 查询站 (ipinfo/ip138)** | 第三方商业 IP 离线数据库 | 定期批量同步更新 | 若该 IP 刚从美国调拨到香港，旧数据库仍显示美国 |
| **Google / YouTube** | 自研全球网络拓扑 + 用户搜索历史 | 实时动态计算 | 结合了你的 Google 账户偏好和历史常用语言 |
| **OpenAI / [ChatGPT](/chatgpt/cannot-open/)** | 严格机房 ASN 风控库 + 实时安全规则 | 高频实时校验 | 针对大规模爬虫机房 IP 实施单独的地区阻断 |
| **Netflix / Disney+** | 版权方定制机房黑名单库 | 商业反代理系统 | 针对数据中心托管 IP 限制非自制剧内容播放 |

## 五、静态 IP vs 动态 IP & 共享 IP vs 独享 IP

| IP 运作机制 | 核心运作逻辑 | 典型优势 | 潜在短板与注意事项 |
| :--- | :--- | :--- | :--- |
| **动态 IP (Dynamic)** | 每次连接或机房轮询时，公网出口 IP 发生变动 | 抗封锁能力强，单个 IP 被阻断不影响整体 | 登录敏感账户时频繁换 IP 易触发异地二次验证 |
| **静态 IP (Static)** | 长期固定使用某一个特定公网 IP 地址 | 适合企业服务器白名单、远程办公绑定 | 一旦该 IP 被目标网站风控，整条线路彻底无法使用 |
| **共享 IP (Shared)** | 机场内数百名用户共同通过同一台出口服务器上网 | 成本极低、性价比高 | 邻居违规操作可能导致该公网 IP 被特定平台连带风控 |
| **独享 IP (Dedicated)**| 该海外公网 IP 仅分配给你个人单独使用 | IP 使用历史完全纯净可控 | 采购成本极高，单点故障风险大 |

## 六、分流规则（Rule）导致不同网站看到不同 IP 的现象

在客户端开启 [Rule 规则分流模式](/clash-verge-rev/) 时，流量会按域名分道扬镳：

```text
                             【分流规则下的多出口 IP 并存现象】

 你的浏览器同时打开两个标签页：
 ├─ 标签页 1：访问【百度 / 淘宝】 ──(命中国内 Direct 规则)──► [国内家庭宽带出口 (看到你的真实宽带 IP)]
 └─ 标签页 2：访问【Google / YouTube】 ──(命中 Proxy 代理规则)──► [海外香港节点出口 (看到香港机房 IP)]
```

- **正常现象解答**：在 Rule 模式下，国内查 IP 网站显示你家宽带、海外查 IP 网站显示香港节点，这正是分流规则生效的完美体现。

```text
 ❌ 误区 1：开启梯子后，手机系统里的 GPS 硬件定位也会自动飞到海外。(错！GPS 依赖卫星硬件芯片)
 ❌ 误区 2：只要买了“住宅 IP”，在任何海外网站随便操作都不会被封号。(错！风控依赖多维度特征)
 ❌ 误区 3：节点名字叫“美国 01”，它的机房物理位置就一定在洛杉矶市政中心。(错！名字仅供区分)

 ❌ 误区 5：原生 IP 一定比机房 IP 网速更快、延迟更低。(错！速度只取决于海缆带宽与物理距离)
 ❌ 误区 6：换个浏览器打开网页，代理节点的出口 IP 就会跟着变。(错！出口 IP 由客户端节点决定)
 ❌ 误区 7：更改电脑本地 DNS 地址可以直接把美国 IP 变成日本 IP。(错！DNS 只负责域名解析)
 ❌ 误区 8：独享静态 IP 永远不会被目标网站拦截封禁。(错！恶意请求依然会被封)
 ❌ 误区 9：使用共享 IP 会导致自己的电脑密码被同机房邻居盗取。(错！HTTPS 传输端到端全加密)
 ❌ 误区 10：只要关闭客户端，刚才访问过的网站就会立刻忘记我。(错！浏览器 Cookie 依然保留)
 ❌ 误区 11：Auto 自动测速模式下，我的出口 IP 会一直保持不变。(错！Auto 随时可能切换节点)
 ❌ 误区 12：IPv6 开启会导致所有国外网站都能看到真实地址。(错！现代客户端已支持 IPv6 代理)
 ❌ 误区 13：IP 被查询网站标为“Hosting”就代表不能正常上网。(错！Hosting 仅代表机房属性)
 ❌ 误区 14：只要把系统语言换成英文，网站就会把我的 IP 识别为美国。(错！语言与 IP 相互独立)
 ❌ 误区 15：一个公网 IP 只能同时供一个人使用。(错！NAT 技术支持数千人共享同一公网出口)
```

## 八、常见问题解答 (FAQ)

### Q1：为什么开启梯子后，在百度搜索“IP”显示的还是我家里的地址？
**答**：因为客户端处于【Rule 规则模式】。百度属于国内网站，命中规则后走国内直连，因此显示真实宽带 IP；如果去 `ipinfo.io` 等外网查询，就会显示海外节点 IP。

### Q2：为什么我的节点名字叫“香港 01”，但在部分网站上却显示在“日本”？
**答**：1. 服务商采用了国内中转调度，出口落地机房临时切换了备份线路；2. 目标网站使用的 IP 地理数据库更新滞后，尚未同步该 IP 块的最新调拨归属地。

### Q3：什么是“原生 IP”？它和普通节点有什么区别？
**答**：“原生 IP”是代理行业中的市场俗称，指该 IP 块的注册所在地与实际机房使用地完全一致。它不是互联网官方标准，仅代表在流媒体等特定版权检测中被识别的地区较为准确。

### Q4：什么是“住宅 IP”？它真的能防止账号被封吗？
**答**：住宅 IP 是指分配给民用家庭宽带的 IP 地址。它绝不能防止违规封号，各平台的风控算法综合考量设备指纹、行为特征、注册资料与支付凭证，切勿盲目迷信。

### Q5：手机开启梯子后，为什么地图软件依然能精准显示我在国内的街道位置？
**答**：因为地图 App 调用的是手机底层的 **GPS 卫星定位芯片、附近 Wi-Fi MAC 地址与蜂窝基站定位**，这些硬件级物理信号完全不受网络代理 IP 影响。

### Q6：频繁切换不同国家的节点（如一会儿美国、一会儿香港）会有什么风险？
**答**：容易触发海外高敏感平台（如 Google、ChatGPT、PayPal）的异地登录安全风控，导致账号被临时锁定或要求多重验证，日常建议固定同一国家节点。

### Q7：什么是“动态 IP”与“静态 IP”？日常翻墙应该选哪种？
**答**：动态 IP 会定期变动出口，抗封锁与抗干扰能力更强，是绝大多数机场的默认配置；静态 IP 长期固定不变，主要用于跨国企业远程办公白名单与特定开发场景。

### Q8：开启【Global 全局代理模式】后，为什么所有的查 IP 网站都显示海外了？
**答**：因为 Global 模式强制让操作系统所有联网请求（不论国内国外）一律通过海外节点转发，此时国内网站也会看到你的海外代理出口 IP。

### Q9：使用共享节点，同机场的其他用户能看到我访问的具体网页内容吗？
**答**：看不到。现代互联网均基于 HTTPS 加密传输协议，数据在你的浏览器与目标网站服务器之间是端到端加密的，同节点的其他用户无法解密你的传输内容。

### Q10：为什么有时候断开梯子重新连接，查到的公网 IP 变了？
**答**：因为很多机场采用了后端负载均衡集群（Load Balancing），每次握手可能会将你分配至该地区机房的不同出口服务器，属于正常负载分配现象。

### Q11：换一个浏览器（如从 Chrome 换到 Edge），梯子的出口 IP 会变吗？
**答**：不会。代理出口 IP 是由桌面客户端连接的海外服务器决定的，与你使用哪款浏览器软件完全无关。

### Q12：为什么访问 ChatGPT 时提示“Not available in your country”，但我明明连了美国节点？
**答**：通常是因为该节点机房被 OpenAI 识别为了大规模滥用数据中心并进行了局部限制，切换为日本或新加坡的原生纯净节点即可恢复，详见 [ChatGPT 无法打开排查](/chatgpt/cannot-open/)。

## 二、为什么锁屏会断开？开启「按需连接 (On Demand)」实现永不断连

很多苹果用户最头疼的问题就是“手机只要息屏锁屏，微信就收不到海外推送，一亮屏才看到 VPN 刚刚重新连上”：

```text
 1. 【iOS 熄屏省电机制内幕】：
    - iPhone 在锁屏后 3~5 分钟，为了极限省电，系统会将 Wi-Fi 芯片切换至超低功耗休眠模式；
    - 此时所有的活跃 TCP 连接会被迫掐断；如果小火箭没有被系统授权“按需拉起”，整个 VPN 隧道就会被系统彻底释放销毁。

 2. 【一键开启【按需连接 (On Demand)】完美解决】：
    - 打开 Shadowrocket 底部【设置 (Settings)】──► 进入【按需连接 (On Demand)】；
    - 将【总是开启 (Always On)】或【按需连接】开关切实打开；
    - 原理：该功能会写入 iOS 系统的底层 VPN 描述文件。一旦系统检测到手机发起网络访问需求，iOS 会在毫秒级自动在后台静默拉起小火箭的 VPN 隧道，彻底告别锁屏断连！
```

## 四、最隐蔽掉线元凶：规则文件过大触发 iOS Jetsam 内存强杀

这是绝大多数普通用户和新手教程都不知道的深层系统级硬伤：

```text
 ⚠️ 【iOS 对网络扩展的残酷物理内存限制】：
 - 普通 iOS 前台 App（如大型手游）可以使用 2GB~3GB 内存；
 - 但通过 Network Extension 框架运行的后台网络插件（包括小火箭、Surge、Loon），
   被苹果系统施加了极其残酷的硬性内存封顶（通常仅为【15MB~30MB】！不同机型略有差异）；
 
 💣 为什么大规则集是闪退强杀元凶？
 1. 许多小白喜欢从 GitHub 导入包含数十万条规则、几百个正则匹配的所谓“超级万能全去广告规则库”；
 2. 当这些规则全部加载到内存并构建路由树时，瞬时内存消耗会飙升至 35MB 以上；
 3. iOS 底层的 Jetsam 内存守护进程会将其无情判定为“内存泄漏”，直接以 SIGKILL 信号强行闪退杀死小火箭进程！
 4. 解决办法：坚决使用小火箭默认的精简规则文件（如 default.conf），规则行数尽量控制在 5000 行以内！
```

## 五、多 VPN 冲突与苹果私密转送 (iCloud Private Relay) 排查

```text
 1. 【苹果单一活动 VPN 通道限制】：
    - iOS 系统在同一瞬间只允许**一个主 Network Extension** 独占系统数据流；
    - 若手机后台开着其他商业 VPN、游戏加速器或某些安全杀毒软件的“流量防护”；
    - 一旦后台其他软件尝试唤醒更新，iOS 就会瞬间剥夺并关停小火箭的 VPN 通道，造成无预警闪断。

 2. 【iCloud 私密转送 (Private Relay) 的干扰】：
    - 如果你的 Apple ID 开通了 iCloud+，并在系统【设置】──►【Apple ID】──►【iCloud】中开启了【私密转送】；
    - 在某些网络抖动时，Safari 可能会绕过小火箭直接强走苹果的私密通道，造成小火箭流量中断假死；
    - 建议在使用小火箭期间，临时在系统设置中暂停 iCloud 私密转送。
```

## 九、常见问题解答 (FAQ)

### Q1：为什么 iPhone 只要一锁屏熄屏，小火箭就会自动断开？
**答**：这是 iOS 的省电休眠机制：锁屏后系统会主动休眠 Wi-Fi 芯片并关闭后台套接字。进入小火箭【设置】──► 开启【按需连接 (On Demand)】，即可授权系统在需要时自动保持或重新拉起隧道。

### Q2：为什么从家里走出室外（Wi-Fi 切成 5G）之后网络会卡死断开？
**答**：因为底层的物理网卡和内网 IP 发生了根本性改变，旧的 TCP 隧道被重置挂起。开启手机【飞行模式】5 秒后关闭，强制让 iOS 系统释放旧接口并重连即可瞬间恢复。

### Q3：为什么小火箭经常莫名其妙自动退出闪退，再次点开发现重新启动？
**答**：90% 是因为导入了过于臃肿的规则文件！iOS 系统给网络扩展施加了残酷的内存封顶（通常仅 15~30MB）；规则过多导致内存溢出触发系统 Jetsam 强杀。换用精简规范的规则文件即可根治。

### Q4：手机开启了“低电量模式”，会对小火箭网络产生影响吗？
**答**：**影响极其严重！** 低电量模式会严苛限制 CPU 算力，并强行阻断所有后台网络扩展的自动心跳维持，极易造成小火箭频繁假死断流；建议在使用科学上网时关闭低电量模式。

### Q5：为什么我和室友同时用一个机场订阅，我经常被踢掉线？
**答**：因为机场服务商通常对单订阅设定了【最大同时在线设备数】（例如限 2 台）。若多台设备同时发起连接，后端鉴权集群会自动踢掉最早连接的设备；一人一账号或购买多设备套餐即可解决。

### Q6：什么是「按需连接 (On Demand)」？开启后会非常耗电吗？
**答**：不会！按需连接是苹果官方标准的高级网络特性，仅在检测到网络请求时在毫秒级自动激活通道，平时处于极低功耗挂起状态，是彻底杜绝锁屏断连的最佳官方解法。

### Q7：频繁掉线的时候，疯狂快速开关连接能恢复吗？
**答**：**绝对不要疯狂快速连击！** 连续频繁重启主开关会导致 iOS 的 Network Extension 进程陷入死锁甚至崩溃；正确做法是开启飞行模式等待 10 秒后再关掉，实现底层的优雅重置。

### Q8：遇到经常掉线，最忌讳的操作是什么？
**答**：最忌讳“病急乱投医从网上乱找臃肿的规则集导入，或者把手机彻底还原网络设置”。按照“开启按需连接 ──► 关闭低电量模式 ──► 换用轻量规则 ──► 检查多设备冲突”单变量逐层排查即可轻松定位根因。

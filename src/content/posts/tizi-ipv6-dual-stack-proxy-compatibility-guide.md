> **【💡 30 秒看懂：梯子环境下的 IPv6 到底是何原理？】**
> - **IPv6 的本质**：互联网第六版网络协议，拥有 128 位超大地址空间。现代家庭宽带与手机流量普遍支持 **IPv4 + IPv6 双栈共存**；
> - **为什么开梯子后“IPv4 变了，IPv6 没变”？** 很多客户端默认只接管了 IPv4 流量，当某个海外网站同时拥有 IPv6 地址时，浏览器可能通过未受代理保护的本地 IPv6 物理宽带直连访问；
> - **核心纠偏**：**千万不要长期一键关闭系统的 IPv6！** 禁用 IPv6 仅作为快速排查的对照变量，真正根治需要让代理客户端（如开启 [TUN 虚拟网卡](/tizi/tun/)）正确配置 IPv6 路由与分流。

## 一、IPv4 vs IPv6 核心技术特征对比总表

| 核心对比维度 | IPv4 (传统第四版协议) | IPv6 (新一代第六版协议) | 在梯子与代理环境中的实际表现 |
| :--- | :--- | :--- | :--- |
| **地址位数与格式** | 32 位（点分十进制，如 `192.0.2.1`） | 128 位（冒号十六进制，如 `240e::1`） | IPv6 地址长度极大，无需复杂的 NAT 端口映射 |
| **DNS 解析记录** | **A 记录** | **AAAA 记录** | 支持双栈的网站会同时返回 A 与 AAAA 记录 |
| **本地链路地址** | 169.254.x.x (APIPA) | `fe80::/10` (Link-Local) | ⚠️ **`fe80::` 仅限局域网通信，绝不属于公网 IP 泄漏** |
| **客户端代理成熟度** | 🟢 **100% 完美支持与全量接管** | 🟡 取决于节点线路、TUN 驱动与 Core 配置 | 需确认客户端是否开启了 IPv6 路由接管 |
| **传输速度与延迟** | 取决于物理光缆与节点线路 | 取决于物理光缆与节点线路 | ❌ **IPv6 并不天然比 IPv4 网速快或延迟低** |
| **隐私安全性** | 共享 NAT 公网出口 | 现代系统默认采用**随机临时隐私地址** | ❌ **IPv6 并不自动提供加密或防追踪能力** |

## 二、IPv6 地址分类与“非公网伪泄漏”辨析

很多小白在 IP 网站上看到 IPv6 字符串就误以为发生了严重泄漏，请对照以下地址类型表：

| IPv6 地址类型 | 标准前缀范围 | 实际网络作用域 | 是否属于公网 IP 暴露 |
| :--- | :--- | :--- | :--- |
| **全球单播公网地址 (GUA)** | `2000::/3` (如 `240e:`, `2408:`, `2409:`) | 全球互联网可路由通信 | 🔴 若本应走代理却直连，属于公网暴露 |
| **链路本地私有地址 (Link-Local)** | `fe80::/10` | 仅在当前 Wi-Fi/交换机同一网段内通信 | 🟢 **完全安全**，路由器局域网通信，外网无法访问 |
| **唯一本地私有地址 (ULA)** | `fc00::/7` / `fd00::/8` | 类似 IPv4 的 `192.168.x.x` 内网私有段 | 🟢 **完全安全**，企业专网或局域网私有地址 |
| **环回测试地址 (Loopback)** | `::1` | 类似 IPv4 的 `127.0.0.1` 本地回环 | 🟢 **完全安全**，本机内部进程通信 |

## 三、深度拆解：“节点支持 IPv6”的三层不同含义

在购买机场套餐或配置代理节点时，用户常说的“支持 IPv6”必须严格拆分为以下 3 个完全独立的层级：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【节点 IPv6 三层能力独立解剖】                                │
 ├──────────────────────────────┬──────────────────────────────┬──────────────────────────────┤
 │ 维度 1：客户端连接节点 (入口) │ 维度 2：节点访问目标 (中继)  │ 维度 3：目标网站所见 (出口)  │
 ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┤
 │ 你的宽带能否通过 IPv6 地址    │ 代理节点服务器能否与目标网站 │ 访问 IP 查询网站时，是否能   │
 │ 成功连接机场的海外入口服务器 │ 的 IPv6 服务器建立 TCP 连接  │ 显示为该节点的专属 IPv6 地址 │
 └──────────────────────────────┴──────────────────────────────┴──────────────────────────────┘
```

> **💡 核心真相**：即便你买的节点**只有 IPv4 出口**，只要代理客户端启用了 DNS 转换或 Fake-IP 机制，你依然可以顺畅访问全球所有支持 IPv6 的海外网站（内核会自动将请求封装在 IPv4 隧道内转发）。

## 四、为什么开梯子后“IPv4 变了，IPv6 仍是本地宽带”？

这是双栈网络环境下最典型的问题，其根本排障逻辑如下：

```text
 1. 【核心诱因】：
    - 代理客户端仅开启了 System Proxy（系统 HTTP 代理），未接管操作系统的原生 IPv6 网络栈；
    - 浏览器通过 Happy Eyeballs 算法发现该网站有 AAAA 记录，直接调用系统的 IPv6 物理网卡发起直连。

 2. 【是否属于 IP 泄漏？】：
    - 如果该网站是国外受限网站（如 ChatGPT、Google），这属于【意外直连旁路】，会导致访问被拦截；
    - 如果该网站是国内网站（如百度、Bilibili），命中 [分流规则](/tizi/routing-rules/) Direct 直连，这属于【完全预期的国内直连】，绝非故障。
```

## 六、IPv6 异常 5 分钟极速排障 SOP（标准 HowTo）

遇到开启代理后外网打不开、提示 IPv6 连接超时时，按以下 6 步标准流程排查：

```text
 Step 1: 检查本地网络 IPv6 基础 ──► 退出代理，访问测试网站确认自己的家庭宽带本身是否具备 IPv6
    ↓
 Step 2: 检查客户端 IPv6 开关 ──► 在 Clash Verge Rev 或 sing-box 设置中，确认勾选了【允许 IPv6 (IPv6 Ingress/Routing)】
    ↓
 Step 3: 启用 TUN 虚拟网卡 ──► 开启 [TUN 模式](/tizi/tun/)，确保系统底层的 IPv6 数据包全量进入 Core
    ↓
 Step 4: 检查分流规则库 ──► 在 [分流规则](/tizi/routing-rules/) 中确认没有意外将 `::/0` 判为 Direct
    ↓
 Step 5: 临时做 A/B 对照测试 ──► 在系统网络适配器中短暂禁用 IPv6；若网页瞬间秒开，说明代理 Core 存在 IPv6 路由黑洞
    ↓
 Step 6: 恢复系统标准配置 ──► 在客户端中配置 Fake-IP 过滤或修复 TUN 驱动，重新开启系统 IPv6 保持健康双栈
```

## 七、关于 IPv6 与梯子的 15 大核心认知误区

```text
 ❌ 误区 1：IPv6 是下一代梯子加速协议，开启 IPv6 以后节点网速会自动翻倍。(错！IPv6 只是底层网络寻址协议)
 ❌ 误区 2：只要开启了梯子，电脑上的本地 IPv6 地址就会瞬间消失。(错！本地物理网卡的 IP 永远不会消失)
 ❌ 误区 3：在 IP 查询网站上看到 `fe80::` 开头的地址说明梯子发生了严重泄露。(错！fe80 为局域网私有地址)
 ❌ 误区 4：遇到任何翻墙网络故障，第一步都应该直接在注册表里永久禁用 IPv6。(错！会破坏系统双栈与现代服务)
 ❌ 误区 5：IPv6 地址包含了电脑的真实物理 MAC 地址，因此没有任何隐私性可言。(错！现代系统全面采用随机临时地址)
 ❌ 误区 6：所有海外机场提供的节点都必须自带独立的 IPv6 公网出口。(错！IPv4 隧道同样能无缝中继 IPv6 访问)
 ❌ 误区 7：访问国内百度显示了国内的 IPv6 地址，说明梯子分流彻底失效了。(错！国内直连命中 Direct 属正常分流)
 ❌ 误区 8：TUN 模式开启后就 100% 绝对不可能发生任何 IPv6 绕过直连。(错！需确认 TUN 网卡正确配置了 IPv6 路由)
 ❌ 误区 9：Ping 某个 IPv6 域名不通，说明该海外网站彻底宕机了。(错！很多海外服务器防火墙禁用了 ICMPv6 探测)
 ❌ 误区 10：移动蜂窝数据网络因为没有光纤宽带，所以绝对不可能支持 IPv6。(错！移动网络 IPv6 普及率远高于固网)
 ❌ 误区 11：在同一个 Wi-Fi 下，手机和电脑获取到的 IPv6 公网前缀一定完全不同。(错！同一局域网共享同一分配前缀)
 ❌ 误区 12：DNS 只要返回了 AAAA 记录，浏览器就绝对不可能再使用 IPv4 访问。(错！Happy Eyeballs 机制会自动竞速择优)
 ❌ 误区 13：企业内网屏蔽了个人代理的 IPv6 是客户端 Bug。(错！企业防火墙与安全策略有权实施合规管控)
 ❌ 误区 14：只要把所有 IPv6 规则都改成 Reject，就能彻底解决网络变慢问题。(错！会导致支持纯 IPv6 的服务直接断连)
 ❌ 误区 15：一个代理节点只要延迟标绿，就代表其 IPv6 出口性能一定和 IPv4 完全一致。(错！两者路由可能跨越不同物理海缆)
```

## 八、常见问题解答 (FAQ)

### Q1：梯子里的 IPv6 到底是什么意思？
**答**：IPv6 是互联网第六版寻址协议。在梯子使用场景中，主要指你的本地网络、代理客户端以及海外节点是否能够正确处理和转发 128 位的 IPv6 数据包，避免流量意外绕过代理发生直连。

### Q2：为什么开启梯子后，IPv4 地址变成了海外，但 IPv6 依然显示国内？
**答**：因为客户端仅接管了系统的 IPv4 流量，未对 IPv6 流量进行虚拟网卡捕获或路由接管；当网站支持 IPv6 时，浏览器便通过本地物理宽带直连访问。开启 [TUN 模式](/tizi/tun/) 即可彻底接管。

### Q3：IPv6 到底会不会导致真实的家庭住址被精确定位？
**答**：不会。IP 地理定位仅能精确到城市或运营商机房级别，现代操作系统普遍采用动态随机临时地址（RFC 4941），绝不会暴露物理门牌号或设备硬件 MAC。

### Q4：为什么说“不建议长期在电脑中永久关闭 IPv6”？
**答**：因为现代操作系统（Windows/macOS）的很多核心网络组件（如远程协同、局域网发现）高度依赖 IPv6；直接禁用可能引发系统级网络异常，正确的做法是在代理客户端内规范 IPv6 路由。

### Q5：什么是 Happy Eyeballs 算法？
**答**：Happy Eyeballs（RFC 8305）是现代浏览器和网络库采用的双栈双向并发建连机制。它会同时向 IPv4 和 IPv6 发起握手探测，自动选择响应最快、最先建立成功的通道传输数据。

### Q6：什么是 DNS 的 AAAA 记录？
**答**：AAAA 记录是 DNS 域名解析中专门用于指向 IPv6 地址的解析记录（而 A 记录指向传统的 IPv4 地址）。

### Q7：开梯子后访问某些网站提示“连接超时”，关掉 IPv6 就好了，这是为什么？
**答**：这说明你的代理客户端或节点虽然接到了 IPv6 请求，但由于海外节点没有可用的 IPv6 出口路由，导致连接陷入黑洞；此时可在客户端设置中开启 IPv4 优先或修复 TUN IPv6 路由。

### Q8：我的机场节点没有提供 IPv6 出口，会影响我正常上网和看 4K 视频吗？
**答**：完全不影响。全球绝大多数网站均完美支持 IPv4，客户端会自动将所有流量通过 IPv4 隧道发送，丝毫不影响速度与画质。

### Q9：什么是 fe80 开头的 IPv6 地址？
**答**：`fe80::` 是链路本地地址（Link-Local Address），仅用于你的电脑和路由器之间在局域网内通信，绝对无法在公网上路由，看到它并不代表公网 IP 泄漏。

### Q10：为什么在手机移动数据流量下，IPv6 总是特别容易连通？
**答**：因为各大移动运营商在 4G/5G 核心网中全面部署了 IPv6 单栈与双栈架构，移动网络的 IPv6 覆盖率和直连质量普遍极高。

### Q11：TUN 模式和 IPv6 是什么关系？
**答**：TUN 模式是在系统底层虚拟出一块支持双栈的虚拟网卡。只有在 TUN 驱动正确启用了 IPv6 协议栈时，全系统的 IPv6 数据包才能被强制送入代理内核处理。

### Q12：怎么测试我当前的代理是否成功代理了 IPv6？
**答**：在开启代理后，访问权威 IPv6 连通性测试网站：若测试显示的 IPv6 出口归属地已变为海外节点机房且与 IPv4 保持一致，即代表 IPv6 已完美走代理。

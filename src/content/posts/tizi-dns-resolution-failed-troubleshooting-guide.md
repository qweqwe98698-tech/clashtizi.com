> **【💡 30 秒极速诊断：为什么开了梯子依然提示 DNS 解析失败 / 域名打不开？】**
> - **核心技术分水岭**：**DNS 解析失败绝不等于 DNS 服务器坏了！** 出现 `NXDOMAIN`、`DNS Timeout` 或 `Could not resolve host` 时，先看是**“单个网站打不开”**还是**“所有网站全瘫痪”**；
> - **高频排障四大黄金法则**：
>   1. **仅海外受限网站打不开，国内秒开**：优先排查 [分流规则](/tizi/routing-rules/) 与代理内核的海外 DNS 解析器；
>   2. **直接输入 IP 能开，输入域名打不开**：100% 证实为 **DNS 解析层或 Fake-IP 映射中断**；
>   3. **Chrome 正常但 Firefox 打不开**：进入 Firefox 设置关闭其内置的【独立 DoH / Secure DNS】即可；
>   4. **看到 `198.18.x.x` 虚拟 IP**：这是 [Fake-IP 模式](/tizi/fake-ip/) 的正常保留地址，不是错误 IP。

## 一、高频 DNS 错误状态码与核心含义速查总表

| DNS 报错代码 / 提示信息 | 底层真实技术含义 | 最常见的触发诱因 | 第一步标准排查动作 |
| :--- | :--- | :--- | :--- |
| **NXDOMAIN (Non-Existent Domain)** | DNS 服务器明确回复“该域名在全网不存在” | 域名拼写错误、域名过期未续费、或上游触发负缓存 | 检查网址拼写，刷新本地 DNS 缓存 |
| **DNS Timeout (查询超时)** | 客户端在设定时间内未收到任何 DNS 应答 | 本地物理宽带阻断、海外 DNS 服务器宕机、或 DoH 握手超时 | 检查客户端 Bootstrap DNS 与代理连通性 |
| **SERVFAIL (Server Failure)** | 上游 DNS 解析器内部错误，无法完成递归查询 | DNSSEC 安全签名校验失败、或上游递归服务器失联 | 检查客户端 DNS 配置，切换备用 DoH 服务器 |
| **REFUSED (拒绝查询)** | DNS 服务器主动拒绝为你提供解析服务 | 企业内网/校园网 DNS 设置了 ACL 访问控制列表 | 确认当前网络权限，检查客户端 DNS 策略 |
| **Could not resolve host** | 终端命令行工具（Git/curl）无法获得可用 IP | 命令行未配置代理环境变量或未开启 [TUN 模式](/tizi/tun/) | 在终端配置 `HTTP_PROXY` 或开启 TUN 网卡 |

## 三、DoH (DNS over HTTPS) 为什么开启后反而解析失败？

DoH 虽然加密了 DNS 查询过程，但在梯子环境下极易产生**“鸡生蛋”的 Bootstrap 依赖循环**：

```text
 1. 【Bootstrap DNS 循环依赖困境】：
    - 代理客户端想要连接海外 DoH 服务器（如 `https://1.1.1.1/dns-query` 或 `dns.google`）；
    - 但客户端必须先解析 `dns.google` 的域名 IP 才能建立 HTTPS 握手连接；
    - 如果客户端未配置明文的【基础引导 DNS (Bootstrap DNS)】，整个 DNS 系统就会陷入死锁超时。

 2. 【浏览器内置 Secure DNS 冲突】：
    - Chrome 或 Firefox 开启了独立 DoH 时，浏览器会绕过代理客户端的 Fake-IP 字典，直接向公网 DoH 发起直连；
    - 若本地物理宽带阻断了公网 DoH 端口，浏览器就会直接弹出 `DNS lookup failed` 报错。
```

## 四、Fake-IP 模式排障：看到 `198.18.x.x` 到底是不是故障？

在主流客户端（Clash Verge Rev / sing-box）中，Fake-IP 是最常用的 DNS 模式：

```text
 1. 【正常运行表现】：
    - ping 某个海外网站时，返回 `198.18.0.1` 属于【100% 预期正常现象】；
    - 内核在内存中建立了 `198.18.0.1 <──► google.com` 的映射字典，真正发往海外节点时会还原为原始域名。

 2. 【真正的 Fake-IP 映射失效排查】：
    - 表现：浏览器提示“ERR_CONNECTION_REFUSED”且客户端连接面板中显示目标全为 IP 而无域名；
    - 根因：代理客户端意外重启导致内存映射表丢失，但操作系统本地 DNS 缓存仍记录着旧虚拟 IP；
    - 解决：在客户端界面点击【清空 Fake-IP 缓存】或在终端运行 `ipconfig /flushdns` 即可秒级修复。
```

## 六、DNS 解析失败 5 分钟极速排障 SOP（标准 HowTo）

遇到开启代理后频繁弹出 DNS 错误或域名打不开时，按以下 6 步标准流程排查：

```text
 Step 1: 确定故障范围 ──► 尝试访问国内百度与海外 Google，判断是单个网站还是全网解析失败
    ↓
 Step 2: 临时切为 [Global 全局模式](/tizi/rule-global-direct/) ──► 若 Global 能打开，说明是分流规则将海外域名误判为了国内直连解析
    ↓
 Step 3: 检查浏览器 Secure DNS ──► 进入 Chrome/Firefox 设置，将【使用安全 DNS】临时切换为【使用系统当前 DNS】
    ↓
 Step 4: 刷新多级 DNS 缓存 ──► 在终端运行 `ipconfig /flushdns` 并点击客户端内的【清空 Fake-IP 缓存】
    ↓
 Step 5: 检查客户端 Bootstrap DNS ──► 确认客户端 DNS 配置中填入了可用的基础 DNS（如 `223.5.5.5`, `119.29.29.29`）
    ↓
 Step 6: 检查 IPv6 干扰 ──► 在客户端中临时开启【IPv4 优先】或在系统网络中短暂禁用 IPv6 进行 A/B 对照测试
```

## 七、关于 DNS 解析失败的 15 大核心认知误区

```text
 ❌ 误区 1：只要遇到网页打不开，第一步就必须把电脑的 DNS 换成 8.8.8.8。(错！在梯子环境下公共 DNS 极易被污染)
 ❌ 误区 2：NXDOMAIN 报错说明目标海外网站一定是被官方防火墙彻底封锁了。(错！可能是域名过期、拼写错误或负缓存)
 ❌ 误区 3：在 Fake-IP 模式下 ping 域名看到 198.18 开头的 IP 说明电脑中毒了。(错！198.18 为预留的虚拟 IP 池)
 ❌ 误区 4：DoH (加密 DNS) 是万能神药，开启后任何网站都能 100% 秒开。(错！DoH 端点受阻会导致全网 DNS 瘫痪)
 ❌ 误区 5：浏览器提示 DNS Error，说明我买的机场所有节点全部跑路了。(错！节点测速正常时通常只是本地 DNS 配置冲突)
 ❌ 误区 6：只要在电脑里装了代理插件，终端里的 Git 命令行就不会报 DNS 错误。(错！Git 命令行不走浏览器沙箱)
 ❌ 误区 7：遇到 DNS 报错时，把所有的分流规则和 Fake-IP 全部关闭是最好的解决办法。(错！会导致海外域名无法分流)
 ❌ 误区 8：nslookup 能查出 IP 就代表浏览器一定能用该 IP 正常打开网页。(错！现代 HTTPS 强依赖 SNI 证书与 Host)
 ❌ 误区 9：所有的海外网站都必须通过同一个 DNS 服务器进行解析。(错！分流规则会将国内外域名交由不同 DNS 解析)
 ❌ 误区 10：为了防止 DNS 报错，必须在电脑里永久关闭 IPv6 协议栈。(错！双栈网络在代理正确配置下可完美运行)
 ❌ 误区 11：在手机上不会发生 DNS 解析失败的问题。(错！移动网络私有 DNS 与 VPN 配置不当同样会引发解析超时)
 ❌ 误区 12：同一个局域网内的所有电脑，DNS 缓存刷新的速度一定完全一致。(错！各设备操作系统与浏览器缓存独立)
 ❌ 误区 13：企业内网打不开公司后台是梯子软件损坏。(错！企业 Split DNS 与内部域名仅限公司内网 DNS 解析)
 ❌ 误区 14：只要把代理端口从 7890 改成 8080，DNS 超时问题就会自动消失。(错！端口号与 DNS 解析路径无关)
 ❌ 误区 15：退出梯子后电脑连不上网是系统网卡损坏。(错！通常是代理退出时未自动清除注册表 System Proxy)
```

## 八、常见问题解答 (FAQ)

### Q1：梯子开启后提示“DNS 解析失败 (DNS lookup failed)”是什么原因？
**答**：通常是因为浏览器的 DNS 请求未正确送达代理内核，或内核配置的海外上游 DNS 服务器发生超时。尝试临时切换为 [Global 全局模式](/tizi/rule-global-direct/) 或清空浏览器 DNS 缓存即可定位。

### Q2：什么是 NXDOMAIN？它和 DNS 污染是一回事吗？
**答**：不是。NXDOMAIN 是 DNS 协议标准返回码，代表“该域名不存在”（可能是网址拼写错误或域名过期）；而 DNS 污染是人为将受限域名解析到了错误的虚假 IP。

### Q3：为什么直接在浏览器里输入网站的 IP 地址打不开，输入域名也打不开？
**答**：现代复杂网站均采用 HTTPS 加密与 CDN 架构，直接输入 IP 会因缺少 SNI 证书信息与 Host 头部被服务器主动拒绝，不能以此判断网站是否存活。

### Q4：看到 `198.18.x.x` 开头的 IP 地址，这是不是说明 DNS 解析出错了？
**答**：完全不是。这是代理客户端开启 [Fake-IP 模式](/tizi/fake-ip/) 后的正常现象，内核利用该虚拟 IP 池在本地快速建立连接，并在底层自动还原为真实域名。

### Q5：为什么 Chrome 浏览器能正常翻墙，但 Firefox 却频繁提示 DNS 超时？
**答**：因为 Firefox 默认开启了独立的“基于 HTTPS 的 DNS (DoH)”，绕过了代理客户端；在 Firefox【设置】──►【网络设置】中关闭 DoH 或设为【使用系统代理设置】即可恢复。

### Q6：什么是 Bootstrap DNS？为什么它非常重要？
**答**：Bootstrap DNS 是代理客户端的“基础引导 DNS”，专门用于在建立代理通道前，解析 DoH 服务器或节点本身的域名；若未配置会导致全网 DNS 死锁。

### Q7：什么是负缓存 (Negative Caching)？
**答**：当某个域名解析失败（如返回 NXDOMAIN）后，操作系统或 DNS 解析器会按照 RFC 标准将“该域名不存在”的状态缓存一段时间；在此期间即使域名恢复，也需手动刷新缓存才能访问。

### Q8：为什么开启 TUN 模式后，电脑所有网页突然全部提示 DNS 错误？
**答**：这是因为 TUN 虚拟网卡接管了系统的 53 端口 DNS 流量，但客户端内部的 DNS 监听服务未正常启动；重启代理客户端或在设置中修复 TUN 驱动即可。

### Q9：在 Windows 上怎么一键清空系统 DNS 缓存？
**答**：按下快捷键 `Win + R`，输入 `cmd` 打开命令提示符，输入命令 `ipconfig /flushdns` 并回车，即可瞬间清空操作系统的全部 DNS 缓存。

### Q10：为什么访问国内网站正常，但访问国外网站频繁提示 DNS Timeout？
**答**：说明分流规则已将海外域名分流给海外 DNS 解析器，但该海外 DNS 服务器连接受阻；在客户端设置中将海外 DNS 替换为公共加密 DNS（如 `8.8.8.8` 或 `1.1.1.1` 的 DoH 格式）即可。

### Q11：IPv6 会不会导致特定网站的 DNS 解析变得极慢？
**答**：会。如果网站返回了 IPv6 (AAAA 记录)，但本地或节点 IPv6 路由不可达，系统会经历漫长的超时重试才会降级至 IPv4；在客户端开启 IPv4 优先可显著提速。

### Q12：为什么关闭梯子软件后，电脑上的所有网页反而全部打不开了？
**答**：这是因为代理软件非正常退出时，未自动将操作系统的【系统代理 (System Proxy)】或虚拟网卡 DNS 复原；重新打开代理软件并正常点击【退出】即可自动修复。

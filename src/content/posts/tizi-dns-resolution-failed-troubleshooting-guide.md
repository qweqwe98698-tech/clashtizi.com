> **【💡 30 秒极速直接答案：DNS 解析失败核心定性与四大排障原则】**
> - **第一核心定性**：**“出现 DNS 解析失败（如 `NXDOMAIN`、`DNS_PROBE_FINISHED_NXDOMAIN` 或 `DNS Timeout`），绝不代表全球 DNS 服务器挂了，而是本地网络发生了运营商 53 端口投毒、客户端 Fake-IP 映射脱节、或浏览器内置 Secure DNS 冲突！”**；
> - **六类典型“DNS 异常”极速对号入座**：
>   1. **直接在浏览器输入海外纯 IP 能开，输入域名显示无法访问** ──► 100% 证实为**纯粹的 DNS 解析阻断或死锁** ──► 在客户端配置加密 DoH 或切换 Fake-IP；
>   2. **浏览器提示 `DNS_PROBE_FINISHED_NXDOMAIN`** ──► 属于**域名拼写错误、本地负缓存 (Negative Cache)，或被本地 DNS 投毒了空地址** ──► 终端执行 `ipconfig /flushdns` 刷新缓存；
>   3. **看到解析出来的 IP 全是 `198.18.x.x`** ──► 这是 **[Fake-IP 模式](/tizi/fake-ip/) 的正常保留虚拟 IP**，绝非错误，无需修改；
>   4. **Chrome 浏览器正常，但 Firefox 浏览器死活打不开** ──► 属于 **Firefox 内置的独立 DoH (Max Protection) 冲突** ──► Firefox 设置中关闭安全 DNS；
>   5. **开启代理后，国内网站解析极慢，全部绕道美国** ──► 属于**客户端未配置国内直连 DNS (Direct Nameserver)** ──► 添加阿里 DNS `223.5.5.5` 作为国内直连分流解析源；
>   6. **提示 `Could not resolve host` 命令行报错** ──► 属于**终端没有配置代理环境变量** ──► 开启客户端中的【TUN 模式】。

## 二、高频 DNS 错误状态码与核心含义速查总表

在排查前，请对照下表确认你的核心 DNS 报错代码：

| DNS 报错代码 / 提示信息 | 底层真实技术含义 | 最常见的触发诱因 | 第一步标准排查动作 |
| :--- | :--- | :--- | :--- |
| **NXDOMAIN (Non-Existent Domain)** | DNS 服务器明确回复“该域名在全网不存在” | 域名拼写错误、域名过期未续费、或上游触发负缓存 | 检查网址拼写，刷新本地 DNS 缓存 |
| **DNS Timeout (查询超时)** | 客户端在设定时间内未收到任何 DNS 应答 | 本地物理宽带阻断、海外 DNS 服务器宕机、或 DoH 握手超时 | 检查客户端 Bootstrap DNS 与代理连通性 |
| **SERVFAIL (Server Failure)** | 上游 DNS 解析器内部错误，无法完成递归查询 | DNSSEC 安全签名校验失败、或上游递归服务器失联 | 检查客户端 DNS 配置，切换备用 DoH 服务器 |
| **REFUSED (拒绝查询)** | DNS 服务器主动拒绝为你提供解析服务 | 企业内网/校园网 DNS 设置了 ACL 访问控制列表 | 确认当前网络权限，检查客户端 DNS 策略 |
| **Could not resolve host** | 终端命令行工具（Git/curl）无法获得可用 IP | 命令行未配置代理环境变量或未开启 [TUN 模式](/tizi/tun/) | 在终端配置 `HTTP_PROXY` 或开启 TUN 网卡 |
| **DNS_PROBE_FINISHED_BAD_CONFIG** | 本地网络适配器配置了无效或不存在的 DNS IP | 电脑网络设置中手动填写的 DNS 地址失效 | 网卡 IPv4 属性中改为“自动获得 DNS 服务器地址” |

## 三、致命现象破译：“输入纯 IP 能通，输入域名打不开”

这是排查中 100% 锁定 DNS 故障的黄金测试法：

```text
 1. 【黄金验证操作】：
    - 在浏览器地址栏中直接输入某个海外知名 IP（如 Cloudflare 的 `1.1.1.1` 或 Google 的 `8.8.8.8`）；
    - 若能正常打开 Cloudflare 欢迎页，但输入 `www.google.com` 却提示无法访问此网站；

 2. 【底层物理定性】：
    - 这 100% 证实：你的电脑到海外节点的【数据传输通道完全畅通】！
    - 故障点 100% 锁死在【域名解析层 (DNS)】：要么是本地发出的 53 端口查询被宽带运营商劫持丢弃，要么是客户端的 Fake-IP 路由表脱节。
    - 应对动作：在客户端开启【Fake-IP 模式】或使用加密的【DoH (DNS over HTTPS)】解析。
```

## 五、DoH (DNS over HTTPS) 与 Bootstrap DNS 鸡生蛋死锁

加密 DNS 能够彻底杜绝运营商投毒，但配置不当会引发死循环：

```text
 ⚠️ 【Bootstrap DNS 的致命死锁】：
 - 当你在客户端中配置海外 DoH 为 `https://dns.google/dns-query` 时；
 - 客户端首先必须知道 `dns.google` 本身的 IP 是什么才能发起 HTTPS 握手！
 - 如果没有配置【基础引导 DNS (Bootstrap DNS)】，客户端无法解析 DoH 服务器域名，导致整个 DNS 模块瞬间瘫痪！
 
 🟢 标准安全配置法则：
 - 必须在配置中填写纯 IP 格式的 Bootstrap DNS（如 `223.5.5.5` 或 `119.29.29.29`）；
 - 专门用来解析 DoH 域名自身，彻底消灭死锁。
```

## 六、IPv6 AAAA 记录投毒与黑洞丢包避坑

如果你的宽带分配了 IPv6，经常会导致严重的 DNS 卡顿：

```text
 1. 【IPv6 投毒黑洞真相】：
    - 很多国内运营商宽带默认优先解析 IPv6 (AAAA 记录)；
    - 当你访问海外网站时，本地 DNS 返回了一个虚假或不可达的 IPv6 地址；
    - 浏览器会陷入 3~5 秒的“Happy Eyeballs”超时等待，直到超时后才回退到 IPv4，造成严重的打开卡顿！

 2. 【一键优化策略】：
    - 参考 [《梯子IPv6与代理兼容指南》](/tizi/ipv6/)；
    - 在代理客户端设置中开启【IPv6 解析过滤 / 禁用 AAAA 记录】；
    - 强制所有海外请求统一使用平稳可靠的 IPv4 隧道出站。
```

```text
    ↓

    ↓
 Step 6: 开启管理员 TUN ──► 遇命令行或独立软件打不开，开启 TUN 虚拟网卡接管
```

## 九、常见问题解答 (FAQ)

### Q1：为什么提示 `DNS_PROBE_FINISHED_NXDOMAIN`？
**答**：`NXDOMAIN` 代表 DNS 服务器返回“该域名不存在”。通常是因为：①网址拼写有误；②本地宽带运营商对该未备案海外域名进行了 53 端口投毒；③系统触发了负缓存。在 CMD 中运行 `ipconfig /flushdns` 刷新缓存，并在客户端中开启 Fake-IP 或加密 DoH 即可解决。

### Q2：为什么直接输入海外 IP 能打开网页，但输入域名就打不开？
**答**：这 100% 证明你的底层网络代理通道完全正常，问题纯属**域名解析层阻断**！在客户端中配置规范的海外 DoH 加密 DNS（如 `https://1.1.1.1/dns-query`）或开启【Fake-IP 模式】即可秒级恢复。

### Q3：什么是 Fake-IP 模式？解析出来全是 198.18.x.x 正常吗？
**答**：**完全正常！** Fake-IP 是现代代理客户端的核心黑科技：客户端在本地瞬间返回一个保留的 `198.18.x.x` 虚拟 IP 给浏览器，由内核在发送海外请求时代为解析，从而大幅降低建连延迟，绝非电脑中毒。

### Q4：为什么 Chrome 能正常翻墙，但 Firefox (火狐) 提示 DNS 解析错误？
**答**：因为 Firefox 默认开启了激进的【基于 HTTPS 的 DNS (DoH)】，绕过了操作系统的代理分流；在 Firefox【设置】──►【隐私与安全】──►【基于 HTTPS 的 DNS】中，将保护级别切为【默认保护】或暂时关闭即可。

### Q5：如何配置国内直连 DNS 与海外加密 DNS 双通道分流？
**答**：最佳黄金搭配：国内直连 DNS (Nameserver) 配置为 `223.5.5.5` 与 `119.29.29.29`（保证国内秒开）；海外远端 DNS (Fallback / Remote) 配置为加密 DoH `https://1.1.1.1/dns-query`（保证海外防投毒）。

### Q6：命令行终端（Git clone / curl）提示 `Could not resolve host` 怎么解决？
**答**：终端命令行默认不读取 Windows 系统代理；在客户端中开启【TUN 虚拟网卡模式】接管整机流量，或者在终端手动设置临时环境变量 `$env:http_proxy="http://127.0.0.1:端口"`。

### Q7：什么是 Bootstrap DNS？为什么不填会导致 DNS 瘫痪？
**答**：Bootstrap DNS 是“引导 DNS”（必须为纯 IP，如 `223.5.5.5`）。客户端必须先通过 Bootstrap DNS 解析出 DoH 服务器自身的 IP 地址，才能与 DoH 服务器建立 TLS 加密连接；缺失会导致死锁。

### Q8：遇到 DNS 解析失败，最忌讳的操作是什么？
**答**：最忌讳“病急乱投医盲目重装系统或重置路由器”。按照“测试纯 IP ──► 刷新本地 DNS 缓存 ──► 检查客户端 DoH 配置 ──► 开启管理员 TUN”四步法，99% 的 DNS 解析难题都能在 3 分钟内彻底解决。

> **【⚠️ 核心急救警示：先不要清空或删除当前订阅！】**
> 
> 很多新手一看到客户端提示“订阅更新失败”，第一反应就是把配置卡片删除、甚至直接卸载客户端——**千万不要这样做！**
> - **旧配置依然有巨大价值**：即使更新失败，旧配置中的部分可用节点可能依然可以正常连网；
> - **清空配置会导致失去对照**：保留旧配置能帮你清晰对比新旧节点变化，避免陷入“彻底断网且无法重新拉取”的死循环。

## 一、订阅更新失败核心报错与根本原因总表

客户端向远程订阅服务器发起请求时，所有网络错误均有迹可循：

| 错误类型 / 状态码 | 客户端日志常见关键词 | 发生此错误的根本原因 | 对应标准解决动作 |
| :--- | :--- | :--- | :--- |
| **HTTP 401 Unauthorized** | `status: 401`, `auth failed` | 订阅链接中的 Token 被后台注销或重置 | 在机场后台重新复制最新的订阅 URL |
| **HTTP 403 Forbidden** | `status: 403`, `forbidden` | 机场账号被暂停、套餐流量耗尽或触发风控 | 登录机场官网查看账户状态及流量余量 |
| **HTTP 404 Not Found** | `status: 404`, `not found` | 机场更换了订阅分发域名，旧 API 已废弃 | 登录后台获取全新的订阅地址并覆盖 |
| **HTTP 500 / 502 / 503** | `server error`, `bad gateway` | 机场后端 Web 服务器故障或正在例行升级维护 | 稍等 10~30 分钟，关注机场官方群公告 |
| **Request Timeout** | `context deadline exceeded` | 当前 Wi-Fi 无法连通订阅服务器或 DNS 解析失败 | 切换为手机热点或借用临时代理更新 |
| **TLS Certificate Error** | `certificate has expired`, `tls` | 本地电脑时间不准或中间网络存在证书审查 | 同步系统时间，**严禁随意关闭安全验证** |
| **Format Parse Error** | `unsupported format`, `yaml error` | 订阅格式与当前客户端核心不兼容 | 在机场后台换用专用格式（如选 Clash） |

## 二、第一步：检查机场账号状态与套餐有效性

在排查本地软件前，必须先确认云端服务本身是否正常：

```text
 1. 登录机场官网后台 ──► 能够正常登录？ (排除全网大面积跑路或官网服务器故障)
        ↓ 是
 2. 查看【我的套餐】 ──► 是否欠费过期？ (很多更新失败纯粹是因为套餐到期了)
        ↓ 有效
 3. 查看【剩余流量】 ──► 流量是否被耗尽？ (部分机场用尽流量后会自动掐断订阅 API)
```

- **误区纠偏**：**“订阅更新失败”绝对不等于“机场跑路”**。绝大多数情况下只是订阅域名遭受网络波动、Token 过期或本地 DNS 解析受阻。

## 三、第二步：重新复制订阅链接，排查字符污染与截断

很多更新失败是由于复制链接时的人为失误引起的：

```text
 ❌ 错误一：复制时漏掉了末尾的几个字符 (Token 不完整导致 401/403)
 ❌ 错误二：从微信/QQ 发送时，链接被聊天软件自动插入了换行符或空格
 ❌ 错误三：使用了旧版订阅转换链接，后端转换服务器已经关停
```

### 正确处理流程：
1. 登录机场用户后台，进入 **【订阅中心】**；
2. 鼠标点击 **【复制订阅链接 (Copy Link)】** 按钮（尽量不要用鼠标长按划选，防止漏字符）；
3. 打开客户端订阅管理，新建一条配置并粘贴，点击更新。

## 四、第三步：网络环境交叉测试法（Wi-Fi vs 手机热点）

这是定位网络阻断最快、最有效的方法：

```text
                               【网络交叉测试判断模型】
                                           │
 ┌─────────────────────────────────────────┴─────────────────────────────────────────┐
 │                                                                                   │
 📶 测试 A：连接家庭/公司 Wi-Fi 点击更新                                📱 测试 B：断开 Wi-Fi，连接手机 5G 热点更新
  - 若 Wi-Fi 失败而手机热点秒成功                                     - 若两者均报 Timeout
  - 证明：原 Wi-Fi 路由器或宽带 DNS 对该订阅域名有拦截                - 证明：订阅分发服务器本身发生故障或被整体阻断
```

### 网络交叉测试结果判定表：

| 测试场景组合 | 测试结果表现 | 故障根因判断 |
| :--- | :--- | :--- |
| **Wi-Fi 失败 / 手机热点成功** | 手机流量能拉取，家里的宽带报错 | **Wi-Fi 路由器 DNS 污染或运营商网络波动** |
| **Wi-Fi 成功 / 手机热点失败** | 宽带正常，移动流量更新超时 | 移动基站特定链路受限，平时建议在 Wi-Fi 下更新 |
| **手机能更新 / 电脑不能更新** | 同一个 Wi-Fi 下手机正常、电脑报错 | **电脑本地防火墙、系统代理残留或系统时间错误** |
| **所有设备所有网络均报错** | 无论换什么网和设备均报 500/Timeout | **机场后端订阅服务正在维护，等待服务商修复** |

## 五、第四步：代理状态对订阅更新的影响（开代理 vs 关代理）

为什么有时“开启梯子后反而更新失败，关闭梯子后却能更新成功”？

```text
 [直连更新模式]：客户端 ════════════ (本地宽带直连) ════════════► 订阅分发服务器 (适合订阅域名未被墙时)
 [代理更新模式]：客户端 ──► [当前已选节点 (若该节点已死)] ──► 订阅服务器 (链路死锁，导致更新超时)
```

- **链路死锁现象**：如果你当前选中的节点本身已经失效断网，而客户端设置了“订阅更新走代理流量”，就会导致更新请求发不出去，从而产生 Timeout；
- **解决策略**：在客户端设置中，将订阅更新方式切换为 **【直连更新】**，或先换用一个当前测速正常的可用绿色节点。

## 六、第五步：排查本地系统时间与 TLS 证书验证错误

HTTPS 订阅链接依赖严苛的 TLS 加密握手协议：

```text
 电脑系统时间偏差 > 3 分钟 ──► TLS 证书校验不合法 ──► 客户端主动切断连接 ──► 抛出 SSL/TLS 握手失败
```

- **修复方法（Windows）**：进入系统【设置】 ──► 【时间和语言】 ──► 【日期和时间】 ──► 点击 **【立即同步 (Sync now)】**；
- **修复方法（macOS）**：进入【系统设置】 ──► 【通用】 ──► 【日期与时间】 ──► 确保勾选“自动设置时间”；
- **🔒 安全底线**：**切勿在客户端里勾选“跳过证书验证 (Allow Insecure / Skip Cert Verify)”**，否则极易遭受公共网络中间人攻击窃取 Token。

## 七、第六步：客户端格式兼容性与多软件交叉验证

不同客户端对订阅配置格式的解析能力存在差异：

| 客户端类别 | 推荐专属订阅格式 | 遇到兼容性问题时的表现 | 应对方案 |
| :--- | :--- | :--- | :--- |
| **[Clash Verge Rev](/clash-verge-rev/)** | Clash 标准 YAML 格式 | 提示 `yaml: unmarshal errors` | 在机场后台选择“一键导入 Clash”格式 |
| **Shadowrocket (小火箭)** | 通用 Subscribe 聚合链接 | 提示 `Invalid format` | 在小火箭中选择类型为【Subscribe】 |
| **v2rayN** | v2ray 标准 base64 格式 | 提示无法识别节点 | 从机场后台复制“v2ray 订阅”导入 |
| **[sing-box GUI](/tutorials/sing-box-config/)** | sing-box 标准 JSON 格式 | 提示 `json decode error` | 确认机场后端是否原生支持 sing-box 格式 |

## 🔒 故障排查期间的凭据安全守则

> **排查安全铁律**：
> - **切勿手改 Token 参数**：订阅 URL 中的签名由后端算法加密生成，任何手动增删字符都会导致 403 废弃；
> - **截图求助必须打码**：向客服或他人发送报错截图时，务必**完全遮盖订阅链接 URL、二维码及 Token**；

## 十、常见问题解答 (FAQ)

### Q1：梯子订阅更新失败，最常见的三个原因是什么？
**答**：1. 机场套餐到期欠费；2. 订阅链接复制不完整或旧链接已被后台重置；3. 本地 Wi-Fi 网络阻断了订阅服务器域名的通信请求。

### Q2：订阅更新提示“Timeout”超时，是不是机场跑路了？
**答**：不一定。通常只是当前网络或 DNS 解析该订阅域名发生了短暂波动。先切换到手机 5G 热点重新尝试，大部分情况下均可秒级解决。

### Q3：为什么报错显示“HTTP 401”或“HTTP 403”？
**答**：401 和 403 均属于权限拒绝错误。代表你使用的这串订阅链接中的 Token 已经失效，或者你的机场账户欠费已停机，需在后台核对套餐并重新获取最新链接。

### Q4：为什么报错显示“HTTP 404 Not Found”？
**答**：404 说明订阅服务器上该路径已不存在。通常是因为机场升级了后端系统或更换了订阅分发域名，旧链接彻底作废，需去官网复制新地址。

### Q5：为什么手机能更新订阅，但同一 Wi-Fi 下的电脑却更新失败？
**答**：说明订阅本身和宽带网络完全正常。问题出在电脑端：检查电脑系统时间是否准确、Windows 防火墙或杀毒软件是否拦截了客户端、或电脑系统代理发生了死锁。

### Q6：为什么更新成功后，节点列表依然是空的（0 节点）？
**答**：通常是因为选错了订阅格式（如在 Clash 里导入了纯文本格式），或者机场后台刚下单套餐尚未完成节点权限下发，建议在后台刷新后重新导入。

### Q7：订阅更新失败，我应该重装客户端吗？
**答**：绝大多数情况下不需要。重装软件无法解决套餐过期、网络阻断或 Token 失效问题。只有当确定所有配置被彻底搞乱且无法恢复时，才考虑重新安装。

### Q8：开启代理后反而无法更新订阅是怎么回事？
**答**：这是因为当前客户端选中的节点本身已经断网失效，而更新请求又被强制通过该节点转发，导致网络死锁。关闭系统代理或切换为直连模式后再点更新即可。

### Q9：出现 SSL / TLS 证书错误，可以直接关闭证书验证吗？
**答**：严禁关闭。关闭证书验证会使你的订阅流量暴露在明文风险中。应优先排查并同步本地系统标准时间，确保加密握手正常。

### Q10：更新订阅会把我本地自定义的分流规则覆盖掉吗？
**答**：如果你的规则写在远程 Profile 文件内部，更新时会被覆盖；如果使用客户端自带的“本地规则 (Mixin / Rule Override)”功能，则不会受到任何影响。

### Q11：订阅更新成功了，但所有节点测速全是红色 Timeout 怎么办？
**答**：这说明订阅拉取成功（订阅层正常），但节点服务器与你的网络通信受阻（进入节点层故障），请直接参考 [Clash 节点全红排查专题](/issues/clash-nodes-timeout/)。

### Q12：怀疑订阅链接泄露被他人盗用了怎么办？
**答**：立即登录机场官网后台 ──► 进入订阅管理 ──► 点击 **【重置订阅 Token】**。旧链接将瞬间永久作废，随后将生成的新链接重新导入你的设备。

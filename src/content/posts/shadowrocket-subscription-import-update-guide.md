> **【💡 30 秒极速直接答案：Shadowrocket 导入订阅核心流程与首要原则】**
> - **订阅导入标准流程**：准备自己的专属订阅 URL ──► 打开 Shadowrocket 首页点击右上角 **`➕`** ──► 将【类型 (Type)】切实切换为 **`Subscribe (订阅)`** ──► 粘贴完整 URL 并填写备注 ──► 点击右上角【完成 (Done)】自动拉取所有节点；
> - **第一排障铁律**：**切勿在更新失败时立刻删除旧订阅！** 只要旧节点列表依然存在且部分可用，删掉只会导致彻底断网；
> - **五类订阅导入与更新异常极速归因**：
>   1. **点击完成一直转圈报 Timeout** ──► 手机本地 DNS 污染或订阅分发域名被运营商阻断 ──► 切到 5G 蜂窝数据重试；
>   2. **报 HTTP 401 / 403 错误** ──► 订阅链接中的 Token 密钥失效或该订阅已被服务商临时冻结 ──► 去后台重新复制最新链接；
>   3. **报 HTTP 404 Not Found** ──► 订阅 URL 字符被聊天软件自动截断丢失参数，或机场更换了订阅接口路径；
>   4. **显示更新成功但节点列表为 0（空白）** ──► 误把分流规则文件 (`.conf`) 当成了节点订阅导入，或服务商未配置任何有效节点；
>   5. **节点全部出现但测速全是红色 Timeout** ──► **这已经不再是订阅问题！** 订阅已完成使命，请直接转入 [节点全部超时排查](/tizi/nodes-timeout/)。

## 一、核心实体辨析：订阅与节点有什么本质区别？

很多 iPhone 初学者常常把“订阅”、“节点”以及“购买 App”混为一谈，导致排查方向彻底走偏：

| 对比维度 | 订阅 (Subscription) | 代理节点 (Node) | 软件 App 购买 |
| :--- | :--- | :--- | :--- |
| **本质属性** | **配置分发与批量获取通道** | **具体的远程服务器连接凭据** | **客户端工具软件的使用授权** |
| **存在形态** | 一条以 `https://` 开头的动态 URL | 包含服务器 IP、端口、协议的独立条目 | App Store 购买的 Shadowrocket 安装包 |
| **数据关系** | 一个订阅通常包含几十个不同国家的节点 | 节点隶属于某个订阅分组，由订阅同步 | 软件本身不含任何订阅，也不含任何节点 |
| **更新行为** | 下拉刷新可整体增删节点与同步变动 | 无法单独远程刷新，依赖订阅统一更新 | 随苹果 App Store 进行版本迭代更新 |
| **常见误区** | ❌ 误以为订阅就是单独一台翻墙服务器 | ❌ 误以为只要节点掉线就代表订阅坏了 | ❌ 误以为买下软件就自带现成的免费节点 |

 2. 【严禁三大危险暴露行为】：

    - 严禁通过微信、QQ 等具有审查和关键词转义机制的聊天窗口直接明文发送超长订阅（极易被平台截断丢失参数导致 404）。

## 三、Shadowrocket URL 导入订阅实操（标准 2026 UI 流水线）

请严格按照以下步骤在 iPhone 或 iPad 上导入订阅：

```text
 步骤 1：在机场后台完整复制你的订阅链接（优先选择通用订阅或 Clash/Shadowrocket 专用链接）；
 步骤 2：打开 Shadowrocket，进入默认的【首页】；
 步骤 3：点击右上角的【➕】号图标，进入添加节点/配置界面；
 步骤 4：点击第一行的【类型 (Type)】，在弹出菜单中向下滑动，选择【Subscribe】（切勿保留在默认的 Shadowsocks）；
 步骤 5：在【URL】输入框中，长按并选择【粘贴】你的订阅链接；
 步骤 6：在【备注 (Remark)】一栏，输入方便记忆的机场名称（如“主用专线”）；
 步骤 7：确认无误后，点击右上角【完成 (Done)】；
 步骤 8：客户端会自动发起网络请求拉取配置，稍等 2~3 秒，首页将整齐列出该订阅下的全部服务器节点！
```

## 四、Shadowrocket 扫码导入实操与二维码本质解密

如果你的电脑屏幕上显示了机场的节点二维码，可以通过手机小火箭直接扫描：

```text
 1. 【扫码操作步骤】：
    - 打开手机上的 Shadowrocket，点击主界面左上角的【扫描二维码】图标；
    - 将相机取景框对准电脑屏幕上的二维码；
    - 识别成功后，App 会自动弹窗提示已成功识别配置，点击保存即可。

 2. 【核心纠偏：扫码导入的一定是“订阅”吗？】：
    - 并非所有二维码都代表订阅！二维码本质上只是一串字符的图形化编码；
    - 若二维码内部存储的是 `vmess://...` 或 `ss://...` 开头的单节点 URI，扫码后只会【新增一个单独节点】，无法实现后续的自动批量更新；
    - 只有当二维码内部编码的是以 `https://` 开头的完整订阅链接时，扫码后才会生成【一个具备批量更新能力的订阅分组】！
```

## 五、URL 导入 vs 二维码导入全维度对比表

| 对比维度 | 复制订阅 URL 导入 | 扫描屏幕二维码导入 | 手动逐个添加节点 |
| :--- | :--- | :--- | :--- |
| **操作便捷性** | 手机端复制粘贴，单手即可完成 | 适合电脑开着后台、手机扫码互联 | 需手动填写服务器、端口、UUID，极其繁琐 |
| **更新能力** | 具备完整的批量一键远程刷新能力 | 若扫出的是订阅则支持，单节点不支持 | 完全不支持批量更新，节点失效需重配 |
| **安全性** | 字符剪贴板流转，避免被摄像头抓拍 | 二维码容易被他人翻拍盗取 | 无 Token 暴露风险，但输入效率极低 |
| **容错率** | 容易被第三方软件截断空格导致 404 | 图形识别容错极高，不会丢失字符 | 人工输入十六进制密钥极易发生拼写错误 |
| **日常推荐度** | 🟢 **第一优先级推荐** | 🟢 **适合跨设备时辅助使用** | 🔴 **仅供自建服务器玩家单机调试** |

## 七、Shadowrocket 订阅日常刷新与手动更新指南

节点服务器的 IP、端口和倍率可能会随维护而发生调整，因此需要定期更新订阅：

```text
 1. 【手动一键更新所有订阅】：
    - 在 Shadowrocket 首页的节点列表区域，直接【单指按住屏幕向下拉动】并松开；
    - 屏幕顶部会出现旋转刷新指示器，客户端会自动并发向所有已保存的订阅链接请求最新节点数据。

 2. 【针对单个特定订阅手动更新】：
    - 在首页找到需要更新的订阅分组卡片；
    - 手指向右滑动或点击右侧叹号 (i) 图标，点击【更新 (Update)】即可单独刷新该分组。

 3. 【自动后台更新的注意事项】：
    - Shadowrocket 设置中支持配置打开 App 自动更新或周期性更新；
    - ⚠️ 切勿将自动更新频率设置得过于激进（如每 5 分钟更新一次），这不仅会加速消耗手机电池，还会频繁触发机场服务端的防刷限流机制，导致你的 IP 被临时封禁！
```

## 八、订阅更新失败五层诊断模型与错误码速查表

当更新订阅报错或一直转圈时，请按下表快速定位根因：

| 错误表现形式 | 发生的网络层级 | 最核心真实诱发诱因 | 针对性排错动作 |
| :--- | :--- | :--- | :--- |
| **Request Timeout (超时)** | 网络传输层 / DNS | 订阅分发服务器被当地宽带运营商 DNS 污染拦截 | 关闭 Wi-Fi，换手机 5G 流量热点重新拉取 |
| **HTTP 401 Unauthorized** | 业务鉴权层 | 订阅 URL 中的 Token 密钥失效或账号被风控 | 登录机场后台，重新生成并复制最新专属订阅 |
| **HTTP 403 Forbidden** | 访问策略层 | 机场服务端限制了客户端 User-Agent 或阻断当前 IP | 检查是否开启了代理导致出口 IP 被服务商拉黑 |
| **HTTP 404 Not Found** | 资源定位层 | 订阅链接拼写错误、参数截断或接口路径已下线 | 确认 URL 是否完整，重新去后台完整复制 |
| **HTTP 429 Too Many Requests**| 流量防刷层 | 频繁快速连击更新，触发服务端的请求频率上限 | 静置等待 15 分钟后再试，切勿狂点刷新 |
| **HTTP 500 / 502 / 503** | 远端服务器层 | 机场的订阅分发服务器正在重启或高负载宕机 | 耐心等待服务商运维修复，切勿删本地配置 |
| **SSL / TLS Handshake Error** | 安全加密层 | 手机系统时间误差超过 60 秒，导致证书校验失败 | 进入系统设置校准北京时间并开启自动设置 |

## 九、重大认知纠偏：关于 Base64 与在线“订阅转换”的真相

```text
 1. 【Base64 仅仅是“编码”，绝对不是“加密”！】：
    - 打开很多订阅链接，会看到一串看似乱码的字符（如 `dm1lc3M6Ly9hYmNk...`）；
    - 很多新手以为这是高级加密，其实这只是最普通的 Base64 编码，任何人在浏览器控制台执行一行代码就能瞬间还原为明文节点和密码；
    - 因此，绝不能认为经过 Base64 编码的链接就是安全的。

 2. 【严禁使用未知公共“在线订阅转换”网站】：
    - 某些免费的在线订阅转换站，其后端服务器会静默记录每一个经过转换的订阅 URL；
    - 不法运营者可以通过脚本全自动搜集这些 URL，白嫖你的付费流量作为公共免费节点分发；
    - 只有在你自己完全可控的私有服务器上搭建的开源转换工具，才具备安全可信度。
```

## 十三、常见问题解答 (FAQ)

### Q1：Shadowrocket 怎么添加订阅链接？
**答**：复制机场后台的订阅 URL，打开 Shadowrocket 首页点击右上角【➕】，点击第一行【类型】切换为【Subscribe】，在【URL】框中粘贴完整链接并输入备注，点击右上角【完成】即可自动拉取所有节点。

### Q2：扫描二维码导入和复制链接导入有什么区别？
**答**：如果二维码编码的是订阅 URL，两者功能完全一致；但如果二维码编码的是单个节点的 URI 协议串，扫码后只会添加一个固定节点，无法在后续进行批量节点自动刷新和更新。

### Q3：为什么导入订阅后显示成功，但节点列表里空空如也（没有节点）？
**答**：常见原因有三个：一是添加配置时未将【类型】切换为 Subscribe；二是误把分流规则文件（`.conf` 链接）当作节点导入；三是服务商后台未给你的账号激活分配节点或返回了空数据。

### Q4：订阅更新时一直转圈，最后提示 Timeout 怎么解决？
**答**：属于本地网络无法连接订阅分发服务器。请关闭 Wi-Fi 改用手机 5G 蜂窝数据重试；若旧节点依然可用，可先开启旧节点连接外网，然后再下拉刷新订阅链接。

### Q5：提示 HTTP 401 或 403 错误是什么意思？
**答**：401 代表鉴权未通过（通常是 Token 密钥错误或套餐已到期）；403 代表服务商服务器主动拒绝请求（通常是因为频繁刷新触发防刷限流，或该订阅禁止当前网络环境访问）。

### Q6：提示 HTTP 404 Not Found 怎么处理？
**答**：404 代表目标资源不存在。通常是因为通过微信等工具转发时订阅链接被截断丢失了核心参数，或者机场管理后台最近更换了新的订阅分发路径，重新去后台完整复制最新 URL 即可。

### Q7：订阅更新失败时，应该把旧的订阅删掉重新添加吗？
**答**：**绝对不要随意删除！** 更新失败往往只是订阅获取接口受阻，原有的节点服务器可能依然完好可用；一旦删光旧配置将彻底失去连接能力，建议坚决保留旧节点。

### Q8：节点已经成功显示在列表里了，但测速全是红色 Timeout 怎么办？
**答**：**这说明订阅已经成功导入完成，当前问题已属于节点或网络连接层！** 请停止排查订阅，直接去系统设置中校准 iPhone 时间，或参考 [《节点全部超时排查指南》](/tizi/nodes-timeout/)。

## 一、四大速度物理指标全维度辨析表：算清真实的网速账

许多用户被不良商家用“千兆”字眼忽悠，请必须掌握以下四大底层指标的真实物理意义：

| 核心物理指标 | 底层真实技术含义 | 对实际看视频/下载的影响 | 真正高速机场的标准底线 |
| :--- | :--- | :--- | :--- |
| **1. 单线程带宽 (Single-Thread)** | 单个 TCP 连接在单位时间内能拉取的数据量 | **决定 YouTube 4K、网页秒开的核心关键！** | **晚高峰单线程 > 50Mbps** |
| **2. 多线程并发 (Multi-Thread)** | 开启 32~64 个连接同时下载测速拉出的总吞吐 | 仅代表迅雷/BT 多并发下载，不代表看视频 | 测速图跑 500M~1000M 属于基准 |
| **3. 丢包率 (Packet Loss)** | 数据包在跨境传输中被丢弃的比例 | 丢包会导致 TCP 频繁重传降速，造成视频卡死 | **专线 `< 0.1%`，普通 `< 1%`** |
| **4. 物理延迟 (Latency / Ping)** | 数据包单向往返的物理耗时 (毫秒) | 决定网页首次点击响应快慢与网游跟手度 | **香港 20ms，日本 50ms，美西 140ms** |

```text
 💡 为什么 20ms 的香港节点看视频卡，140ms 的美国专线看 4K 秒开？
 - 毫秒 (ms) 只是“汽车从北京开到上海需要多长时间”，它决定的是【响应快慢】；
 - 带宽和丢包率则是“这条高速公路有多少条车道，路上有没有坑洼导致车祸”，它决定的是【数据吞吐量】！
 - 只要美国专线带宽给足、0 丢包，除了首次加载有 0.1 秒轻微延迟外，后续 4K/8K 视频流将如开闸泄洪般飞速缓冲！
```

## 二、为什么测速跑满 1000M，看 YouTube 4K 依然卡顿？

这是 90% 的新手最容易踩入的测速误区：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【测速跑满千兆但看视频卡顿的技术真相】                        │
 ├─────────────────────────────────────────────────────────────────────────────────────────────┤
 │ 1. 【测速软件的“多线程并发作弊”】：                                                         │
 │    - Speedtest 等测速工具默认开启 16~32 个线程同时拉取数据；                                │
 │    - 哪怕单连接速度只有 20Mbps，32 个线程并发相加也能轻松在图表上画出“600Mbps 满载”！      │
 │                                                                                             │
 │ 2. 【YouTube 视频流的单线程工作机制】：                                                     │
 │    - YouTube、Netflix 播放视频时，浏览器只与服务器建立【单个 TCP 连接】持续拉取视频分片；  │
 │    - 若机场节点为了防大流量薅羊毛，在后端将单连接限速至 15Mbps，那么看 4K（码率需 35Mbps）必卡！│
 │                                                                                             │
 │ 3. 【丢包引发的 TCP 拥塞控制“断崖式降速”】：                                               │
 │    - 在公网海缆中，一旦发生 3% 的微小丢包，TCP 算法会误以为网络发生严重堵塞；               │
 │    - 算法会自动将传输窗口（Window Size）直接砍半，导致传输速度瞬间从 100Mbps 暴跌至 5Mbps！ │
 └─────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 七、常见高频问题解答 (FAQ)

### Q1：高速机场怎么选？最核心的第一指标是什么？
**答**：**晚高峰单线程带宽 (Single-Thread Bandwidth) 与丢包率！** 在晚上 20:30~22:30 黄金高峰期，单连接持续速率稳定在 **`> 50Mbps`** 且丢包率 **`< 0.1%`（专线为 `0%`）**，是保障 4K 秒开与大文件满速下载的第一铁律。

### Q2：什么是 IPLC 物理专线？为什么专线速度远快于普通中转？
**答**：IPLC 是租用跨国内陆点对点的专用物理光纤进行数据传输，**全程不走公网海缆、完全不经过 GFW 审查**。物理光纤独享带宽，彻底消灭了晚高峰国际海缆拥堵造成的丢包与降速，全天候满速秒开。

### Q3：为什么测速图显示 800M，但我看 YouTube 4K 依然卡顿？
**答**：因为测速软件默认开启了 32 个线程并发，拉出的是多连接瞬时峰值；而 YouTube 属于**单线程持续数据传输**。若节点单连接被限制在 15Mbps 或存在 3% 以上的微小丢包，TCP 算法会触发拥塞控制大幅降速导致卡顿。

### Q4：看 4K 和 8K 视频分别需要多少真实带宽？
**答**：YouTube 4K 60FPS 视频的码率通常在 **`25Mbps ~ 45Mbps`**；8K 60FPS HDR 视频码率在 **`80Mbps ~ 150Mbps`**。只要机场单连接持续带宽达到 50Mbps 以上，即可实现 4K 进度条随意拖动 0 缓冲。

### Q5：主流客户端（Clash Verge Rev、v2rayN、小火箭）中哪款跑大带宽最强？
**答**：电脑端强烈推荐 **[Clash Verge Rev](/clash-verge-rev/)**（Mihomo 核心并发吞吐性能极强）或 **[v2rayN](/v2rayn/)**（Sing-box 核心资源占用低）；iOS 推荐 **[Shadowrocket](/shadowrocket/)**。

### Q6：什么是 BBR 拥塞控制算法？
**答**：BBR (Bottleneck Bandwidth and RTT) 是 Google 开发的革命性 TCP 拥塞控制算法。优质机场在服务器内核开启 BBR 后，能主动探测网络真实瓶颈，在丢包环境下依然能榨干物理带宽，传输速度提升 3~5 倍。

### Q7：打外服联机网游（如 Apex、Steam）需要什么样的速度？
**答**：网游对带宽要求不高（每小时仅消耗几十 MB），但对 **网络抖动 (Jitter < 3ms) 与丢包率 (0%)** 要求极高；必须选择支持全端口 UDP 转发的 **IPLC 游戏专线** 并开启客户端【TUN 模式】。

### Q8：遇到高速机场突发降速怎么办？
**答**：按照标准排查流程：先检查本地 Wi-Fi 信号（切换 5G 频段避开 2.4G 干扰）、在客户端策略组中切换到冷门的新加坡或美西专线节点、登录机场官网查看最新节点扩容公告。

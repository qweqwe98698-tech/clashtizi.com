## 二、硬核技术原理：IPLC/IEPL 到底赢在哪里

### 2.1 从一次晚高峰抓包说起

先把现象摆出来。工作日晚 21:00，一条普通公网中转线路，从国内某三线城家宽出口到香港落地，`mtr` 结果大致是这样：

```
HOST: client                    Loss%   Snt   Last   Avg  Best  Wrst StDev
 1. 192.168.1.1                  0.0%   200    1.2   1.3   0.9   4.1   0.4
 2. 100.64.0.1 (CGNAT)           0.0%   200    6.8   9.2   5.1  42.7   6.1
 3. 202.97.x.x (电信出口)         2.5%   200   18.4  26.7  15.2 210.3  31.5
 4. 202.97.y.y (国际骨干)        11.0%   200   45.1  88.3  38.7 480.6  92.4
 5. 203.0.x.x (香港入口)         14.5%   200   52.3 102.7  44.1 512.9 108.2
 6. target (落地)                15.0%   200   53.0 105.4  45.0 530.1 112.6
```

第 3 跳开始出现丢包，第 4 跳（国际骨干 202.97 段）丢包率飙到 11%，落地端稳定在 15%。这不是"墙"在丢包，而是**国际出口链路超售 + 拥塞队列溢出**。同一时间，一条 IEPL 专线跑同样的 `mtr`：

```
HOST: client                    Loss%   Snt   Last   Avg  Best  Wrst StDev
 1. 192.168.1.1                  0.0%   200    1.1   1.2   0.9   3.8   0.3
 2. 10.x.x.x (专线内网入口)       0.0%   200    5.4   5.6   5.0   8.2   0.5
 3. 10.x.x.x (IEPL 内网隧道)      0.0%   200   28.1  28.4  27.9  30.1   0.4
 4. target (落地)                0.0%   200   28.5  28.7  28.2  30.5   0.4
```

丢包 0%，抖动 StDev 0.4ms。差距是数量级的。

### 2.2 IPLC 与 IEPL 的物理层差异

很多人把 IPLC 和 IEPL 混着说，工程上必须区分：

- **IPLC（International Private Leased Circuit）**：国际私有租用电路，运营商在物理层（SDH/OTN）给你划一条端到端专线，二层透传，本质是"你独占一根线"。带宽按 E1（2M）/STM-1（155M）等粒度售卖，成本极高。
- **IEPL（International Ethernet Private Line）**：国际以太网专线，基于 MPLS/VPLS 在运营商内网构建点对点以太网通道，三层隔离但共享底层物理资源。成本比 IPLC 低一个数量级，是机场行业主流方案。

对用户的实际影响：**两者都不过公网 BGP、不经过 GFW 国际出口、不参与公网路由震荡**。数据包从国内入口进入运营商内网后，走的是运营商自有骨干，直到海外落地机房才重新接入公网。GFW 的 DPI 设备部署在国际出口网关，专线流量根本不经过那里。

### 2.4 TCP 拥塞控制：为什么丢包对吞吐是毁灭性的

TCP 的吞吐公式（简化的 Mathis 模型）：

```
Throughput ≈ (MSS / RTT) × (C / √p)
```

其中 `p` 是丢包率，`C` 是常数。注意 `√p` 在分母——丢包率翻 4 倍，吞吐掉一半。这就是为什么公网线路丢包从 0.1% 涨到 5%，下载速度会从满速掉到几百 KB/s。

不同拥塞控制算法在丢包下的表现差异巨大：

| 算法 | 丢包判据 | 丢包后行为 | 适用场景 |
| --- | --- | --- | --- |
| Cubic | 丢包即拥塞 | 窗口砍半，线性恢复 | 传统公网，对随机丢包敏感 |
| BBRv1 | 带宽×RTT 建模 | 不因随机丢包降窗 | 高丢包链路，专线首选 |
| BBRv2 | 加入丢包率上限 | 丢包超阈值才降 | 兼顾公平性 |
| BBRv3 | 改进探测与公平 | 更平滑 | 新一代内核 |

**关键结论**：专线本身丢包接近 0，BBR 的收益主要体现在入口段（家宽到国内入口）和落地段的公网部分。但如果你用的是公网中转，即便服务端开了 BBR，国际骨干段的丢包依然会拖垮整体体验——因为 BBR 只能优化自己这一端的发送行为，管不了中间路由器的队列丢弃。

### 2.5 MTU/MSS 分片：被忽视的性能杀手

IEPL 内网隧道常常叠加一层封装（VXLAN/GRE），导致有效 MTU 从 1500 降到 1450 甚至 1400。如果客户端 MSS 没跟着调，会出现：

- 大包被分片，`tcpdump` 里看到大量 `fragmented IP packet`
- PMTUD（路径 MTU 发现）被 ICMP 屏蔽时，连接直接卡死
- 表现为"能 ping 通、能打开网页，但下载/视频卡住"

排查命令：

```bash
# 探测路径 MTU
ping -M do -s 1472 target.com   # 1472+28=1500
ping -M do -s 1422 target.com   # 1422+28=1450

# 抓包看分片
tcpdump -i any -nn 'ip[6:2] & 0x1fff != 0'
```

服务端调优（Linux）：

```bash
# /etc/sysctl.conf
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
net.ipv4.tcp_mtu_probing = 1
net.ipv4.tcp_base_mss = 1024
net.core.rmem_max = 67108864
net.core.wmem_max = 67108864
net.ipv4.tcp_rmem = 4096 87380 33554432
net.ipv4.tcp_wmem = 4096 65536 33554432
net.ipv4.tcp_slow_start_after_idle = 0
```

应用后 `sysctl -p`，用 `sysctl net.ipv4.tcp_congestion_control` 确认生效。

### 2.6 UDP QoS 限速：为什么"看视频卡、下载却快"

运营商对 UDP 流量的 QoS 策略普遍比 TCP 激进。QUIC（HTTP/3）、WireGuard、部分代理协议的 UDP 转发，在晚高峰会被限速甚至丢弃。这就是"Speedtest 跑满、YouTube 4K 却转圈"的典型症状。

缓解思路：

1. 客户端优先走 TCP 系协议（VLESS+TCP+TLS、Trojan）
2. 若必须 UDP，选有独立 UDP 中转的专线（如部分 IEPL 提供 UDP 优化通道）
3. 关闭浏览器 QUIC：Chrome 地址栏输入 `chrome://flags/#enable-quic` 设为 Disabled

### 2.7 抖动（Jitter）才是体感的核心

带宽决定"能跑多快"，抖动决定"稳不稳"。视频会议、游戏、SSH 交互对抖动极度敏感。公网线路晚高峰抖动常达 80–300ms，专线可压到 1–5ms。这是 IPLC/IEPL 最不可替代的价值。

## 四、全平台客户端调优实战

### 4.1 Windows / macOS：Clash Verge Rev

1. 从 GitHub Release 下载对应平台安装包，安装后首次启动会提示安装服务模式（TUN 模式必需），点击安装。
2. 进入"订阅"页，粘贴机场订阅链接，点击导入。若订阅被墙，先用手机热点或临时梯子导入。
3. 进入"设置"，打开 **TUN 模式**（接管全局流量）、**系统代理**（可选，TUN 开启后可关）、**DNS 覆写**。
4. DNS 配置建议：

```yaml
dns:
  enable: true
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16
  nameserver:
    - https://223.5.5.5/dns-query
    - https://1.1.1.1/dns-query
  fallback:
    - https://8.8.8.8/dns-query
    - tls://1.0.0.1:853
```

5. 验证 DNS 是否泄漏：访问 `browserleaks.com/dns`，确认解析服务器不是你本地 ISP。

### 4.2 iOS：Shadowrocket 小火箭

1. App Store 用非国区 Apple ID 购买下载（国区已下架）。详细步骤见 [Shadowrocket 小火箭 iOS 安装与分流教程](/shadowrocket/)。
2. 添加订阅：首页右上角 `+` → 类型选 Subscribe → 粘贴链接 → 保存。
3. 全局路由选"配置"或"代理"，开启"绕过中国大陆"。
4. 关键设置：
   - **DNS**：设置为 `1.1.1.1` 或 `8.8.8.8`，避免使用运营商 DNS
   - **TUN 模式**：iOS 上叫"VPN 模式"，默认开启
   - **UDP 转发**：若专线支持，开启以优化游戏/视频通话
5. 若节点全红，参考 [梯子节点超时全红与连接失败排障指南](/tizi/nodes-timeout/)。

### 4.3 Android：Sing-box / v2rayNG

**Sing-box**（推荐，功能最全）：

1. 从 GitHub 下载 APK 安装。
2. 导入订阅：配置 → 新建 → 从剪贴板导入。
3. 开启 TUN 模式（需 root 或使用 VPN 模式）。
4. 路由规则参考 [Sing-box 全能通用配置与路由规则教程](/tutorials/sing-box-config/)。

**v2rayNG**（轻量）：

1. 安装后点击右上角 `+` → 从剪贴板导入订阅。
2. 设置 → 路由模式选"绕过局域网及中国大陆"。
3. 详细配置见 [v2rayN Windows 客户端配置与排障完整教程](/v2rayn/)（界面逻辑相通）。

### 4.4 通用调优要点

- **关闭 IPv6**：多数专线未优化 IPv6，开启后易出现"部分网站打不开"。客户端设置里禁用 IPv6 解析。
- **MSS 钳制**：若出现大包卡死，在客户端配置 `tcp-mss: 1400`。
- **协议选择**：VLESS+TLS 优先，Trojan 次之，避免使用已被重点识别的老协议。
- **订阅更新频率**：专线节点 IP 相对稳定，每周更新一次订阅即可，无需频繁刷新。

## 五、深度 FAQ 排障

### Q1：节点全部超时、全红，但国内网站正常

**排查分支**：

1. **订阅是否过期**：登录机场官网查看流量与到期时间。
2. **本地网络是否被劫持**：`nslookup google.com` 看返回 IP 是否异常。
3. **客户端时间是否准确**：TLS 握手依赖系统时间，偏差超 5 分钟直接失败。`w32tm /resync`（Windows）或 `sudo sntp -sS time.apple.com`（macOS）。
4. **订阅链接是否被墙**：用手机热点重新导入订阅。
5. **端口是否被封**：换节点或换协议测试。

详细流程见 [梯子节点超时全红与连接失败排障指南](/tizi/nodes-timeout/)。

### Q2：能打开 Google，但打不开部分国外网站

典型是 **DNS 污染 + 分流规则误判**。解决：

1. 客户端开启 fake-ip 模式，强制所有域名走代理解析。
2. 检查分流规则是否把目标域名误判为"直连"。
3. 用 `curl -v https://target.com` 看卡在哪一步。

### Q3：ChatGPT 报 1020 错误 / 无法访问

1020 是 Cloudflare 的区域封锁拦截，说明你的落地 IP 被标记为"高风险区域"或"数据中心 IP"。

**解决**：

1. 切换到原生 IP 节点（光速云、飞猫云标注原生解锁的节点）。
2. 清除浏览器 Cookie 和缓存，重新登录。
3. 关闭浏览器 WebRTC，避免真实 IP 泄漏。
4. 若仍失败，换节点区域（日本/新加坡通常比香港宽松）。

### Q4：晚高峰速度断崖式下跌

**排查**：

1. `mtr` 定位丢包发生在哪一跳。若在运营商出口（第 2–3 跳），是本地线路问题；若在国际骨干，是公网拥塞。
2. 若你用的是公网中转，这是结构性问题，换专线才能根治。
3. 若已是专线仍慢，检查是否触发了机场的限速策略（部分套餐有单节点限速）。

### Q5：视频能播但一直缓冲，下载却很快

UDP QoS 限速的典型症状。解决：

1. 关闭浏览器 QUIC（`chrome://flags/#enable-quic` → Disabled）。
2. 客户端协议从 UDP 系切到 TCP 系。
3. 换支持 UDP 优化的专线节点。

### Q6：如何判断一个机场会不会跑路

**防跑路决策树**：

1. **运营年限**：< 1 年的新机场风险最高，优先选 2 年以上的。
2. **是否支持月付**：只卖年付、拒绝月付的，跑路成本低，警惕。
3. **是否有公开 SLA**：如光速云的 5 年 SLA 承诺，是相对可靠的信号。
4. **节点是否自有**：宣称"企业级专线""华为云节点"的比"个人 VPS 中转"可靠。
5. **社区口碑**：在多个独立论坛交叉验证，警惕单一来源的吹捧。
6. **支付方式**：支持支付宝/微信的比只收加密货币的更容易追溯。

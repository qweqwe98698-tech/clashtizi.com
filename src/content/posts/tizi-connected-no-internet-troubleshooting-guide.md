> **【💡 30 秒极速直接答案：代理连接成功但没网核心定性与四大排障原则】**
> - **第一核心定性**：**“客户端显示 Connected（已连接）、节点测速显示绿色延迟，绝对不等于整机流量已经成功打通！”** 测速仅代表你的设备与远端服务器握手成功；如果浏览器依然打不开网页，**90% 的原因出在本地流量拦截层（系统代理未写入、TUN 虚拟网卡未授权、分流规则误设为 Direct、或本地 DNS 死锁）**；
> - **六类典型“连上没网”极速分诊与应对**：
>   1. **所有网页（国内百度和国外 Google）全打不开** ──► 属于**节点出口断网**、**本地 DNS 解析死锁**或**底层路由环路** ──► 换绿色节点或重启网络；
>   2. **国外网站秒开，国内微信、淘宝严重转圈卡死** ──► 属于**分流模式误切成了【全局 (Global / Proxy)】** ──► 切回【规则 (Rule / Config)】模式秒级复活；
>   3. **大部分外网正常，唯独一个特定小众网站打不开** ──► 属于**分流规则未收录该域名被误判直连**，或目标平台屏蔽机房 IP ──► 手动添加 Proxy 规则或换出口 IP；
>   4. **Chrome 浏览器正常翻墙，但 Telegram、Git 命令行、游戏联机连不上** ──► 这些独立应用无视系统代理 ──► 开启客户端中的**【TUN 虚拟网卡模式】**；
>   5. **直接输入海外纯 IP 能开，输入网址显示无法访问** ──► 本地 DNS 解析死锁 ──► 配置公共加密 DNS (DoH) 并刷新缓存；
>   6. **关掉梯子软件后，整台电脑网页全打不开了** ──► 属于**系统代理残留** ──► 在 Windows 代理设置中关闭“手动设置代理”。

## 二、六大典型“连上没网”现象分类与第一优先级应对总表

在排查前，请对照下表确认你的电脑或手机到底遭遇了哪一种“没网”：

| 故障现象分类 | 核心阻断层级 | 最核心真实诱发诱因 | 第一步标准应对动作 |
| :--- | :--- | :--- | :--- |
| **A：节点测速正常，但浏览器打不开外网** | 系统代理未生效 | 客户端仅开启了本地端口，未将代理写入系统设置 | 检查并切实打开客户端中的【系统代理 (System Proxy)】 |
| **B：外网秒开，但国内微信、淘宝全卡死** | 路由分流模式层 | 分流模式误选为【全局 (Global / Proxy)】，国内流量绕美 | 将分流模式切实切回【规则 (Rule / Config)】智能分流 |
| **C：浏览器正常，但电报/Git终端/游戏断网** | 应用层协议支持度 | 这些独立软件和网游无视 Windows 系统代理 | 开启客户端中的【TUN 虚拟网卡模式】接管整机流量 |
| **D：输入纯 IP 能开，输入网址就打不开** | 域名解析 (DNS) 层 | 本地 DNS 解析死锁，或配置了无效的境外 53 端口 DNS | 在客户端配置加密 DNS (DoH) 或填入 `223.5.5.5` |
| **E：关掉代理软件后，整台电脑彻底断网** | 系统代理残留层 | 客户端异常退出时未能注销 Windows 注册表代理 | 在 Windows 设置中手动关闭“使用代理服务器”开关 |
| **F：开启 TUN 模式后电脑反而彻底断网** | 虚拟网卡驱动层 | 未以管理员身份运行，或虚拟网卡驱动与杀毒软件冲突 | 以管理员身份重新启动客户端，重启电脑释放驱动 |

## 三、第一步排查：系统代理 (System Proxy) 是否真正接管流量

在 Windows 和 macOS 上，绝大多数浏览器默认依赖操作系统的“系统代理”设置：

```text
 1. 【为什么连接成功了浏览器依然没网？】：
    - 很多开源客户端（如 Clash Verge Rev、v2rayN）启动并连接节点后，默认仅仅在本地启动了端口监听（如 127.0.0.1:7897 或 10809）；
    - 如果你没有手动勾选【系统代理】，Windows 根本不知道要将浏览器的流量送给该客户端！
    - 表现：客户端里跑测速全绿，但浏览器访问网页依然走本地直连，外网依然打不开。

 2. 【检查系统代理是否真正写入（Windows 实操）】：
    - 按下快捷键 `Win + I` 打开系统设置 ──► 进入【网络和 Internet】──►【代理】；
    - 查看“手动设置代理”：
      * 【使用代理服务器】是否处于【开】状态？
      * 代理 IP 是否为 `127.0.0.1`，端口是否与客户端一致（Clash 通常为 7897，v2rayN 通常为 10809）；
    - 若未开启，在客户端中重新打开【系统代理】开关即可。
```

## 四、第二步排查：分流模式误配（Rule 智能分流 vs Global 全局 vs Direct 直连）

分流模式决定了客户端如何对待不同网址的请求：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【三大核心分流模式底层网络行为对比】                          │
 ├──────────────────────┬──────────────────────────────┬───────────────────────────────────────┤
 │ 路由模式名称         │ 流量处理底层逻辑             │ 实际网络表现与潜在翻车点              │
 ├──────────────────────┼──────────────────────────────┼───────────────────────────────────────┤
 │ **Rule (规则模式)**   │ 匹配规则库走代理，国内走直连 │ 🟢 **推荐 99% 的时间长期使用**，国内秒开，国外翻墙 │
 ├──────────────────────┼──────────────────────────────┼───────────────────────────────────────┤
 │ **Global (全局模式)** | 所有流量全量强制送入海外节点 │ 🔴 国内应用极度卡顿，微信发图转圈，网银异地风控拦截 │
 ├──────────────────────┼──────────────────────────────┼───────────────────────────────────────┤
 │ **Direct (直连模式)** | 所有流量直接裸连，完全不走代理│ 🔴 **相当于关闭梯子功能！所有海外受阻网站彻底打不开**│
 └──────────────────────┴──────────────────────────────┴───────────────────────────────────────┘
```

**黄金诊断法则**：
- 如果在 Rule 模式下某个海外网站打不开，**临时切为 Global 全局模式测试 1 分钟**：
  * 若 Global 下秒开：**100% 证明你的节点和底层链路完全正常！** 纯粹是分流规则未收录该域名被误判成了直连；
  * 若 Global 下依然打不开：说明是节点服务器断网、DNS 解析死锁或本地端口冲突。

## 五、第三步排查：TUN 虚拟网卡模式与应用程序代理兼容性

为什么有时“浏览器能正常看 YouTube 4K，但 Telegram、Discord、Git 命令行或外服网游却显示无网络”？

```text
 1. 【Windows 系统代理的物理局限性】：
    - Windows 的【系统代理】本质上只是应用层 HTTP 代理（WinINet API）；
    - 只有 Chrome、Edge 等通用浏览器会自动遵守该设置；
    - Telegram、Discord、游戏客户端、终端命令行默认直接调用底层的裸套接字，完全无视系统代理！

 2. 【开启 TUN 虚拟网卡模式一键全局穿透】：
    - TUN 模式会在操作系统内核加载一张驱动级虚拟网卡（Layer 3），强行拦截整台设备的所有 IP 数据包（包括 TCP 与 UDP）；
    - 开启 TUN 模式后，任何软件无需进行繁琐的单独代理配置，自动全部实现透明翻墙！
    - ⚠️ 注意：开启 TUN 模式必须为客户端赋予【管理员权限】运行。
```

## 六、第四步排查：浏览器独立代理扩展（SwitchyOmega）截胡冲突

如果你发现 **Edge 浏览器能正常翻墙，但主力 Chrome 浏览器死活打不开网页**：

```text
 1. 【浏览器扩展代理独占机制】：
    - Chrome 规定：一旦安装了代理管理扩展（如 SwitchyOmega、ZeroOmega 或某些安全去广告插件），
    - 浏览器会直接交出代理控制权，Windows 系统的全局代理被彻底废弃！
 2. 【解决办法】：
    - 点击 Chrome 右上角的插件图标，打开 SwitchyOmega；
    - 将代理模式切换为 **【[系统代理] (System Proxy)】**；
    - 刷新网页，Chrome 瞬间恢复正常上网。
```

## 七、第五步排查：退出梯子后电脑彻底断网（系统代理残留彻底解决）

这是 Windows 平台使用代理工具最常见、最容易让新手恐慌的难题：

```text
 ⚠️ 【为什么退出软件后电脑连百度都打不开了？】：
 - 客户端开启系统代理时，在注册表中将代理服务器指向了 `127.0.0.1:端口`；
 - 当客户端被任务管理器强杀、死机断电或异常崩溃退出时，来不及执行“注销代理”代码；
 - 导致 Windows 开机后依然在向空无一人的本地端口发请求，整台电脑全线瘫痪断网！
 
 🟢 15 秒极速恢复标准解法：
 1. 按下快捷键 `Win + I` 打开 Windows 系统设置；
 2. 点击【网络和 Internet】──► 选择【代理】；
 3. 在“手动设置代理”区域，将【使用代理服务器】的开关切实【关闭】，点击保存，国内网络瞬间恢复！
```

## 八、代理连接成功但没网 5 分钟极速排障 SOP（标准 HowTo）

遇到显示已连接但打不开网页时，请严格按以下 6 步标准顺序排查：

```text
 Step 1: 测出真实握手 ──► 客户端执行真连接延迟测试，确认选中的节点有绿色有效毫秒数（排查节点故障）
    ↓
 Step 2: 核查系统代理 ──► 检查客户端【系统代理】是否开启，Win+I 核验 Windows 注册表代理是否写入
    ↓
 Step 3: 核对分流模式 ──► 确认处于【规则 (Rule)】模式，切勿误选【直连 (Direct)】或【全局 (Global)】
    ↓
 Step 4: 清理浏览器插件 ──► 检查 Chrome 是否装了 SwitchyOmega，切为“系统代理”模式
    ↓
 Step 5: 开启管理员 TUN ──► 遇电报、Git 或游戏不通，退出客户端以管理员身份运行，开启 TUN 虚拟网卡
    ↓
 Step 6: 终极飞行模式重置 ──► 开启飞行模式 10 秒后关闭，强制清理操作系统网络扩展接口死锁
```

 ❌ 误区 14：看到网页报错 ERR_CONNECTION_TIMED_OUT 就断定电脑中毒。(错！纯粹是节点出口无法连接目标服务器)

## 十、常见问题解答 (FAQ)

### Q1：为什么梯子显示“Connected 已连接”，但浏览器依然打不开网页？
**答**：最常见原因是客户端没有成功开启“系统代理 (System Proxy)”。连接成功只代表软件与节点通了，必须打开系统代理，Windows/Mac 的浏览器才会把上网流量发给软件。

### Q2：为什么把梯子软件关掉之后，电脑连百度和微信都断网了？
**答**：这是典型的“系统代理残留”。客户端退出时没有将 Windows 代理开关复位。按 `Win+I` 进入【网络和 Internet】──►【代理】，手动关闭“使用代理服务器”即可秒级恢复。

### Q3：为什么切换到“Global 全局模式”能上网，换回“Rule 规则模式”就没网了？
**答**：这证明节点和网络完全正常。问题在于 Rule 模式的规则库把你想访问的网址错误地判定成了“Direct 直连”，或者分流策略组选错了失效节点，更新订阅规则即可。

### Q4：为什么 Chrome 浏览器可以翻墙，但电脑上的游戏或命令行终端没网？
**答**：因为很多桌面软件和游戏不遵循操作系统的“系统代理”设置。在客户端设置中安装并开启 **【TUN 虚拟网卡模式】**，即可强制捕获所有底层网络数据包。

### Q5：开启 TUN 模式后反而所有网站都打不开了是怎么回事？
**答**：通常是因为 TUN 模式未以管理员权限运行，导致虚拟网卡路由表死锁；或者电脑上存在其他残留的虚拟网卡冲突。以管理员身份重新启动软件即可。

### Q6：为什么 Google 能秒开，但是访问 ChatGPT 却提示“无法访问此网站”？
**答**：这说明你的梯子网络完全通畅，不是断网故障。原因是 ChatGPT 对数据中心机房 IP 进行了地区阻断或风控拦截，切换到日本/新加坡原生节点即可。

### Q7：浏览器安装了代理扩展（如 SwitchyOmega）会产生冲突吗？
**答**：会。浏览器扩展的优先级通常高于操作系统设置。如果扩展内配置了错误的转发规则，会导致浏览器流量无法进入客户端，建议排查时先停用扩展或切为【系统代理】模式。

### Q8：什么是“Direct 直连模式”？为什么选了它之后国外网站都打不开？
**答**：Direct 模式代表让所有流量直接连接目标服务器，完全不经过任何海外代理节点。误选 Direct 模式相当于直接在裸连状态下访问外网，自然无法打开。

> **【⚠️ 核心急救认知：客户端显示 Connected ≠ 所有流量都已经走代理！】**
> 
> 很多新手遇到最困惑的情况是：**“客户端明明显示绿色已连接（Connected），测速也完全正常，但打开 Chrome 依然显示无法访问网络”**。
> - **连接成功只代表通信链路建立**：它只证明客户端与远端节点服务器握手成功，不代表操作系统和浏览器已经把流量交给了客户端；
> - **90% 的原因在本地流量路由**：问题通常出在 **【系统代理 (System Proxy) 未打开】**、**【分流规则误判 (Rule 判成 Direct)】**、**【浏览器独立代理扩展冲突】** 或 **【DNS 解析死锁】**。

## 一、“连接成功”与“流量真正出海”的核心机制解耦

要彻底搞懂为什么“连上了却没网”，必须理解数据包在操作系统内部的 4 级流向：

```text
                               【现代代理数据包 4 级流向全景图】

 [应用程序 (浏览器/微信/游戏)]
        │
        ├──► ① 是否支持系统代理？ ──(是)──► [System Proxy 机制] ──► [客户端本地监听端口] ──┐
        │                                                                              │
        └──► ② 不支持系统代理？   ──(是)──► [TUN 虚拟网卡劫持] ──► [客户端核心 Core]  ───┼──► [加密发往海外节点]
                                                                                       │
                                                                   [③ 匹配分流规则] ──┘
                                                                   - Rule: 智能分流 (国内直连/海外代理)
                                                                   - Global: 全部走代理
                                                                   - Direct: 全部不走代理 (直接断网)
```

## 二、第一步：排查 System Proxy（系统代理）是否正确接管

在 Windows 和 macOS 上，浏览器默认依赖操作系统的系统代理设置：

### 1. 现象一：客户端开了，但浏览器依然直连
- **原因**：很多开源客户端（如 [Clash Verge Rev](/tutorials/clash-verge-setup/)）安装后，默认仅在本地开启代理端口（如 `127.0.0.1:7897`），并不会自动修改系统设置；
- **修复方法**：在客户端左侧或设置界面，找到 **【系统代理 (System Proxy)】** 并将其切换为开启状态。

### 2. 现象二：退出梯子软件后，电脑彻底断网连不上国内网页
- **原因（系统代理残留）**：客户端异常退出或崩溃时，未能及时清理系统注册表中的代理开关，导致 Windows 依然把流量发往已经不存在的本地端口；
- **极速修复 SOP（Windows）**：
  1. 按 `Win + I` 打开系统设置 ──► 点击 **【网络和 Internet】** ──► 进入 **【代理 (Proxy)】**；
  2. 找到 **【手动设置代理】** ──► 将“使用代理服务器”开关**彻底关闭** ──► 保存后网页瞬间恢复。

## 三、第二步：排查分流模式（Rule vs Global vs Direct）

分流模式决定了客户端如何对待不同网址的请求：

| 分流模式 | 数据处理逻辑 | 典型应用场景 | 容易导致的“没网”误区 |
| :--- | :--- | :--- | :--- |
| **Rule (规则模式)** | 命中规则列表走代理，国内域名直连 | **日常长期推荐使用** | 若新网站未包含在规则库中，会被误判直连导致打不开 |
| **Global (全局模式)** | 不论国内国外，100% 全部走节点 | 排查规则故障 / 跨境业务 | 国内应用（微信/网易云）变慢甚至提示异地登录 |
| **Direct (直连模式)** | 100% 全部不走代理，相当于关闭梯子 | 极少数纯内网调试 | **误开此模式会导致所有外网彻底打不开** |

```text
 💡 黄金排查法：如果你的 Rule 模式打不开 Google，请立刻在客户端中将模式切为【Global 全局模式】。
 - 若 Global 模式下能正常秒开：100% 证明节点和链路完全正常，纯属分流规则错误或策略组选错了节点！
```

## 四、第三步：排查 TUN 模式与应用程序代理兼容性

为什么有时“网页能正常看 YouTube，但 Telegram、Discord 或 Steam 游戏却显示无网络”？

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                                   【System Proxy 与 TUN 模式差异表】                        │
 ├──────────────────────────────┬──────────────────────────────┬──────────────────────────────┤
 │ 对比维度                     │ System Proxy (系统代理)      │ TUN Mode (虚拟网卡模式)      │
 ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┤
 │ **接管流量范围**             │ 仅限 Chrome、Edge 等通用浏览器 | 操作系统全局所有流量 (含游戏/命令行) │
 │ **对非标准 App 支持**        │ ❌ 大量客户端软件不遵循系统设置 | ✅ 强制捕获底层 IP 数据包    │
 │ **管理员权限要求**           │ 无需额外驱动                 │ 需要安装并授权虚拟网卡驱动   │
 │ **常见冲突风险**             │ 软件退出后易残留代理地址     │ 与旧版杀毒软件或网络防火墙抢占路由 │
 └──────────────────────────────┴──────────────────────────────┴──────────────────────────────┘
```

- **解决策略**：在客户端设置中安装 **【TUN 模式驱动】** 并开启 TUN 开关，即可解决所有非浏览器软件（如终端 Git、即时通讯软件、外服游戏）无法连网的问题。

## 五、第四步：排查浏览器独立代理扩展与 Secure DNS 冲突

浏览器自身的环境配置常常是隐蔽的故障点：

```text
 1. 检查浏览器代理扩展 ──► 是否安装了 SwitchyOmega 等插件？ (插件可能强制覆盖客户端设置)
        ↓ 解决：暂时禁用第三方代理插件，交由系统代理接管
 2. 检查浏览器安全 DNS (Secure DNS) ──► 是否开启了 DoH 加密 DNS？ (DoH 可能会绕过本地分流)
        ↓ 解决：在 Chrome 设置【隐私和安全】中，将“使用安全 DNS”暂时切为“使用当前服务商”
```

## 🔒 故障排查安全与操作底线

> **排查安全铁律**：
> - **切勿盲目执行“一键重置 Winsock / 网络重置”**：一键重置会清空所有网卡驱动与局域网静态 IP，通常只需手动关闭系统代理即可；
> - **切勿长期使用 Global 模式浏览国内服务**：长期开启全局代理会导致国内银行 APP、微信触发异地登录风控；

## 八、常见问题解答 (FAQ)

### Q1：为什么梯子显示“Connected 已连接”，但浏览器依然打不开网页？
**答**：最常见原因是客户端没有成功开启“系统代理 (System Proxy)”。连接成功只代表软件与节点通了，必须打开系统代理，Windows/Mac 的浏览器才会把上网流量发给软件。

### Q2：为什么把梯子软件关掉之后，电脑连百度和微信都断网了？
**答**：这是典型的“系统代理残留”。客户端退出时没有将 Windows 代理开关复位。按 `Win+I` 进入【网络和 Internet】──►【代理】，手动关闭“使用代理服务器”即可秒级恢复。

### Q3：为什么切换到“Global 全局模式”能上网，换回“Rule 规则模式”就没网了？
**答**：这证明节点和网络完全正常。问题在于 Rule 模式的规则库把你想访问的网址错误地判定成了“Direct 直连”，或者分流策略组选错了失效节点，更新订阅规则即可。

### Q4：为什么 Chrome 浏览器可以翻墙，但电脑上的游戏或命令行终端没网？
**答**：因为很多桌面软件和游戏不遵循操作系统的“系统代理”设置。在客户端设置中安装并开启 **【TUN 虚拟网卡模式】**，即可强制捕获所有底层网络数据包。

### Q5：开启 TUN 模式后反而所有网站都打不开了是怎么回事？
**答**：通常是因为 TUN 模式的虚拟网卡与电脑已有的杀毒软件、公司 VPN 或本地 DNS 发生了路由抢占。关闭 TUN 模式，改用标准系统代理即可。

### Q6：为什么 Google 能秒开，但是访问 ChatGPT 却提示“无法访问此网站”？
**答**：这说明你的梯子网络完全通畅，不是断网故障。原因是 ChatGPT 对数据中心机房 IP 进行了地区阻断或风控拦截，切换到日本/新加坡原生节点即可。

### Q7：浏览器安装了代理扩展（如 SwitchyOmega）会产生冲突吗？
**答**：会。浏览器扩展的优先级通常高于操作系统设置。如果扩展内配置了错误的转发规则，会导致浏览器流量无法进入客户端，建议排查时先停用扩展。

### Q8：什么是“Direct 直连模式”？为什么选了它之后国外网站都打不开？
**答**：Direct 模式代表让所有流量直接连接目标服务器，完全不经过任何海外代理节点。误选 Direct 模式相当于直接在裸连状态下访问外网，自然无法打开。

### Q9：手机热点能正常翻墙，连家里 Wi-Fi 显示连接成功却没网怎么办？
**答**：说明路由器开启了特定的 DNS 拦截或防护。尝试将电脑本地连接的 DNS 手动修改为公共 DNS（如 `223.5.5.5` 或 `119.29.29.29`）后重新连接。

### Q10：客户端里的“策略组 (Proxy Group)”选错了会导致没网吗？
**答**：会。如果分流规则把国外流量分给了“PROXY”策略组，而你在该策略组下手动选中了一个已经超时失效的红色节点，就会导致全网瘫痪。

### Q11：排查“连接成功但没网”需要重装电脑系统吗？
**答**：绝对不需要。这纯属网络应用层的代理路由与开关问题，按照“系统代理 ──► 分流模式 ──► TUN 模式”五分钟内即可彻底排查修复。

### Q12：为什么有时候开启梯子后国内网页打开速度变得极慢？
**答**：通常是因为你开启了【Global 全局模式】，导致访问国内网站的请求也绕道海外节点再回国。切回【Rule 规则模式】即可实现国内直连加速。

> **【💡 30 秒极速分诊：Clash Verge Rev 开了但没网，问题到底在哪一层？】**
> - **第一核心定性**：**“节点测速显示绿色（有毫秒延迟）”绝对不等于“电脑可以正常上网”！** URL-Test 仅代表内核能向测试网址发送握手包，完全不代表你的浏览器数据流能顺利穿透代理链路；
> - **六种“没网”现象极速定位**：
>   1. **所有节点测速全是红色 Timeout** ──► 节点/网络物理级中断 ──► 转入 [节点全部超时排查](/clash-verge-rev/nodes-timeout/)；
>   2. **节点显示绿色数字，但浏览器打不开网页** ──► 查看连接 (Connections) 面板：若无任何请求，为 [System Proxy 系统代理未生效](/clash-verge-rev/system-proxy-not-working/)；
>   3. **普通代理正常，一旦点开 TUN 模式全机断网** ──► 虚拟网卡路由死锁或缺少提权服务 ──► 转入 [TUN实操与排查](/clash-verge-rev/tun/)；
>   4. **模式切到 Global 能秒开，切回 Rule 全挂** ──► 分流规则或策略组选错节点 ──► 转入 [Global能用Rule不能排查](/clash-verge-rev/rule-mode-not-working/)；
>   5. **能直接输入 IP 访问后台，但输入域名提示打不开** ──► 遭遇本地 DNS 污染或死锁 ──► 转入 [DNS解析失败排查](/tizi/dns-resolution-failed/)；
>   6. **退出 Clash Verge Rev 后整台电脑全网断网** ──► 典型的本地系统代理残留，去网络设置中关闭代理开关即可秒级复活。

## 一、六大“没网”症状与第一优先级排查对照表

| 具体没网症状分类 | 底层真实技术阻断点 | 最核心诱发诱因 | 第一步标准排错动作 |
| :--- | :--- | :--- | :--- |
| **A：节点全部红，任何网站打不开** | 节点出站链路整体中断 | 系统时间偏差、宽带欠费、机场维护 | 校准本地时间，检查光猫网络，重启 Core |
| **B：节点全绿，但浏览器完全没网** | 流量根本没有流进代理内核 | 系统代理开关未勾选、杀毒软件拦截 | 打开 Connections 确认是否有浏览器请求跳出 |
| **C：普通模式正常，一开 TUN 就断网** | 虚拟网卡创建失败或路由死锁 | 缺少服务模式权限、多虚拟网卡冲突 | 安装服务模式，关闭其他 VPN，勾选 Bypass LAN |
| **D：Global 正常，切回 Rule 就没网** | 智能分流规则或策略组异常 | 主策略组选到了红色死节点、规则缺失 | 手动将规则主策略组固定为一个绿色可用节点 |
| **E：浏览器秒开，但特定 App 断网** | 目标应用不主动读取系统代理 | 游戏使用 UDP 裸包，CLI 依赖环境变量 | 为该软件配置环境变量，或按需开启 TUN 模式 |
| **F：退出软件后，整台电脑网页全挂** | 典型的“系统代理残留” | 客户端非正常退出，未清理注册表端口 | 手动关闭 Windows 设置中的“使用代理服务器” |

## 四、为什么“节点显示有延迟 (ms)”，网页却死活打不开？

这是最具有迷惑性的故障场景：客户端里每个节点都绿油油地标着 `45ms`、`80ms`，但浏览器访问 Google 永远提示无法连接：

```text
 1. 【测试机制与真实访问路径不同】：
    - 节点旁边的数字是【URL-Test】机制的测试结果：Mihomo 内核直接向一个极简测试地址（如 Cloudflare 204）发了个轻量探针；
    - 只要探针握手成功，就会点亮绿灯；但这绝不代表你的 Chrome 浏览器已经成功把数据包通过系统代理送给了内核。

 2. 【核心断流点排查】：
    - 检查 Windows 系统代理：按 `Win + I` 进入【网络和 Internet】──►【代理】，确认“使用代理服务器”是否处于打开状态，且 IP 为 `127.0.0.1`；
    - 检查端口冲突：若电脑后台还开着其他代理软件（如 v2rayN 或旧版 CFW），本地 7890 端口被抢占，也会导致浏览器发出的请求被送进死胡同。
```

## 五、受控 A/B 隔离测试法：快速定位故障层级

通过四组极速双向对比，可以在 2 分钟内将问题精准锁定到某一特定功能模块：

| A/B 测试对比组 | 测试方法与操作 | 诊断结论与排查分支 |
| :--- | :--- | :--- |
| **测试 1：Global vs Rule** | 将模式切为 `Global`，在代理面板任选一绿节点刷新网页 | 若 Global 正常但 Rule 失败 ──► **100% 为规则或策略组选点问题** |
| **测试 2：System Proxy vs TUN** | 关闭系统代理，安装服务模式后打开 `TUN 模式` 重试 | 若 TUN 正常但代理失败 ──► **系统代理注册表未写入或端口被占** |
| **测试 3：Wi-Fi vs 手机热点** | 断开家庭光猫 Wi-Fi，用电脑连接手机 4G/5G 热点测试 | 若热点正常但 Wi-Fi 失败 ──► **路由器 DNS 污染或光猫防火墙阻断** |
| **测试 4：纯 IP 访问 vs 域名访问** | 在浏览器直接访问 `1.1.1.1` 或海外公开 IP 地址 | 若 IP 能通但域名打不开 ──► **标准 DNS 解析死锁或 Fake-IP 异常** |

## 八、关于“开了没网”的 15 大核心认知误区

```text
 ❌ 误区 1：只要节点测速显示绿色，就证明整台电脑 100% 绝对能顺利翻墙。(错！URL-Test 仅代表探针成功)
 ❌ 误区 2：一遇到打不开网页，第一反应就是把订阅删光、把客户端卸载重装。(错！盲目重装只会丢配置且无用)
 ❌ 误区 3：电脑没网时，把 TUN、Global、DNS 全部同时打开能“大力出奇迹”。(错！多重变量混合只会让网络彻底死锁)
 ❌ 误区 4：看到浏览器提示连接被拒绝，立刻去网上下载不知名的“一键网络修复包”。(错！极易植入恶意木马)
 ❌ 误区 5：为了解决连上没网，听信谣言在电脑里把 Windows 防火墙彻底永久关闭。(错！防火墙不会拦截正常代理端口)
 ❌ 误区 6：连接代理后局域网的 NAS 和打印机搜不到了，说明整台电脑网络坏了。(错！属于私有网段未开启 Bypass LAN)
 ❌ 误区 7：在两个策略组里把节点切成一样的，翻墙速度就会自动加倍。(错！单一连接只会走单条线路)
 ❌ 误区 8：退出软件后打不开网页，说明主板网卡被客户端烧坏了。(错！99% 是未清理残留的本地系统代理)
 ❌ 误区 9：节点显示 20ms 的时候没网，换成 120ms 的节点就更不可能有网了。(错！20ms 节点可能正处于流量封控)
 ❌ 误区 10：只要把所有规则全部删掉，没网的问题就会自动修复。(错！删除规则将导致失去所有代理引导)
 ❌ 误区 11：在公司内网里连上没网，肯定是机场节点服务器故障。(错！企业防火墙网关严密阻断了外部加密出站)
 ❌ 误区 12：在手机上能正常连，电脑上连不上就一定是电脑中毒了。(错！两端的代理入口机制和系统网络环境各异)
 ❌ 误区 13：看到 Fake-IP 的 198.18 虚拟 IP 就断定网络被劫持了。(错！属于代理内核标准的高效 DNS 映射机制)
 ❌ 误区 14：只要把系统 DNS 改成 8.8.8.8，所有的没网故障就全能自动修复。(错！若流量压根没进内核，改 DNS 无效)
 ❌ 误区 15：打不开网页时，疯狂快速连点几十次刷新能冲破拦截。(错！高频请求会直接触发服务器 WAF 防刷拉黑)
```

## 九、常见问题解答 (FAQ)

### Q1：为什么节点测速全是绿色且有延迟数字，但浏览器就是打不开任何网页？
**答**：测速绿仅代表客户端内核能与节点服务器建立握手连接；打不开网页通常是因为浏览器的流量没有送进客户端。请打开 Windows 网络设置，检查【代理】中的“使用代理服务器”是否已开启，并查看客户端左侧【连接】面板是否有该网页的请求跳出。

### Q2：怎么在客户端里确认流量到底有没有进入代理内核？
**答**：打开 Clash Verge Rev 左侧的【连接 (Connections)】实时监控面板，重新在浏览器中刷新打不开的网页。若列表中立即跳出了该域名的请求记录，证实流量已成功进入内核；若空空如也，说明流量在系统代理入口层被拦截。

### Q3：为什么退出 Clash Verge Rev 之后，电脑连国内的百度都打不开了？
**答**：这是经典的“系统代理残留”：软件关闭时未自动清理操作系统的代理注册表，导致系统仍把数据发往已关闭的 7890 端口。在 Windows【网络设置】──►【代理】中手动关闭“使用代理服务器”，或重新打开软件正常点击右键退出即可秒级恢复。

### Q4：为什么普通系统代理能用，一旦在设置里开启 TUN 模式全机就彻底断网了？
**答**：说明核心的虚拟网卡路由发生了死锁或权限不足。请先在设置中安装并点亮【服务模式 (Service Mode)】，确保勾选了【Bypass LAN (绕过局域网)】，并彻底退出其他后台可能存在的 VPN 或游戏加速器。

### Q5：为什么切到 Global 模式网页能秒开，一切回 Rule 模式就显示无法访问？
**答**：Global 能用证明你的节点和网络完好无损！切回 Rule 没网通常是因为规则主策略组误选了一个红色超时的死节点，或者该网站的域名未被规则库收录被误判为了国内直连。进入代理面板手动将该策略组换为绿色可用节点即可。

### Q6：能直接通过 IP 地址访问外网服务，但输入域名就显示无法访问怎么办？
**答**：属于典型的 DNS 解析异常或死锁。说明客户端的 DNS 模块未能正确将域名解析出目标地址；进入客户端设置清空 Fake-IP 缓存，或参考 [《DNS解析失败排查指南》](/tizi/dns-resolution-failed/) 配置正确的引导 DNS。

### Q7：开了 Clash 之后，为什么家里的局域网 NAS (192.168.1.x) 和打印机连不上了？
**答**：这是因为代理软件错误接管了局域网私有网段。在客户端设置中开启【Bypass LAN (绕过局域网)】选项，并在自定义规则中确保 `IP-CIDR,192.168.0.0/16,DIRECT` 规则置顶生效即可完美解决。

### Q8：遇到开了没网，最忌讳的操作是什么？
**答**：最忌讳“病急乱投医同时改动多个设置”（比如一边改 DNS、一边换规则、一边卸载驱动、一边关防火墙）。这样只会引入更多不可逆的故障变量导致彻底断网；科学方法是每次只改一个变量，用连接面板查看反馈。

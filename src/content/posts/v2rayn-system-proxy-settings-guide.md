> **【💡 30 秒极速直接答案：v2rayN 系统代理核心开关与正确使用姿势】**
> - **核心开关位置**：Windows 任务栏右下角小托盘 ──► 找到 V 字图标鼠标右键 ──► 找到【系统代理】子菜单：
>   1. **【自动配置系统代理】**：**日常翻墙必选！** 托盘图标**变为红色**，向 Windows 注册表写入 `127.0.0.1:10809`，浏览器即刻可以翻墙；
>   2. **【清除系统代理】**：**不翻墙时必选！** 托盘图标**变为蓝色**，注销注册表代理，防止关机或退出后电脑断网；
>   3. **【不改变系统代理】**：仅供配合第三方插件（如 SwitchyOmega）或软路由的高阶用户使用；
> - **为什么电报、Git 或游戏不走代理？** Windows 系统代理本质是应用层 HTTP 代理，仅对 Chrome/Edge 浏览器有效！非浏览器软件（Telegram、Discord、终端命令行、Steam 游戏）默认不读取注册表，必须**在软件内手动填 `127.0.0.1:10808` (SOCKS)** 或**开启 v2rayN 的【TUN 模式】**！

## 一、托盘图标三大状态与系统代理选项深度对比

在 Windows 任务栏右下角，v2rayN 的图标颜色直接反映了当前系统代理的接管状态：

| 托盘图标颜色 | 对应的系统代理菜单项 | 注册表实际状态 | 实际网络表现与适用场景 |
| :--- | :--- | :--- | :--- |
| 🔴 **鲜艳红色图标** | **【自动配置系统代理】** | `ProxyEnable = 1` (生效中) | 🟢 **正常翻墙状态**：Chrome/Edge 自动走代理，可正常访问 Google、YouTube |
| 🔵 **纯净蓝色图标** | **【清除系统代理】** | `ProxyEnable = 0` (已注销) | ⚪ **纯后台/直连状态**：内核后台运行但系统不走代理，电脑完全使用本地物理宽带 |
| 🟡/⚪ **无改变状态**| **【不改变系统代理】** | 保持当前注册表不变 | 🟣 **高阶定制状态**：供搭配浏览器 SwitchyOmega 插件或局域网局域分流使用 |

## 二、为什么 2026 年彻底淘汰 PAC 模式？（PAC vs 核心路由深度辨析）

在旧版 v2rayN 中常看到“PAC 模式”，但现代 6.x / 7.x 版本已全面弱化甚至移除 PAC，**取而代之的是底部的【路由分流 (Routing)】**：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【PAC 模式 vs 核心路由分流技术对比】                          │
 ├──────────────────────┬──────────────────────────────┬───────────────────────────────────────┤
 │ 核心比对维度         │ 老旧的 PAC 模式 (已淘汰)     │ 现代核心路由规则 (推荐常驻)           │
 ├──────────────────────┼──────────────────────────────┼───────────────────────────────────────┤
 │ **分流执行位置**     │ 由浏览器执行 JavaScript 脚本 | 由底层 Xray / Sing-box 内核直接匹配   │
 │ **规则库维护方式**   │ 依赖古老的 gfwlist.txt 文本  │ 实时编译的 `geoip.dat` 与 `geosite.dat`│
 │ **非浏览器软件支持** │ 🔴 仅浏览器能解析 PAC 脚本   │ 🟢 接管所有走代理端口的桌面软件与服务 │
 │ **性能与维护难度**   │ 规则陈旧易崩溃，更新繁琐     │ 毫秒级二进制树查找，占用极低，自动同步│
 └──────────────────────┴──────────────────────────────┴───────────────────────────────────────┘
```

**实操准则**：不要在系统代理中折腾 PAC 模式！保持托盘为【自动配置系统代理】，**分流策略完全交由客户端主界面下方的【路由】切换为【绕过大陆 (bypass-mainland)】即可！**

## 三、双端口分工：HTTP 代理 (10809) 与 SOCKS5 代理 (10808)

在 v2rayN 的【设置】──►【参数设置】中，默认开启了两个本地端口：

| 端口号 | 协议类型 | 核心技术特性 | 适用软件与具体配置范例 |
| :--- | :--- | :--- | :--- |
| **`10809`** | **HTTP / HTTPS 代理** | 支持标准 Web 协议，Windows 系统代理默认绑定的就是该端口 | 浏览器、curl、Git (`http.proxy`)、大部分前端开发工具 |
| **`10808`** | **SOCKS5 代理** | 支持传输层 TCP/UDP 无连接代理，穿透性与原生协议支持更广 | **Telegram、Discord、Proxifier、游戏辅助工具首选** |

## 四、终极痛点剖析：为什么浏览器能翻墙，某些软件死活不走代理？

许多用户遇到“在 Chrome 看 4K 视频飞快，但桌面电报一直转圈、Git 命令行 clone 报错连接超时”，原因在于**软件底层网络调用的差异**：

```text
 ⚠️ 【Windows 代理机制物理硬伤】：
 微软系统的“系统代理”，仅仅是一个针对 WinINet API 的软性注册表提示。
 绝大多数开发者编写控制台程序或跨平台软件时，直接调用底层的 Winsock 或 Libuv 裸套接字，
 这些应用从不主动去读取注册表里的 10809 端口！
```

### 常见不走代理软件的针对性手动配置指南：

#### 1. Telegram (电报) 桌面端配置
- 打开 Telegram 左上角菜单 ──►【Settings (设置)】──►【Advanced (高级)】──►【Connection type (连接类型)】；
- 选择【Use custom proxy (使用自定义代理)】──► 点击【Add proxy】；
- 选择 **`SOCKS5`**，主机填 `127.0.0.1`，端口填 **`10808`**；保存后右下角瞬间打勾连接！

#### 2. Git 命令行配置代理
在 CMD 或 PowerShell 中执行以下命令，为 Git 全局绑定本地代理：
```bash
# 设置 HTTP/HTTPS 代理走 10809 端口
git config --global http.proxy http://127.0.0.1:10809
git config --global https.proxy http://127.0.0.1:10809

# 若不需要时，执行以下命令即可取消：
git config --global --unset http.proxy
git config --global --unset https.proxy
```

#### 3. CMD 与 PowerShell 终端临时代理
普通控制台执行 `curl` 或下载脚本时，在当前窗口临时生效：
```powershell
# Windows PowerShell 终端中执行：
$env:http_proxy="http://127.0.0.1:10809"
$env:https_proxy="http://127.0.0.1:10809"

# 经典 CMD 命令行中执行：
set http_proxy=http://127.0.0.1:10809
set https_proxy=http://127.0.0.1:10809
```

## 五、退出客户端后电脑全线断网？——系统代理残留与注册表死锁彻底解决

这是使用 v2rayN 必须掌握的救命知识点：

```text
 1. 【为什么会发生代理残留断网？】：
    - 当你在托盘处于【红标 (自动配置系统代理)】时，Windows 注册表被强制写入了 127.0.0.1:10809；
    - 如果你直接用任务管理器结束进程、电脑突然死机、或直接合上笔记本断电关机；
    - v2rayN 根本来不及执行“注销代理”的代码，导致电脑开机后依然在向空无一人的 10809 端口发请求，整台电脑全线瘫痪断网！

 2. 【15 秒极速复原方案（二选一）】：
    - 【方案 A】：重新打开 v2rayN，在右下角托盘右键 ──► 点击【清除系统代理】（图标变蓝），然后正常点击退出，代理瞬间清除！
    - 【方案 B】：按下 `Win + I` 打开 Windows 设置 ──► 进入【网络和 Internet】──►【代理】──► 将“手动设置代理”下的【使用代理服务器】开关手动拨到【关】，点击保存即可！
```

## 八、常见问题解答 (FAQ)

### Q1：v2rayN 托盘图标的红色和蓝色分别代表什么意思？
**答**：**红色代表【自动配置系统代理已开启】**，此时 Windows 注册表被写入了代理地址，浏览器等应用会自动走代理翻墙；**蓝色代表【清除系统代理（纯后台运行）】**，此时虽然 v2rayN 仍在运行，但系统不会主动走代理，处于本地宽带直连状态。

### Q2：为什么开启了系统代理（红标），但 Telegram 或 Discord 依然转圈连不上？
**答**：因为 Windows 的“系统代理”仅适用于标准浏览器；Telegram 等软件默认不读取系统注册表代理。**在 Telegram 的网络设置中手动添加 SOCKS5 代理：地址 `127.0.0.1`，端口 `10808`** 即可秒级解决；或者直接开启 v2rayN 的【TUN 模式】。

### Q3：关闭 v2rayN 之后，为什么电脑网页全打不开了，微信也断网？
**答**：属于经典的**注册表系统代理残留**！重新打开 v2rayN，在右下角托盘右键选择【清除系统代理】即可；或者按下 `Win + I` 打开系统设置 ──► 进入【网络和 Internet】──►【代理】──► 将“使用代理服务器”手动关闭。

### Q4：什么是 PAC 模式？2026 年还需要用 PAC 吗？
**答**：**完全不需要，PAC 模式已被全面淘汰！** PAC 依赖浏览器执行臃肿的 JavaScript 脚本分流，规则维护陈旧。现代 v2rayN 推荐直接使用底部的【绕过大陆 (bypass-mainland)】核心路由分流，性能和稳定性高几个数量级。

### Q5：HTTP 端口 10809 和 SOCKS 端口 10808 有什么区别？
**答**：`10809` 是 HTTP/HTTPS 代理端口，专门对接浏览器和 Windows 系统代理；`10808` 是传输层 SOCKS5 代理端口，支持无连接的 TCP/UDP 流量，专门供 Telegram、Proxifier 等独立应用手动配置使用。

### Q6：CMD 终端或 PowerShell 运行 git clone 或 curl 为什么不走代理？
**答**：命令行工具默认不会读取 Windows 注册表系统代理。在终端中执行 `$env:http_proxy="http://127.0.0.1:10809"` 赋予环境变量临时代理，或者通过 `git config --global http.proxy` 永久配置。

### Q7：开启系统代理后，国内网银和微信会被监控或限速吗？
**答**：只要你的客户端底部路由选择的是 **【绕过大陆 (bypass-mainland)】**，所有国内网站与 App 的数据包都会在本地直接放行走本地直连，完全不经过海外代理节点，既不会降速也不会被风控。

### Q8：平时退出 v2rayN 最规范的标准动作是什么？
**答**：最规范的动作是：**先在右下角托盘图标右键 ──► 点击【清除系统代理】（图标变蓝）──► 然后再右键点击【退出】**。养成这一良好习惯，能 100% 杜绝关机或重启后的断网难题。

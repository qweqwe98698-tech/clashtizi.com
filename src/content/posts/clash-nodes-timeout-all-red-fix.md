> **文章摘要**：
> 在使用 Clash Verge Rev、Clash for Windows 或各类基于 Mihomo/Clash 内核的客户端时，节点延迟测试突然全部显示 `Timeout` 或“全红”，并不必然意味着节点服务器全部宕机。故障可能源于本机系统时间偏差、订阅格式损坏、客户端核心（Core）假死、系统代理端口冲突、DNS 污染解析失败、TUN 虚拟网卡驱动异常或本地防火墙拦截。本文提供了一套标准化的由浅入深排查决策流，帮助你在 5 分钟内快速定位并解决断网问题。

---

## ⚡ 30 秒快速判断 (Quick Answer)

**遇到 Clash 无法上网或节点全红时，请根据以下场景快速定位排查方向：**

1. **如果只有个别 1~2 个节点 Timeout**：通常属于该服务器单点网络波动或正在维护，直接切换到同地区的其他可用节点即可。
2. **如果所有节点突然同时全部全红 (Timeout)**：**90% 的概率是本机环境问题**，优先排查操作系统时间是否同步、订阅是否过期、客户端内核是否假死，以及本地 Wi-Fi 是否通畅。
3. **如果节点测速显示几十毫秒延迟，但网页完全打不开**：重点检查客户端**代理模式（是否误设为 Direct）**、**系统代理（System Proxy）是否开启**，以及 **DNS 是否解析异常**。
4. **如果一开启系统代理，整个电脑所有软件（包括微信/百度）立即断网**：说明本地端口发生冲突或系统代理注册表未正确写入，优先关闭系统代理并检查 Mixed-Port 端口占用。

| :--- | :--- | :--- |

| **更新订阅提示 Network Error 或 invalid yaml** | 机场节点链接失效、流量用尽、订阅链接被拦截 | 登录服务商后台检查账户状态、更换订阅链接 |

## 一、为什么 Clash 会出现节点 Timeout？（网络链路解析）

要快速排障，首先需要了解数据包在通过 Clash 时的真实流转路径：

```text
[应用程序 / 浏览器]
       │
       ▼ (1. 捕获流量)
[系统代理 System Proxy / TUN 虚拟网卡]
       │
       ▼ (2. 路由分流与域名解析)
[Clash / Mihomo 客户端内核] ◄──► [DNS 解析模块 (Fake-IP / Redir)]
       │
       ▼ (3. 加密出站)
[本地物理网卡 & 路由器]
       │
       ▼ (4. 跨境传输)
[远端代理节点服务器] ──► [目标网站 (Google/YouTube)]
```

- **URL Test（延迟测试）的本质**：Clash 节点列表显示的延迟，是客户端内核向指定测试网址（如 `http://www.gstatic.com/generate_204`）发起 HTTP HEAD/GET 握手所消耗的时间。
- **为什么不是 ICMP Ping？**：很多用户习惯称其为“Ping”，但 Clash 绝大多数使用的是基于应用层的 **URL Test (Connection Test)**。当测试请求在设定的超时阈值（通常为 5000ms）内未收到响应包时，界面就会标记为 **Timeout（红色）**。
- **排错逻辑**：链路中的任何一个环节（系统时间、DNS、本地端口、路由器、远端服务器）出现中断，都会导致最终表现为 Timeout。

## 二、单节点超时与全部节点全红有什么区别？

| 维度 | 单个 / 少数节点 Timeout | 所有节点全部全红 (All Red) |
| :--- | :--- | :--- |
| **故障位置** | 远端服务器单点故障或机房维护 | **本机操作系统、客户端内核或本地基础网络** |
| **波及范围** | 仅影响特定国家/地区的节点 | 导致所有外网乃至国内应用同时受阻 |
| **典型诱因** | 节点 IP 被墙、机房迁移、单机带宽拥塞 | 系统时间误差、内核假死、端口冲突、DNS 故障 |
| **解决思路** | 无需折腾电脑，切换其他节点即可 | 按照本文 1~5 步逐一排查本地系统环境 |

## 三、第一步：确认本地基础网络是否正常

在怀疑 Clash 之前，**必须先排除物理网络与光猫连接是否正常**：

1. **彻底关闭 Clash 代理**：在客户端中关闭 **「系统代理 (System Proxy)」** 与 **「TUN 模式」**。
2. **测试基础连通性**：打开浏览器，直接访问国内大型网站（如 `https://www.baidu.com` 或 `https://www.bilibili.com`）。
3. **结果判定**：
   - **如果连百度都打不开**：说明是你的网线松动、Wi-Fi 掉线、路由器死机或宽带欠费，请先恢复本地网络。
   - **如果国内网站秒开，但开启 Clash 后全红**：说明物理网络正常，问题出在 Clash 软件、配置或代理链路上，请继续执行第二步。

---

## 四、第二步：检查并同步系统时间与时区（最高频诱因）

这是导致 Clash 所有节点毫无征兆全红的**第一大罪魁祸首**。

- **技术原理**：Clash 依赖 TLS 1.3 / VMess / VLESS / Shadowsocks 等高强度加密协议与远端服务器进行握手校验。TLS 证书握手对时间戳要求极其苛刻，如果本机时间与全球标准时间偏差超过 **60 秒**，服务器会出于防重放攻击保护直接拒绝建立连接，所有节点瞬间全部 Timeout。

```text
[系统时间偏差 > 60s] ──► [TLS 证书握手校验失败] ──► [连接被拒] ──► [全部节点显示 Timeout]
```

### Windows 10 / 11 快速修复：
1. 右键屏幕右下角任务栏的 **时间区域** $ightarrow$ 选择 **「调整日期和时间」**。
2. 确保开启 **「自动设置时间」** 与 **「自动设置时区」**（时区应为 `UTC+08:00 北京，重庆，香港特别行政区，乌鲁木齐`）。
3. 找到并点击 **「立即同步 (Sync Now)」** 按钮，直到下方出现对勾提示。

### macOS 快速修复：
1. 打开 **「系统设置」** $ightarrow$ **「通用」** $ightarrow$ **「日期与时间」**。
2. 确保勾选 **「自动设置时间与日期」**（来源选择 `time.apple.com`）。

## 五、第三步：更新订阅并检查配置有效性

节点配置过期、流量耗尽或订阅被服务商重置也会导致全红：

1. **手动刷新订阅**：
   - 在 Clash Verge Rev 中点击左侧 **「订阅 (Profiles)」** 栏目。
   - 找到当前正在使用的配置文件，点击右侧的 **🔄 刷新 (Update)** 按钮。
2. **观察更新结果**：
   - **如果提示绿色成功**：检查节点列表中是否刷新出了最新节点，再次点击右下角的测速按钮。
   - **如果提示 Network Error / 403 Forbidden / 401 Unauthorized**：
     - 说明机场账户可能已到期、流量耗尽，或原订阅链接已被服务商废弃。
     - 请登录机场后台复制最新的订阅链接重新导入。
3. **检查配置文件大小**：如果下载下来的配置仅有几百字节，通常说明机场返回了错误页面（如 HTML 网页而非 Yaml 配置），请联系服务商客服。

## 六、订阅有节点但全部 Timeout 怎么办？

如果确认订阅更新成功、节点列表也完整存在，但测速依旧全红，请按以下优先级排查：

1. **检查本地防火墙**：确认 Windows Defender 防火墙没有拦截 `verge-mihomo.exe` 或 `clash-core.exe`。
2. **检查节点加密协议**：某些老旧 Clash 客户端不支持 Hysteria 2、TUIC v5 或 VLESS Reality 新协议，导致无法解析出站。建议升级至现代化的 **[Clash Verge Rev 客户端](/clash-verge-rev/)**。
3. **更换测试 URL**：在设置中将延迟测试 URL 由默认地址修改为：`http://cp.cloudflare.com/generate_204` 或 `http://www.google.com/generate_204`。

## 七、第四步：完全重启 Clash 客户端与核心进程 (Core)

有时仅点击右上角的“×”号只是将窗口最小化到了系统托盘，后台假死的 Core 进程并未退出：

1. **彻底退出程序**：在 Windows 右下角系统托盘中，右键 Clash 图标，选择 **「Quit / 退出」**。
2. **结束残留进程**：
   - 按下 `Ctrl + Shift + Esc` 打开任务管理器。
   - 在进程列表中查找是否有残留的 `Clash Verge`、`clash-meta.exe`、`mihomo.exe` 或 `clash-win64.exe`。
   - 若存在，全部右键选择 **「结束任务」**。
3. **重新以正常权限启动**：重新双击打开客户端，等待 3 秒使核心完成端口绑定。

## 十、第五步：检查系统代理 (System Proxy) 状态与端口冲突

许多用户遇到“节点测速全绿，但浏览器就是打不开网页”，问题往往出在系统代理注册表：

```text
[浏览器发送请求] ──► [Windows 系统代理设置: 127.0.0.1:7897] ──► [Clash 监听端口: 7897] ──► [成功转发]
```

1. **核对系统代理开关**：
   - 进入 Windows **「设置」** $ightarrow$ **「网络和 Internet」** $ightarrow$ **「代理」**。
   - 确认 **「使用代理服务器」** 处于开启状态。
2. **核对代理端口一致性**：
   - 检查系统代理填写的端口（如 `127.0.0.1:7897` 或 `127.0.0.1:7890`）。
   - 打开 Clash 设置，确认其 **「Mixed-Port (混合端口)」** 或 **「HTTP Port」** 与系统代理中的数字**必须完全一致**。
3. **排查端口抢占**：
   - 如果同时开启了 Fiddler、Charles、其他 VPN 软件或特定杀毒软件，可能会将系统代理端口强行修改为其他数值，导致 Clash 无法接管流量。关闭这些冲突软件即可。

## 十一、开启系统代理后无法上网怎么办？

如果一打开系统代理整个电脑就连微信都发不出消息：

1. **第一步**：立即在 Clash 主界面关闭 **「系统代理 (System Proxy)」**。
2. **第二步**：确认国内网络是否立刻恢复正常。
3. **第三步**：如果关闭后恢复，说明 Clash 的出站流量遇到了死循环或本地端口被阻断。
   - 打开 Clash 基础设置，将 **Mixed Port** 从默认的 7890/7897 修改为一个不常用端口（例如 `17890` 或 `27890`）。
   - 重新开启系统代理进行测试。

## 十二、第六步：检查代理模式（Rule / Global / Direct）

代理模式选择错误会导致访问行为与预期完全不符：

| 模式名称 | 流量转发逻辑 | 适用场景 | 常见误区与风险 |
| :--- | :--- | :--- | :--- |
| **Rule (规则模式 - 强烈推荐)** | 根据规则分流：国内直连，国外走代理 | 日常主力使用，省流量且不影响国内应用 | 规则文件过旧可能导致新海外域名未走代理 |
| **Global (全局模式)** | 所有连接（包括国内网站）强制经过选定代理 | 调试特定外网服务、排查分流规则问题 | **若选中的节点失效，整台电脑所有网络瘫痪** |
| **Direct (直连模式)** | 所有连接直接直连，完全不走任何代理 | 临时停用代理功能，完全由本地网卡出站 | **选此模式将完全无法访问任何被阻断网站** |

> 💡 **检查建议**：日常使用请务必保持在 **「Rule (规则)」** 模式；如果在 Global 模式下选了一个超时的节点，浏览器将出现所有网页全部打不开的假死状态。

## 十三、第七步：检查 DNS 设置与 Fake-IP 机制

DNS 是科学上网中最容易产生隐蔽故障的环节：

```text
[用户输入域名] ──► [Clash 内置 DNS 模块] ──► [返回 Fake-IP (198.18.0.x)] ──► [内核建立代理连接]
```

- **为什么会出现“有延迟但打不开网页”？**：当本地 DNS 缓存混乱或运营商推送了错误解析时，浏览器拿到了被污染的 IP，根本没有将流量交给 Clash 内核处理，报错 `DNS_PROBE_FINISHED_NXDOMAIN` 或 `ERR_NAME_NOT_RESOLVED`。
- **排查方法**：
  1. 检查 Clash 的 DNS 模式，确认启用了 **Fake-IP** 或 **Redir-Host**。
  2. 确认 Nameserver 中配置了可靠的公共 DNS（如阿里 DNS `223.5.5.5`、腾讯 DNSPod `119.29.29.29` 以及海外安全 DNS `8.8.8.8`）。

## 十四、Windows 如何安全刷新 DNS 缓存？

当频繁更换网络环境或切换代理后，清理本地旧解析缓存能快速解决 80% 的网页加载报错：

1. 按下快捷键 `Win + R` 打开运行窗口，输入 `cmd` 并回车。
2. 在黑底控制台中输入以下标准命令并按下回车：
   ```bash
   ipconfig /flushdns
   ```
3. 屏幕提示 **“已成功刷新 DNS 解析缓存 (Successfully flushed the DNS Resolver Cache)”** 后，完全关闭并重新打开浏览器即可。

## 十五、第八步：检查 TUN 虚拟网卡模式与驱动

**TUN 模式**（虚拟网卡模式）能够接管整机所有网络流量（包括不支持系统代理的游戏、CMD 终端、Docker 等），但对系统底层权限要求极高：

1. **检查 TUN 驱动安装**：在 Clash Verge Rev 中进入 **「设置」** $ightarrow$ **「TUN 模式」**，确认已成功安装虚拟网卡服务（Wintun 驱动）。
2. **管理员权限运行**：TUN 模式必须拥有 Windows 管理员权限才能修改系统路由表。请右键 Clash 图标选择 **「以管理员身份运行」**。
3. **排查 TUN 与 System Proxy 冲突**：通常开启 TUN 模式后，无需同时开启 System Proxy（系统代理），两者同时开启可能在某些系统上引发路由冲突。

## 十六、第九步：检查 Windows 防火墙与第三方杀毒软件

企业内网环境、校园网或安装了特定杀毒卫士（如 360、火绒、深信服安全助手）的电脑，常会在后台静默拦截代理核心进程：

1. **临时测试放行**：
   - 打开 Windows 安全中心 $ightarrow$ **「防火墙和网络保护」** $ightarrow$ **「允许应用通过防火墙」**。
   - 找到 `Clash Verge`、`verge-mihomo.exe`，确认其在 **“专用”** 与 **“公用”** 网络下均已勾选放行。
2. **安全原则**：⚠️ **绝不建议永久关闭 Windows 防火墙**。只需在防火墙中为 Clash 核心建立正确的出站放行规则即可，排查完毕后应保持系统安全防护开启。

## 十七、为什么换手机 5G 热点后 Clash 立即正常？

如果同一台电脑在连接手机热点时节点全绿、飞速上网，但连上家庭/公司 Wi-Fi 就全部全红：

- **技术成因**：
  1. **宽带出口 IP 评分过低**：该宽带分配的公网 IP 恰好处于被远端机房安全策略拦截的网段。
  2. **路由器 DNS 劫持/阻断**：部分智能路由器（或开启了家长控制/安全拦截的网关）拦截了出站加密流量。
  3. **光猫/路由器 NAT 映射耗尽**：长时间未重启的路由器在处理大量高并发连接时丢包。
- **解决对策**：断电拔掉家庭光猫和无线路由器电源，等待 2 分钟后重新通电开机，强制宽带运营商重新分配新的公网出口 IP。

## 十八、为什么节点有延迟，但 Google / YouTube 打不开？

很多新手常问：“测速明明显示 45ms，为什么依然打不开 Google？”

1. **测速 URL 并不代表全网可达**：节点的 URL Test 仅证明客户端到测试服务器（如 gstatic）的握手成功，但该节点可能因配置问题无法解析或访问 YouTube。
2. **分流规则拦截**：检查 Clash 的 **「代理 (Proxies)」** 规则组中，`Google`、`YouTube` 或 `PROXY` 策略组是否误选为了 `DIRECT (直连)` 或某个失效的子节点。
3. **IPv6 优先级冲突**：部分运营商 IPv6 存在断流，可尝试在 Clash 配置中关闭 IPv6 解析，优先使用 IPv4 出站。

## 四、Clash 运行日志快速诊断表

当遇到疑难问题时，查看 Clash 的运行日志能够瞬间找到根因：

| 日志包含的关键报错词 | 更可能的原因分析 | 推荐修复动作 |
| :--- | :--- | :--- |
| `dial tcp: i/o timeout` | 节点连接超时，网络未连通或端口被封 | 检查系统时间，切换其他可用节点 |
| `bind: address already in use` | 本地端口冲突，7890/7897 已被其他程序占用 | 在设置中更改 Mixed-Port 为其他端口 |
| `connection refused` | 目标服务器主动拒绝连接或本地防火墙拦截 | 检查防火墙放行规则，重启内核 |
| `certificate has expired / untrusted` | 本地系统时间错误或遭遇中间人证书篡改 | 立即校准 Windows 系统日期与时间 |
| `DNS resolve failed / no such host` | DNS 解析彻底失败，无法获取节点真实 IP | 更换客户端 DNS，执行 ipconfig /flushdns |
| `permission denied (TUN)` | TUN 虚拟网卡权限不足，无法写入系统路由 | 退出软件，右键以管理员身份重新运行 |

## 🚫 这些错误操作不建议作为第一反应

在日常维护中，以下盲目操作通常不仅无法修好网络，还可能引发二次故障：

1. ❌ **一看到全红就立即重装操作系统**：99% 的问题仅出在系统时间和配置层面，重装系统完全是南辕北辙。
2. ❌ **永久关闭 Windows Defender 与系统防火墙**：使电脑完全暴露于网络威胁之中，正确做法仅需针对客户端添加应用白名单。
3. ❌ **随意修改 Windows 注册表代理键值**：极易导致关闭代理后整个电脑永久断网。
4. ❌ **下载来历不明的所谓“Clash 修复一键脚本”**：存在被植入恶意木马、窃取账号密码与劫持流量的严重安全风险。
5. ❌ **同时运行多个不同品牌的代理客户端**：多个软件争抢系统代理与 7890 端口，必然引发全网崩溃。

## ❓ 常见问题解答 (FAQ)

### Q1: Clash 节点 Timeout 是什么意思？
> **答**：Timeout 表示客户端发起的网络握手测试在规定时间（通常为 5 秒）内未收到服务器回应。可能是节点离线，也可能是本地系统时间错误导致握手失败。

### Q2: 为什么 Clash 所有节点会突然全部全红？
> **答**：最常见的原因是本机系统时间与标准北京时间存在偏差（导致证书握手失败）、客户端内核假死、机场订阅已过期，或本地 Wi-Fi 路由器拦截了出站流量。

### Q3: 为什么有节点延迟，但打开浏览器依然无法上网？
> **答**：说明客户端到节点服务器的通路正常，但电脑流量未正确导入。请检查是否开启了「系统代理 (System Proxy)」、代理模式是否误设为 Direct、或本地 DNS 是否发生解析污染。

### Q4: 开启 Clash 系统代理后，为什么连百度和微信都断网了？
> **答**：通常是因为 Clash 监听的端口被其他软件抢占，导致系统代理请求无人应答。请在设置中修改 Mixed-Port 端口（如改为 17890），或检查防火墙是否拦截了 Core 核心。

### Q5: 开启 TUN 模式后电脑无法上网怎么办？
> **答**：请确认是否以“管理员身份”运行 Clash，并检查 Wintun 虚拟网卡驱动是否安装成功。若依旧异常，可在设置中重装 TUN 驱动并重启电脑。

### Q6: 为什么手机连接热点时 Clash 正常，用家里 Wi-Fi 就全红？
> **答**：这证明客户端软件与配置完全正常，问题出在家庭宽带或路由器上。可尝试重启光猫和路由器以更换公网 IP，或将路由器 DNS 修改为 1.1.1.1。

### Q7: Clash Verge Rev 提示 Core 启动失败怎么办？
> **答**：通常是因为默认端口（7890/7897）被旧的 Clash 进程或其他后台代理占用。打开任务管理器结束所有残留的 clash/mihomo 进程，并在设置中修改端口后重启内核。

### Q8: Clash for Windows 节点总是全红还能用吗？
> **答**：CFW 已停止维护多年，无法较好兼容现代 VLESS/Hysteria 2 协议。建议直接切换至仍在活跃维护的现代化替代客户端 **[Clash Verge Rev](/clash-verge-rev/)**。

### Q9: 刷新 DNS 解析缓存对解决 Clash 故障有用吗？
> **答**：非常有用。在 CMD 中运行 `ipconfig /flushdns` 可以清除本机过期的域名映射，解决因 DNS 脏缓存导致的网页无法加载问题。

### Q10: 为什么更新订阅后节点列表还是旧的或全红？
> **答**：可能机场订阅链接已被重置，或当前网络无法连接到机场的订阅分发服务器。可尝试在浏览器中直接打开订阅链接测试是否能下载配置文件。

### Q11: 为什么重启 Clash 后就能短暂恢复上网？
> **答**：重启会清空堆积的连接池与释放被占用的端口。如果频繁发生，说明客户端版本存在内存泄漏，或者防病毒软件在定时阻断后台守护进程。

### Q12: 怎样判断是机场跑路了还是自己电脑设置问题？
> **答**：先确认关闭 Clash 后本地网络正常，再将订阅导入手机端客户端测试。如果手机和电脑在不同网络下均无法更新订阅且官网打不开，才可能是服务商故障。

## 🏁 总结与科学排障建议

遇到 Clash 节点超时与无法上网时，**切忌盲目乱改系统深层设置**。请牢记核心排查三部曲：
1. **先断开，测基础**：先关代理确认本地物理宽带健康。
2. **看范围，分内外**：单节点超时换节点，全节点全红先同步北京时间。
3. **查端口，顺链路**：核对系统代理端口、代理模式与 DNS 状态。

> **【⚠️ 核心急救警示：看到节点全红，先不要删除配置或重装软件！】**
> 
> 很多新手一打开客户端发现节点列表全是刺眼的红色“Timeout”，就惊慌失措地清空所有配置甚至卸载客户端——**切勿盲目操作！**
> - **全红不等于机场跑路**：90% 的“全红”纯粹是因为客户端测速机制（URL Test）受阻、底层 Core 核心未成功启动、或本地 Wi-Fi 的 DNS 解析发生了冲突；
> - **保留现场才能快速诊断**：清空配置不仅无法解决问题，反而会导致失去订阅对比样本。

在动手排查前，请花 30 秒做以下快速状态归类：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                                   【节点全红 30 秒快速分流法】                              │
 ├──────────────────────────────┬──────────────────────────────┬──────────────────────────────┤
 │ 客户端表现或现象             │ 故障所在核心层级             │ 第一步执行动作               │
 ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┤
 │ 🔴 **订阅本身也更新失败**    │ 订阅层故障 (非节点层)        │ 先看 [订阅更新失败排查指南](/tizi/subscription-update-failed/) |
 │ 🔴 **仅 1~2 个节点超时**     │ 单节点服务器维护             │ 直接鼠标点击切换到同地区备用节点 │
 │ 🔴 **Wi-Fi 全红 / 手机热点正常**│ 当前路由器 / 宽带阻断        │ 重启路由器或修改电脑本地 DNS  │
 │ 🔴 **手机正常 / 电脑全红**   │ 电脑端 Core / 防火墙拦截     │ 重启客户端或检查 Core 运行状态 │

 │ 🟡 **开启 TUN 后全部变红**   │ 虚拟网卡路由 / 权限冲突      │ 暂时关闭 TUN 模式改用系统代理 │
 │ 🔴 **所有设备/网络全部全红** │ 机场节点集中维护 / 协议变更  │ 登录机场官网查看最新线路公告  │
 └──────────────────────────────┴──────────────────────────────┴──────────────────────────────┘
```

## 一、单节点超时 vs 区域性超时 vs 全部节点全红对比

区分节点故障的范围，是缩小排查半径的关键：

| 故障范围现象 | 典型表现特征 | 最可能的根本原因 | 建议处置动作 |
| :--- | :--- | :--- | :--- |
| **单节点超时** | 只有 `香港 01` 超时，`香港 02` 和 `日本` 正常 | 该物理服务器正在重启或机房维护 | 鼠标切换至其他绿色节点即可 |
| **单地区全部超时** | 所有香港节点全红，但日本、美国全部是绿色 | 机场到香港方向的中继海缆发生波动 | 临时换用日本或新加坡节点过渡 |
| **特定协议全部超时** | VLESS 节点全红，Shadowsocks 节点全绿 | 客户端底层 Core 版本过旧不支持新协议 | [升级客户端版本](/tutorials/clash-verge-setup/) 或更新内置 Core |
| **所有节点全部全红** | 无论切换哪个国家和协议，100% 显示 Timeout | 本地网络阻断、Core 崩溃、或测试 URL 挂掉 | 按照本文下述步骤逐层排障 |

## 二、第一步：排查测速机制误报（URL Test 失败 ≠ 节点坏掉）

很多时候，“节点全红”仅仅是测速机制本身的乌龙：

```text
 [客户端测速逻辑]：节点 ──► 向测试网址 (如 www.google.com/generate_204) ──► 计算响应毫秒数
                          │
                   若该测试 URL 本身被拦截 ──► 客户端统一标记为红色【Timeout】
                   但实际上访问 YouTube / ChatGPT ──► 节点依然完全可用！
```

### 实测验证法：
1. 随意选中一个显示为红色 Timeout 的香港或日本节点；
2. 确保开启了 **【系统代理 (System Proxy)】**；
3. 打开浏览器无痕窗口访问 `https://www.google.com`；
4. **如果网页能秒开**：证明节点和网络完全正常，纯属测速目标 URL 引起的误报，无需理会红字。

## 三、第二步：网络出口交叉测试（Wi-Fi 宽带 vs 手机 5G 热点）

这是区分“本地家庭宽带问题”还是“机场服务器问题”最快的一招：

```text
                               【网络交叉测试判断模型】
                                           │
 ┌─────────────────────────────────────────┴─────────────────────────────────────────┐
 │                                                                                   │
 📶 测试 A：电脑连接家庭 Wi-Fi 测速全部全红                           📱 测试 B：电脑连接手机 5G 个人热点测速全部变绿
  - 证明：机场服务器和客户端 Core 完全正常                             - 证明：原家庭宽带路由器、本地 DNS 或运营商骨干网
  - 核心原因：家庭路由器被开启了异常过滤或 DNS 污染                   - 解决方案：修改本地电脑 DNS 为公共 DNS 或重启光猫
```

### 网络环境测试对照表：

| 测试环境组合 | 测试结果表现 | 结论与核心修复点 |
| :--- | :--- | :--- |
| **Wi-Fi 全红 / 手机热点全绿** | 换热点后所有节点瞬间恢复绿色 | **原 Wi-Fi 路由器 DNS 异常或宽带运营商波动** |
| **手机热点全红 / Wi-Fi 全绿** | 手机流量无法连通，宽带正常 | 手机卡运营商移动网络基站链路受限 |
| **公司/校园网全红 / 热点正常** | 公司内网全部超时，热点秒连 | **触发了公司 IT 企业的防火墙出网限制** |
| **所有网络下所有设备均全红** | 换了 3 种网络依然 100% 全红 | **机场节点大面积维护或订阅配置本身失效** |

## 四、第三步：排查客户端底层 Core（内核）运行状态

在 [Clash Verge Rev](/tutorials/clash-verge-setup/)、sing-box 等现代客户端中，界面（UI）与底层代理内核（Core）是分离的：

```text
 界面 (UI 正常点按) ──(若通信中断/内核崩溃)──► 底层 Core (无法收发数据) ──► 导致所有节点显示 Timeout
```

### 客户端 Core 检查清单：
1. **Core 是否被杀毒软件拦截**：检查 Windows Defender 或第三方安全管家是否将 `clash-meta.exe` 或 `sing-box.exe` 误报隔离；
2. **内核版本是否太旧**：如果机场上线了最新的 `VLESS Reality` 或 `Hysteria2` 协议，而老旧客户端的内核无法解析，会导致所有新节点显示 Timeout；
3. **Core 重启修复法**：在客户端设置中找到 **【重启内核 / Restart Core】**，点击后重新触发一次测速。

## 五、第四步：TUN 模式与 System Proxy（系统代理）冲突排查

分流模式与虚拟网卡的配置错误是电脑端全红的常见元凶：

| 代理模式状态 | 容易引发的故障现象 | 排查与修复方法 |
| :--- | :--- | :--- |
| **开启了 TUN 虚拟网卡模式** | 开启瞬间节点测速全红，甚至本地微信断网 | 检查是否缺少管理员权限；暂时**关闭 TUN 模式**，改用【系统代理】 |
| **系统代理 (System Proxy) 未开启** | 节点显示绿色，但浏览器无法上网 | 开启客户端内的系统代理开关（这不会影响节点测速本身） |
| **误选了【Direct (直连模式)】** | 客户端把所有流量强制直连，不走代理 | 将分流模式切回 **【Rule (规则模式)】** 或 **【Global】** |
| **开启了多个代理软件冲突** | 同时开着多个 VPN 或客户端抢占端口 | 彻底退出其他网络加速器与代理软件，保留唯一客户端 |

## 六、第五步：排查本地系统时间偏差与 TLS 握手失败

代理协议（尤其是基于 TLS/Reality 伪装的新型协议）对本地时钟精度的容错范围极小：

```text
 电脑时间偏差 > 60 秒 ──► 节点 TLS 握手鉴权被服务端判定非法 ──► 直接断开连接 ──► 节点显示 Timeout
```

- **Windows 修复**：按 `Win + I` 打开设置 ──► 【时间和语言】 ──► 【日期和时间】 ──► 点击 **【立即同步】**；
- **macOS 修复**：系统设置 ──► 【通用】 ──► 【日期与时间】 ──► 确保勾选“自动设置时间与日期”。

## 七、节点全红诊断八层模型（8-Layer Diagnostic Model）

遇到顽固全红故障时，请严格按以下标准顺序向下排查，切勿跨层乱改：

```text
 Layer 1: 订阅状态层 ──► 确认机场账号有效、套餐未欠费且能正常刷新订阅
    ↓
 Layer 2: 测速机制层 ──► 浏览器直接打开 Google，确认是否仅为测速 URL 误报
    ↓
 Layer 3: 网络出口层 ──► 切换手机 5G 个人热点，排查家庭 Wi-Fi 与宽带拦截
    ↓
 Layer 4: 客户端核心层 ──► 检查 Core 是否正常运行，重启客户端或升级内核
    ↓
 Layer 5: 虚拟网卡与系统层 ──► 暂时关闭 TUN 模式，校准电脑系统互联网时间
    ↓
 Layer 6: 协议兼容层 ──► 观察是否仅特定新协议超时，换用通用 Shadowsocks 节点
    ↓
 Layer 7: 软件交叉验证层 ──► 使用另一台设备或另一款开源客户端 (如 v2rayN) 验证
    ↓
 Layer 8: 服务商基础设施层 ──► 确认所有环境均全红后，登录官网查看维护公告或提工单
```

## 🔒 故障排查期间的安全底线

> **核心排查安全守则**：
> - **切勿轻信来源不明的“节点修复补丁”**：网络上所谓的“一键修复脚本”极可能植入流氓证书与挖矿后门；
> - **严禁永久关闭防火墙**：排查仅需确认 Core 程序是否被放行，绝不可为了翻墙彻底破坏操作系统安全防护体系；

## 九、常见问题解答 (FAQ)

### Q1：梯子节点全部显示超时（全红），最常见的原因是什么？
**答**：最常见的三个原因：1. 测速目标网址（URL Test）本身被拦截引起的虚假误报；2. 本地家庭 Wi-Fi 发生了 DNS 污染或路由故障；3. 客户端底层的代理内核（Core）崩溃或被安全软件阻止。

### Q2：节点全红是不是代表机场已经跑路了？
**答**：绝对不能这样轻易下结论。先登录机场官网后台查看账户能否登录、套餐是否过期，并用手机流量连接测试。如果官网正常且手机能连，纯属电脑本地配置问题。

### Q3：为什么客户端里所有节点都显示红色 Timeout，但网页却能秒开？
**答**：这说明节点本身通信完全正常。全红是因为客户端用来测速的默认测试地址（如 Google 生成的 204 链接）在握手时超时，属于纯粹的测速机制误报。

### Q4：为什么连接家庭 Wi-Fi 节点全红，一开手机 5G 热点就全变绿了？
**答**：这证明机场服务器完全正常。原因是你的家庭路由器开启了安全拦截、路由器 DNS 发生污染、或光猫拨号出现了临时链路异常，重启路由器通常可解决。

### Q5：为什么手机上节点全部正常，电脑上却全部显示超时？
**答**：问题出在电脑端系统环境：检查电脑系统时钟是否准确、Windows 防火墙是否拦截了客户端 Core 进程、或者电脑上开启了冲突的第三方网络加速器。

### Q6：什么是客户端的 Core（内核）？它损坏了会怎么样？
**答**：Core 是客户端底层真正负责网络加密和中继传输的核心引擎。如果 Core 被杀毒软件误杀或版本过旧，会导致客户端界面虽能点击，但所有节点无法发起连接（全部超时）。

### Q7：开启 TUN 虚拟网卡模式后节点全部超时怎么办？
**答**：通常是因为 TUN 模式的虚拟网卡接管了系统默认网关并引发了路由死锁。关闭 TUN 模式，改用通用的“系统代理 (System Proxy)”模式即可恢复。

### Q8：电脑时间不准真的会导致所有节点连接超时吗？
**答**：是的。现代加密协议（如 TLS、Reality）对时间戳校验极其严苛，一旦系统时钟偏差超过 1~2 分钟，服务端会直接拒绝建立安全连接导致全红。

### Q9：为什么只有某一种协议（如 VLESS）的节点全红，其他节点全绿？
**答**：说明你的客户端版本较旧，内置的代理内核不支持该新协议的解密算法。前往 GitHub 官方 Releases 页面更新客户端到最新版本即可。

### Q10：节点全红时，我应该把订阅删除重新添加吗？
**答**：不建议。删除订阅不会修复本地网络、系统时间或内核问题，反而会导致失去现有的节点列表。应先通过网络和客户端交叉测试定位根因。

### Q11：所有设备、所有网络测试全部节点都全红怎么办？
**答**：当手机热点、家庭宽带、所有客户端均无法连接任何节点时，大概率是机场服务器正在进行全网大规模维护或服务器 IP 遭到集中封锁，需等待服务商发布公告修复。

### Q12：为什么有时候节点全红，什么都没操作过了几个小时自己又变绿了？
**答**：常见于机场运维团队完成了机房线路的故障切换、或者本地运营商在晚高峰后解除了骨干网链路拥堵，服务器自动恢复连通。

## 一、Clash Verge Rev 核心认知与项目关系辨析

### 1. Clash Verge Rev 是什么？
Clash Verge Rev 是目前开源社区中最为主流的跨平台代理客户端图形界面（GUI）。其前端基于 Tauri/Rust 架构打造，界面轻盈优雅、内存占用低，内部默认集成了活跃维护的 **Mihomo 内核**，负责执行所有底层网络包路由与加密通信。

### 2. Clash Verge Rev 与旧版 Clash for Windows 有什么区别？

| 比较维度 | Clash Verge Rev (当前首选主力) | Clash for Windows (已于 2023 年停更) |
| :--- | :--- | :--- |
| **项目维护状态** | **开源社区持续活跃更新维护** (2026 在线维护) | **作者已彻底归档停更**，不再修复安全漏洞 |
| **底层内核架构** | 深度集成 **Mihomo (Clash.Meta) 现代内核** | 搭载旧版停更的官方 Clash Core |
| **下一代抗封锁协议** | **原生支持 Hysteria 2、TUIC v5、VLESS** | 无法解析现代高速抗封锁节点协议 |
| **软件架构与资源** | 基于 Tauri / Rust 构建，系统资源占用极低 | 基于传统 Electron 架构，内存占用相对偏高 |
| **跨平台一致性** | Windows、macOS (Intel/Apple Silicon)、Linux 体验一致 | 主要侧重 Windows，Mac 端体验脱节 |

## 四、各操作系统平台下载安装详细步骤

### 1. Windows 系统安装流程
1. 打开官方 Release 页面，下载最新稳定版的 `Clash.Verge_x.x.x_x64-setup.exe`；
2. 双击运行安装程序。若 Windows SmartScreen 弹出“Windows 已保护你的电脑”提示，点击【更多信息】并选择【仍要运行】；
3. 按照向导点击下一步直至完成安装；
4. 首次启动软件时，Windows 防火墙会弹出网络访问许可，务必同时勾选【专用网络】与【公用网络】，并点击【允许访问】。

### 2. macOS 系统安装流程
1. 根据 Mac 芯片类型下载对应的 `.dmg` 镜像（Apple Silicon 选 `aarch64`，Intel 选 `x64`）；
2. 双击打开 DMG 文件，将 **Clash Verge** 图标拖拽进入 **Applications (应用程序)** 文件夹；
3. 在应用程序列表中双击打开。若系统弹出“无法打开，因为无法验证开发者”，打开 Mac 的【系统设置】──►【隐私与安全性】，向下滚动找到拦截提示，点击【仍要打开】即可。

### 3. Linux 系统安装流程
- **AppImage 格式（推荐）**：
  ```bash
  chmod +x Clash.Verge_*.AppImage
  ./Clash.Verge_*.AppImage
  ```
- **DEB 包格式（Ubuntu / Debian）**：
  ```bash
  sudo dpkg -i clash-verge_*.deb
  sudo apt-get install -f # 自动补齐依赖
  ```

## 七、节点选择与策略组核心原理解析

完成订阅导入后，点击左侧导航栏的 **「代理 (Proxies)」** 页面即可开始选节点：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【Proxies 页面策略组运作机制】                                │
 ├──────────────────┬──────────────────────────────────────────────────────────────────────────┤
 │ 策略组类型       │ 运作机制与特征                                                           │
 ├──────────────────┼──────────────────────────────────────────────────────────────────────────┤
 │ **Select (手动选择)** | 用户点击哪个节点，流量就固定走哪个节点。最稳定可控，推荐日常使用         │
 │ **URL-Test (自动优选)**| 客户端定期向目标地址发包测速，自动将流量分发给当前延迟最低的节点         │
 │ **Fallback (故障转移)**| 默认始终走主节点，仅当主节点宕机超时后，自动平滑切入备用节点             │
 │ **Load-Balance (负载均衡)**| 将多条并发连接均匀分配至不同节点，适合高并发下载，不推荐流媒体与登录   │
 └──────────────────┴──────────────────────────────────────────────────────────────────────────┘
```

### 节点延迟（ms）的正确认知（URL-Test $\neq$ 下载速度）
在“代理”页面右上角点击 **⚡ 闪电图标** 可以发起批量延迟测试：
- **延迟显示的本质**：该数字表示客户端向特定测试网址发起 HTTP 握手并收到响应的时间（URL-Test），**不是底层 ICMP Ping 延迟**；
- **核心误区纠偏**：**30ms 的节点不一定比 120ms 的节点下载速度快！** 延迟低仅代表响应灵敏，真实下载速率取决于节点服务器分配的物理带宽与线路丢包率。

## 八、三大分流模式精准选型：Rule、Global 与 Direct

在界面的最上方，通常提供了三种全局路由模式供随时切换：

| 模式名称 | 核心路由逻辑 | 最佳适用场景 | 关键避坑提醒 |
| :--- | :--- | :--- | :--- |
| 🥇 **Rule (规则模式)** | 按域名/IP/规则集智能分流：国内网站直连，海外受限网站走代理 | 🟢 **99% 新手日常首选！** 完全不影响国内微信与百度 | 依赖规则库更新，规则漏掉的海外小众网站可能走直连 |
| 🥈 **Global (全局模式)** | 无视所有分流规则，电脑进入内核的所有流量统一发往指定海外节点 | 🟡 仅用于临时排障：测试网页打不开是否为分流规则遗漏 | ❌ 严禁长期开启！会导致国内所有 App 绕道海外大幅减速 |
| 🥉 **Direct (直连模式)** | 不经过任何海外节点，全量数据包通过本地宽带直连互联网 | ⚪ 用于在不退出客户端的情况下，临时排查本地宽带连通性 | ❌ 并不是关闭软件，内核仍在后台监听系统网络端口 |

> 详细机制可参考深度专项：[《梯子Rule、Global、Direct是什么？规则模式与全局代理区别》](/tizi/rule-global-direct/)。

## 九、System Proxy (系统代理) 与 TUN 模式选型决策

这是让电脑软件流量成功送入代理内核的关键一步：

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【流量接管两大入口深度对比】                                  │
 ├──────────────────────┬──────────────────────────────┬───────────────────────────────────────┤
 │ 对比维度             │ System Proxy (系统代理)      │ TUN 模式 (虚拟网卡)                   │
 ├──────────────────────┼──────────────────────────────┼───────────────────────────────────────┤
 │ **底层接管原理**     │ 操作系统向应用提供本地代理端口 | 在系统网络层创建虚拟网卡底层抓包      │
 │ **覆盖软件范围**     │ 浏览器、普通办公软件与合规 App | 全电脑所有软件（包括游戏、终端命令行）│
 │ **游戏与 UDP 支持**  │ 较弱，无法捕获底层裸 UDP     │ **原生完美支持全量 UDP 与游戏对局**   │
 │ **系统权限需求**     │ 无需特殊管理员权限           │ 需要安装虚拟网卡服务或管理员授权      │
 │ **局域网 NAS 影响**  │ 几乎零影响                   │ 若未开启 Bypass LAN 可能引发内网断连  │
 │ **新手推荐选型**     │ 🟢 **日常办公/追剧首选开启** | 🔵 **仅在打外服游戏或跑代码时按需开启** |
 └──────────────────────┴──────────────────────────────┴───────────────────────────────────────┘
```

### 1. 怎么开启 System Proxy？
进入客户端左侧【设置 (Settings)】──► 找到【系统代理 (System Proxy)】开关，点击打开即可。浏览器即可瞬间畅游外网。

### 2. 怎么开启 TUN 模式？
1. 进入左侧【设置】──► 找到【服务模式 (Service Mode)】，若提示未安装，点击其右侧的安装按钮并授予管理员权限；
2. 安装完成后服务模式图标变为绿色可用状态；
3. 找到【TUN 模式 (Tun Mode)】开关，点击开启即可在系统底层虚拟出 Wintun 适配器接管全量网络。

> 深度排障指南：[《梯子TUN模式是什么？虚拟网卡与应用分流说明》](/tizi/tun/) 与 [《梯子为什么有些软件不走代理？》](/tizi/app-not-using-proxy/)。

## 十、DNS、Fake-IP 与 IPv6 配置准则（新手建议保持默认）

- **看到 `198.18.x.x` 地址不要慌**：Clash Verge Rev 默认采用 [Fake-IP 模式](/tizi/fake-ip/)。在该机制下，客户端向系统返回 `198.18.0.1` 等保留虚拟 IP 属于正常现象，内核会在底层发往节点前还原为真实域名；
- **不要随意关闭 IPv6**：如果家庭宽带原生支持 IPv6 且代理运行顺畅，无需刻意禁用；仅当出现 IPv4 正常但 IPv6 网页打不开时，才参考 [《梯子IPv6与代理兼容指南》](/tizi/ipv6/) 进行针对性优化；
- **黄金准则**：新手第一次使用切忌同时修改 DNS、TUN、IPv6 和规则集，以免破坏基线环境增加排障难度。

## 十一、排错神器：Connections (实时连接) 与 Logs (日志)

遇到任何网页打不开或软件连不上时，**最专业的第一动作不是换节点，而是看连接监控**：

1. **打开「连接 (Connections)」面板**：
   - 刷新打不开的网页，查看连接列表中是否跳出了该域名的请求；
   - 查看该请求命中的 **Rule 规则名称**；
   - 查看最终分配的 **策略组 (Proxy Group)** 与 **出口节点 (Chains)**；
   - 若状态显示为 **`Direct`**，说明被分流规则误伤，需补充分流规则；若无任何连接记录，说明应用未进入代理入口。
2. **打开「日志 (Logs)」面板**：
   - 查看是否有标红的 `Timeout`、`DNS resolve failed` 或 `Connection refused` 报错，秒级捕获真实根因。

## 十二、三种更新机制深度辨析（表 3）

## 十三、正确退出软件与防止“代理残留”断网

```text
 ⚠️ 【全网最高频故障预警】：
 很多用户直接关机或通过任务管理器强制杀掉 Clash Verge Rev 进程，随后发现电脑任何网页都打不开了！
 
 根因：客户端未能在退出时将操作系统的「系统代理注册表」复原，导致系统仍顽固地将流量送往已关闭的 7890 本地端口！
 
 正确操作：
 1. 退出前在设置中手动关闭「系统代理」开关；
 2. 或在任务栏右下角托盘图标上单机右键，选择正常的【退出 (Quit)】，客户端会自动复原系统网络。
```

## 十七、常见问题解答 (FAQ)

### Q1：Clash Verge Rev 到底是什么？它安全吗？
**答**：Clash Verge Rev 是一个基于开源 Tauri/Rust 框架开发的新一代跨平台代理客户端，集成了持续维护的 Mihomo 内核。只要你从官方 GitHub Release 页面下载官方编译包，其代码完全开源透明，是目前安全性极高的主流客户端之一。

### Q2：它和以前停更的 Clash for Windows 是一回事吗？
**答**：完全不是。Clash for Windows 早在 2023 年已正式停更；Clash Verge Rev 是由全新开源社区独立重构的新项目，界面更现代、资源开销更小，且原生支持 Hysteria 2 等前沿抗封锁协议。

### Q3：为什么从 GitHub 下载时经常打不开或者速度极慢？
**答**：由于国内网络对 GitHub 资源的访问限制，网页可能偶发超时。可借助合规的加速镜像、手机热点或通过官方提供的备用发布通道完成初次安装包下载。

### Q4：为什么订阅导入成功后，代理页面却显示 0 个节点？
**答**：通常有三种原因：一是忘记鼠标左键单击该配置卡片进行激活；二是机场套餐已到期或流量耗尽导致服务端下发了空配置；三是订阅链接被本地网络拦截。

### Q5：为什么所有节点测速全部显示红色的 Timeout？
**答**：所有节点在同一瞬间全红，99% 是本地问题：请首先校准操作系统系统时间（误差超过 60 秒将导致 TLS 握手彻底失败），其次确认家庭宽带物理连通性。

### Q6：节点显示绿色且有几百毫秒延迟，为什么网页依然打不开？
**答**：延迟测试仅代表代理内核与海外服务器之间的握手通畅；网页打不开说明电脑浏览器的流量根本没有送入代理内核，请进入设置面板检查【系统代理 (System Proxy)】开关是否已正常开启。

### Q7：什么是 TUN 模式？我平时看网页需要开它吗？
**答**：平时看网页和追剧**完全不需要开启 TUN 模式**，普通的系统代理更加轻量省电。只有当你玩 Steam/Epic 外服联机网游、使用 Git 命令行，或遇到特定软件不理会系统代理时，才需要开启 TUN 模式。

### Q8：为什么退出 Clash Verge Rev 之后，电脑所有网页反而全部连不上网了？
**答**：这是因为非正常退出时，未自动复原操作系统的系统代理注册表设置；重新启动 Clash Verge Rev，并在左下角设置中正常点击【退出】，或手动在 Windows 设置中关闭系统代理即可秒级恢复。

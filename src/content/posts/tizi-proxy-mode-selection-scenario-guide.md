> **【💡 30 秒极速决策：梯子模式到底应该怎么选？】**
> - **核心决策法则**：选模式千万不要单选一个词，必须拆为**两步决策**：
>   1. **第一步选“流量入口”**：`System Proxy (系统代理)` 还是 `TUN (虚拟网卡)`？
>   2. **第二步选“路由策略”**：`Rule (规则分流)`、`Global (全局代理)` 还是 `Direct (直连)`？
> - **典型场景黄金推荐组合**：
>   - 🟢 **普通网页 / 办公 / 看视频 (90% 用户首选)**：`System Proxy + Rule`（最省电、最稳定、完全不影响微信与百度）；
>   - 🔵 **外服网游 / 开发者终端 / 多软件混用**：`TUN + Rule`（全系统应用级抓包，同时保持国内直连）；
>   - 🟡 **特定网站打不开排障对照**：临时切换为 `Global` 验证是否为规则误判；
>   - ⚪ **排查本地网络与宽带连通性**：临时切换为 `Direct`。

## 核心架构速查：代理模式“入口层 + 策略层”二维决策矩阵

```text
 ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
 │                               【代理模式二维决策全景矩阵】                                  │
 ├──────────────────────────────────────────────┬──────────────────────────────────────────────┤
 │ 🚪 流量入口层 (Ingress: 流量怎么进 Core)      │ 🧭 路由策略层 (Egress: 进入 Core 后怎么走)    │
 ├──────────────────────────────────────────────┼──────────────────────────────────────────────┤
 │ - **System Proxy (系统代理)**                │ - **Rule (规则模式)**：智能分流（国内直连/国外代理）│
 │   轻量省电，仅接管支持系统代理的浏览器与 App   │ - **Global (全局模式)**：所有请求强制走指定海外代理  │
 │ - **TUN 模式 (虚拟网卡)**                    │ - **Direct (直连模式)**：绕过海外节点，全量本地直连  │
 │   底层网卡抓包，接管游戏/UDP/终端所有流量    │                                              │
 └──────────────────────────────────────────────┴──────────────────────────────────────────────┘
```

## 一、五大核心概念速查总表

| 模式 / 概念名称 | 属于哪个层级 | 核心工作机制 | 核心解决什么问题 | 关键认知误区纠偏 |
| :--- | :--- | :--- | :--- | :--- |
| **System Proxy (系统代理)** | 流量入口层 | 操作系统向支持的应用提供本地 HTTP/SOCKS 代理端口 | 浏览器与普通办公 App 轻量翻墙 | ❌ 并不是全系统所有软件都会走代理 |
| **TUN 模式 (虚拟网卡)** | 流量入口层 | 在操作系统网络层创建虚拟网卡，全量捕获 TCP/UDP 数据包 | 游戏、Git 终端及不支持代理的软件强制接管 | ❌ 并不是开 TUN 就会让所有网站变卡 |
| **Rule (规则模式)** | 路由策略层 | 按域名/IP/规则集智能识别：国内直连、国外代理 | 日常上网免切节点，不消耗多余套餐流量 | ❌ 并不是自动测速选择最快节点 |
| **Global (全局模式)** | 路由策略层 | 无视分流规则，将进入内核的所有流量统一发往指定节点 | 排查分流规则失效、特定单地区访问验证 | ❌ 并不是全球节点加速，国内网站也会变慢 |
| **Direct (直连模式)** | 路由策略层 | 不经过任何海外代理节点，全部走本地物理宽带直连 | 测试目标网站在本地宽带下的原生连通性 | ❌ 并不是退出代理客户端，内核仍在监听 |

## 三、七大核心使用场景精准选型指南

不同应用场景对底层网络协议的需求截然不同，请对照以下场景决策指南：

| 核心应用场景 | 推荐模式组合 | 核心决策理由 | 关键注意事项与避坑指南 |
| :--- | :--- | :--- | :--- |
| 🌐 **网页浏览与日常办公** | `System Proxy + Rule` | Chrome/Edge 完美支持系统代理，国内网站秒开 | 保持默认即可，无需开启复杂的 TUN 虚拟网卡 |
| 🎮 **外服 Steam / 网游联机** | `TUN + Rule` | 游戏大量使用底层裸 UDP 套接字，系统代理无法捕获 | 开启 TUN 模式，并在规则中将游戏进程设为代理 |
| 💻 **程序员终端 (Git/npm/pip)** | `TUN + Rule` 或配置环境变量 | 终端命令行默认不读取桌面系统代理设置 | 开启 TUN 可免去逐个配置 `HTTP_PROXY` 的繁琐 |
| 🤖 **AI 工具 (ChatGPT/Claude)** | `System Proxy + Rule` | 网页端只需标准代理，重点在于**出口节点机房质量** | 选用住宅/原生节点，避免频繁切换不同国家出口 |
| 🎬 **流媒体 (YouTube/Netflix)** | `System Proxy + Rule` | 视频加载依赖节点带宽，规则模式可避免浪费国内流量 | 4K 播放只需选带宽大的节点，无需全局模式 |
| 📁 **局域网 NAS / 打印机** | `System Proxy + Rule` | 确保私有网段（`192.168.x.x`）处于 [Direct 直连](/tizi/lan-tun-conflict/) | 若开 TUN 必须开启【Bypass LAN】避免内网断连 |
| 📥 **BT / P2P 大文件下载** | 临时切为 `Direct` 或分流直连 | P2P 下载极其消耗节点带宽，且很多机场节点禁用 BT | 避免被机场服务商按违规封禁套餐 |

## 四、为什么“不建议长期无脑开启 Global 模式”？

很多新手误以为 Global 模式是“最彻底、最快速”的翻墙方式，实则存在诸多隐患：

```text
 1. 【国内 App 严重减速】：
    - 打开微信、淘宝、百度、Bilibili 时，所有数据包全部绕道海外节点再折返回国，延迟从 10ms 飙升至 200ms+；

 2. 【套餐流量迅速耗尽】：
    - 电脑后台的系统更新、国内网盘下载、本地视频缓存均会扣除宝贵的海外机场高速流量；

 3. 【局域网与内网服务断连】：
    - 路由器后台（192.168.1.1）、NAS 文件共享（SMB）可能被错误发往海外服务器，导致内网设备彻底失联。
```


## 六、关于代理模式选择的 15 大核心认知误区

```text
 ❌ 误区 1：TUN 模式比 System Proxy 更高级，所以平时应该无脑一直开着 TUN。(错！无特殊需求无需增加网卡驱动开销)
 ❌ 误区 2：Global 模式就是“全球节点智能加速”，能让所有网站网速翻倍。(错！Global 只是强行无视规则走单一节点)
 ❌ 误区 3：玩外服游戏只要开启了 Rule 规则模式就一定能加速。(错！游戏必须配合 TUN 模式才能接管 UDP 流量)
 ❌ 误区 4：Direct 直连模式就是把电脑上的梯子软件彻底关闭了。(错！客户端仍在后台运行监听，只是流量不走节点)
 ❌ 误区 5：使用 ChatGPT 必须强制开启 Global 模式才能登录。(错！只需分流规则将 OpenAI 域名分流至支持地区即可)
 ❌ 误区 6：开着 TUN 模式就绝对 100% 不可能访问到局域网 NAS 了。(错！只要配置了 Bypass LAN 即可完美共存)
 ❌ 误区 7：在手机上需要像电脑一样纠结要不要安装 TUN 驱动。(错！手机端通过系统 VPN 接口天然实现了全量接管)
 ❌ 误区 8：只要把模式切换成 Global，就能突破 Netflix 的版权地区限制。(错！流媒体解锁取决于节点的 IP 属性与机房)
 ❌ 误区 9：Rule 模式里的 Auto 策略组会自动帮我选择全网下载速度最快的节点。(错！URL-Test 仅测试首次延迟 Ping)
 ❌ 误区 10：为了防止 IP 泄漏，必须把电脑上的 IPv6 彻底永久禁用。(错！在客户端正确开启 IPv6 路由接管即可)
 ❌ 误区 11：命令行工具（Git/curl）只要开启了 System Proxy 就会自动走代理。(错！命令行工具需开启 TUN 或配置变量)
 ❌ 误区 12：在公司电脑上开启 TUN 模式可以神不知鬼不觉地绕过企业监控。(错！企业防火墙与网关依然能记录底层流量)
 ❌ 误区 13：所有的代理客户端在不同操作系统上的默认模式都完全一样。(错！Windows、macOS 与移动端机制各异)
 ❌ 误区 14：只要把所有规则全部写成 Direct，电脑就会自动翻墙。(错！Direct 代表直连本地，完全不使用代理)
 ❌ 误区 15：遇到任何网络报错，只要频繁在几个模式之间切来切去就能自动修好。(错！盲目切换会导致路由表混乱)
```

## 七、常见问题解答 (FAQ)

### Q1：新手第一次用梯子，到底应该选择哪种模式？
**答**：强烈推荐选择 **`System Proxy (系统代理) + Rule (规则模式)`**。这是最省心、最稳定且最省流量的黄金组合，国内网站自动直连不降速，国外受限网站自动走代理。

### Q2：System Proxy 和 TUN 模式到底有什么区别？
**答**：System Proxy 仅向系统提供一个本地代理端口，只有主动读取系统代理的软件（如浏览器）才会走代理；TUN 模式是在系统底层虚拟出一块网卡，将全电脑所有软件（包括游戏、命令行）的数据包全量强制捕获。

### Q3：为什么说“平时上网不建议一直开着 Global 模式”？
**答**：因为 Global 模式会无视规则让所有流量绕道海外。访问国内的微信、淘宝、百度时会经历漫长的跨国传输，不仅速度大幅变慢，还会极速消耗你的机场套餐流量。

### Q4：玩 Steam、Epic 外服游戏时，应该选什么模式？
**答**：推荐选择 **`TUN 模式 + Rule 模式`**。游戏联机使用底层裸 UDP 协议，必须依靠 TUN 虚拟网卡才能成功送入代理；配合 Rule 模式可确保游戏更新走国内直连、游戏对局走低延迟海外节点。

### Q5：为什么我的 Git 命令行在开着系统代理时依然连不上 GitHub？
**答**：因为终端命令行程序出于跨平台设计，默认不读取 Windows/macOS 的桌面系统代理。开启客户端的 [TUN 模式](/tizi/tun/) 或在终端运行 `$env:http_proxy="http://127.0.0.1:7890"` 即可解决。

### Q6：使用 ChatGPT / Claude 这类 AI 工具，需要开 Global 吗？
**答**：完全不需要。只需保持 `Rule 模式`，并在客户端节点列表中手动选择一个支持 AI 服务的国家（如美国、日本、新加坡）即可正常使用。

### Q7：什么是 Direct 模式？它在什么时候有用？
**答**：Direct 模式让所有流量全部绕过海外代理节点、直接使用你的本地宽带连接目标。它主要用于快速测试某个网站在本地直连网络下的真实连通性。

### Q8：开启 TUN 模式后，电脑为什么打不开局域网 NAS 和打印机了？
**答**：这是因为 TUN 虚拟网卡错误接管了私有 IP 段。在客户端设置中勾选【Bypass LAN (绕过局域网)】，并在规则中置顶局域网 Direct 规则即可彻底恢复。

### Q9：看 YouTube 4K 视频应该选什么模式？
**答**：选用 **`System Proxy + Rule`** 即可。视频流畅度取决于你所选节点的带宽与物理延迟，只要在策略组中选中高速节点即可，完全没必要开 Global。

### Q10：在手机（iPhone / Android）上，模式选择有什么不同吗？
**答**：手机端代理客户端（如 Shadowrocket / sing-box）通过系统 VPN 框架运行，相当于默认具备了类似电脑端 TUN 的全量接管能力；手机端只需保持【配置 / 规则模式 (Rule)】即可。

### Q11：什么时候才真正需要用到 Global 模式？
**答**：主要用于**排障对照**：当你访问某个冷门海外网站打不开、怀疑是分流规则库遗漏了该域名时，临时切为 Global；若 Global 能打开，说明只需补充一条规则即可。

### Q12：为什么不能同时开启两个不同软件的 TUN 模式？
**答**：因为两款软件会在操作系统底层同时创建虚拟网卡并争抢默认网关路由表，导致严重的路由死锁与底层网络瘫痪。

> - **第一核心定性**：**“浏览器能翻墙，但特定软件打不开”100% 证实你的节点与客户端内核 (Core) 完好无损！** 遇到问题切忌盲目换节点；
> - **三大高频根因极速对号入座**：
>   1. **浏览器正常，但 Git / Steam / 终端命令依然连不上外网** ──► 该应用根本不读取操作系统的桌面代理设置，需配置应用内代理或开启 [TUN 模式](/clash-verge-rev/tun/)；
>   2. **打开连接 (Connections) 面板能看到该软件请求，但状态显示为 `Direct`** ──► 请求已进内核，但被分流规则误判为了国内直连 ──► 转入 [Rule失效排查](/tizi/rule-mode-not-working/)；
>   3. **退出 Clash Verge Rev 之后整台电脑突然断网没网** ──► 遭遇了“系统代理残留 (Proxy Residual)”，操作系统仍顽固指向已关闭的 7890 端口。

## 一、五大典型故障分类与第一排查方向速查总表

| 故障现象分类 | 底层真实技术含义 | 最核心诱发诱因 | 第一步标准应对动作 |
| :--- | :--- | :--- | :--- |
| **A：System Proxy 开关完全没反应** | 客户端未能成功修改操作系统的代理注册表 | 杀毒软件锁定网络设置、缺少管理员权限 | 检查 Windows 系统代理设置面板是否被勾选 |
| **B：浏览器秒开，但特定软件直连** | 目标应用网络栈不主动读取桌面系统代理 | 游戏使用裸 UDP 套接字，CLI 依赖环境变量 | 为该软件单独配置代理，或开启 [TUN 模式](/clash-verge-rev/tun/) |
| **C：连接面板显示请求，但状态为 Direct** | 流量已成功进内核，但路由策略决定直连 | 分流规则缺失，或被国内白名单规则抢先命中 | 在自定义规则中将该软件域名/IP 置顶为代理 |
| **D：连接面板显示 Proxy，但依然打不开** | 流量接管与规则均正常，出口网络受阻 | 策略组选到了超时节点，或遭遇网站 IP 封锁 | 在策略组中手动换一个延迟绿色的可用节点 |
| **E：退出客户端后整台电脑网页全打不开** | 典型的“系统代理残留 (Proxy Residual)” | 客户端异常崩溃或强杀，未自动复原系统代理 | 重新打开客户端正常退出，或在系统关闭代理 |

## 三、为什么浏览器能翻墙，而其他桌面软件完全不走代理？

初学者最困惑的问题：“既然系统代理叫‘系统’代理，为什么不能代理全系统所有软件？”

```text
 1. 【系统代理本质上只是“建议性设置”而非“强制抓包”】：
    - Windows/macOS 的系统代理（System Proxy）本质上只是系统设置里的一个公用登记处（告诉大家：本机 7890 端口有代理可用）；
    - 应用程序在联网时，有权选择“听从系统建议”，也有权选择“完全不予理睬直接连网”；
    - 只有 Chrome、Edge、Safari 等主流浏览器和标准办公软件会主动读取该设置。

 2. 【哪些常见软件天生不理会系统代理？】：
    - **外服联机游戏**：Steam、Epic、战网、各大网游，大量使用底层裸 UDP 套接字，根本无法通过 HTTP/SOCKS 系统代理中转；
    - **开发命令行工具**：Git、curl、npm、pnpm、pip、Docker，出于跨平台设计，默认完全无视 Windows/Mac 桌面代理；
    - **部分即时通讯与流媒体**：Telegram、Spotify 等，需在软件内部手动设置代理，或依赖虚拟网卡接管。
```

## 四、开发命令行工具（Git / curl / npm / pip）免开 TUN 代理配置指南

如果不想因为一两个命令就大动干戈开启 TUN 虚拟网卡，可直接通过官方支持的环境变量或命令实现秒级代理：

### 1. 终端通用临时环境变量（推荐日常使用）
在 PowerShell 或 CMD 中运行以下命令，**当前终端窗口内的所有后续命令将自动走代理**（关闭窗口后自动失效）：
```powershell
# PowerShell 环境
$env:http_proxy="http://127.0.0.1:7890"
$env:https_proxy="http://127.0.0.1:7890"

# CMD 环境
set http_proxy=http://127.0.0.1:7890
set https_proxy=http://127.0.0.1:7890
```

### 2. 各常用命令行工具官方永久配置
| 常用开发工具 | 官方标准配置命令 | 官方标准取消配置命令 |
| :--- | :--- | :--- |
| **Git 命令行** | `git config --global http.proxy http://127.0.0.1:7890` | `git config --global --unset http.proxy` |
| **npm 包管理器**| `npm config set proxy http://127.0.0.1:7890` | `npm config delete proxy` |
| **pnpm 包管理** | `pnpm config set proxy http://127.0.0.1:7890` | `pnpm config delete proxy` |
| **Python pip**  | `pip install 模块名 --proxy http://127.0.0.1:7890` | 单次生效，无需额外取消 |

> 📌 **注**：以上命令中的 `7890` 请替换为您在 Clash Verge Rev 设置中看到的实际【Mixed Port (混合端口)】。

```text
 └─────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 六、杀毒软件与多客户端冲突：为什么 System Proxy 开启了却没写入？

有时候在 Clash Verge Rev 界面里把系统代理开关点绿了，但实际系统代理根本没打开：

```text
 1. 【安全卫士与杀毒软件恶意拦截】：
    - 某些国产杀毒软件或网络防火墙将“修改系统代理”判定为木马劫持行为，并在后台静默恢复注册表；
    - 表现：你在客户端里刚打开系统代理，几秒后开关自动变灰，或者系统设置里代理始终是空的；
    - 解决：在杀毒软件中将 Clash Verge Rev 添加进信任白名单，放行其修改系统代理的权限。

 2. 【多个代理客户端互相打架】：
    - 电脑后台同时运行着 v2rayN、旧版 CFW、浏览器代理扩展（如 SwitchyOmega）或公司内网 VPN；
    - 多个程序同时争抢操作系统的代理设置，导致注册表被反复覆盖引发死锁；
    - 解决：彻底退出后台其他代理工具与冲突插件，只保留单一客户端运行。
```

## 七、System Proxy 不生效 5 分钟极速排障 SOP（标准 HowTo）

遇到系统代理异常、浏览器能用但某些软件连不上时，按以下 6 步标准顺序排错：

```text
 Step 1: 验证系统设置写入 ──► 打开 Windows/Mac 系统代理设置，确认代理 IP 指向 127.0.0.1 且端口一致
    ↓
 Step 2: 监控 Connections 请求 ──► 打开客户端连接面板，触发故障软件，观察是否有请求数据包出现
    ↓
 Step 3: 若无任何连接记录 ──► 判定为应用不读取系统代理，为该软件单独配置代理参数或开启 TUN 模式
    ↓
 Step 4: 若显示为 Direct 直连 ──► 判定为规则误判，在自定义规则中为该软件目标域名追加代理分流
    ↓
 Step 5: 若显示为 Proxy 但超时 ──► 判定为出站节点受阻，在 Proxies 策略组中切换其他绿色低延迟节点
    ↓
 Step 6: 检查退出残留 ──► 电脑断网时，手动关闭操作系统代理设置中的“使用代理服务器”开关
```

## 八、关于 System Proxy 的 15 大核心认知误区

```text
 ❌ 误区 1：只要把 System Proxy 点绿，电脑里 100% 的所有软件就必须自动翻墙。(错！很多软件根本不读系统代理)
 ❌ 误区 2：System Proxy 就是 Global 全局模式。(错！System Proxy 是流量入口，策略依然按 Rule 智能分流)
 ❌ 误区 3：浏览器能正常翻墙，就绝对能证明电脑上的所有游戏都能加速。(错！游戏依赖 UDP，系统代理捕获不到)
 ❌ 误区 4：一遇到软件不走代理，立刻就去把客户端卸载重装。(错！重装依然解决不了该应用不读取系统代理的本质)
 ❌ 误区 5：系统代理设置里的 127.0.0.1 是海外翻墙服务器的真实 IP。(错！127.0.0.1 代表本机，是指向本机客户端)
 ❌ 误区 6：为了让命令行走代理，必须在电脑里永久开启 TUN 虚拟网卡。(错！配置简单的终端环境变量更为轻量可控)
 ❌ 误区 7：退出梯子后电脑打不开网页，一定是电脑的主板或网卡物理损坏了。(错！99% 是未清理残留的本地系统代理)
 ❌ 误区 8：只要把所有规则全部删光，软件不走代理的问题就会自动消失。(错！删除规则只会让所有分流功能瘫痪)
 ❌ 误区 9：同时运行两个翻墙软件并同时开启系统代理能实现双倍网速。(错！两者反复覆写系统代理会导致严重冲突断网)
 ❌ 误区 10：在公司电脑上开启系统代理可以神不知鬼不觉规避企业网关监管。(错！企业内网具备严格的合规审计)
 ❌ 误区 11：在手机上也会经常发生类似电脑的系统代理残留断网问题。(错！手机端通过系统 VPN 框架管理，退出即释放)
 ❌ 误区 12：遇到软件连不上，盲目在几十个节点之间秒级切换。(错！若流量压根没进客户端，换一万个节点也没用)
 ❌ 误区 13：为了排查系统代理不生效，听信网上谣言直接永久关闭防火墙。(错！防火墙不会阻止正常的本地代理端口通信)
 ❌ 误区 14：看到网页提示连接被拒绝，立刻去修改系统 hosts 文件。(错！盲目修改 hosts 会破坏域名解析基线)
 ❌ 误区 15：Firefox 浏览器的网络行为和 Chrome/Edge 绝对完全一模一样。(错！Firefox 具备完全独立的网络代理设置)
```

## 九、常见问题解答 (FAQ)

### Q1：为什么开启了 System Proxy，但 Steam 游戏和 Git 命令行依然连不上？
**答**：因为外服游戏（使用底层裸 UDP）和开发命令行程序（出于跨平台设计）默认不主动读取 Windows/macOS 的桌面系统代理设置。需在终端配置 `HTTP_PROXY` 环境变量，或在客户端中开启 [TUN 虚拟网卡模式](/clash-verge-rev/tun/) 强制接管。

### Q2：怎么在客户端里确认某个软件到底有没有走代理？
**答**：打开 Clash Verge Rev 左侧的【连接 (Connections)】实时监控面板，重新操作该软件。若列表中出现该软件进程的连接行，且显示目标策略组名称，说明已成功走代理；若完全没有该软件的记录，说明它未进入代理。

### Q3：为什么关闭 Clash Verge Rev 后，电脑上的所有网页全部打不开了？
**答**：这是经典的“系统代理残留”：软件异常退出时未自动清除系统的代理设置，导致系统仍把流量发往已关闭的 7890 端口。重新打开软件正常点击【退出】，或在 Windows【网络设置】──►【代理】中手动关闭“使用代理服务器”即可秒级恢复。

### Q4：在客户端里把系统代理开关点亮了，但实际系统设置里依然显示关闭？
**答**：通常是因为杀毒软件（如 360、火绒或某些安全卫士）锁定了系统网络配置注册表，阻止外部程序修改代理。将 Clash Verge Rev 加入杀毒软件的白名单信任列表，或右键以管理员身份运行客户端即可解决。

### Q5：为什么 Chrome 浏览器能正常翻墙，但 Firefox 却报错打不开？
**答**：因为 Firefox 拥有完全独立的代理设置模块。进入 Firefox 的【设置】──► 滚动到底部找到【网络设置】──► 勾选【使用系统代理设置】即可与 Chrome 保持一致。

### Q6：System Proxy 和 TUN 模式到底应该选哪一个？
**答**：平时上网、看 YouTube 视频或日常办公，**首选 System Proxy**，开销最小且稳定；只有当你玩外服网游、运行 Docker/Git，或遇到某些软件死活不遵循系统代理时，才建议开启 TUN 模式。

### Q7：开着系统代理时，访问国内的百度和微信会变慢吗？
**答**：只要你的客户端模式保持为 **`Rule (规则模式)`**，国内网站在进入客户端后会被分流规则自动识别为 Direct 直连，完全走你的本地原生物理宽带，速度与平常完全一致，绝不会绕道海外。

### Q8：怎么给 Git 命令行一键配置走 Clash 代理？
**答**：在终端运行：`git config --global http.proxy http://127.0.0.1:7890` 即可；若不需要走代理时，运行 `git config --global --unset http.proxy` 即可一键取消。

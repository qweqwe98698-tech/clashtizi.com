## 一、为什么"免费节点"在协议层就是高危资产

先把结论钉在协议栈上：一个公共免费节点的风险不在"速度慢"，而在于**你无法验证链路两端之外还有谁在监听**。抓包视角下，免费节点的典型拓扑是这样的：

```
[你的终端] --TLS--> [聚合爬虫节点/家宽反代] --明文HTTP/裸TCP--> [上游中转] --> [落地]
                          ↑
                    运营者在此处可完整解密
```

绝大多数免费节点由爬虫脚本批量抓取公开订阅、或由个人用 VPS 自建后公开分享。问题出在中间那一跳：节点服务端持有你的 TLS 会话终结权。当客户端与服务端完成 TLS 握手后，服务端是明文的——它能看到你访问的完整域名（SNI）、HTTP Host、甚至在你未强制 HTTPS 时看到请求体。更恶劣的做法是**主动降级**：对 `example.com` 返回一个自签证书诱导你点"继续访问"，或对特定域名做 DNS 污染返回钓鱼 IP。

### 1.1 TLS 指纹与 SNI 嗅探的微观机制

TLS 握手第一个包 ClientHello 里携带 SNI 扩展（明文），中间设备据此判断目标域名。免费节点运营者若与某些"数据合作方"勾连，SNI 列表本身就是一份高价值的用户画像数据。同时，客户端的 JA3/JA4 指纹（由 TLS 版本、加密套件顺序、扩展列表哈希而成）会暴露你用的是 Clash、Sing-box 还是原生浏览器——这既是 GFW 主动探测的依据，也是节点方做用户分层的依据。

用 `tcpdump` 抓一次握手就能看清：

```bash
# 抓取 443 端口的 ClientHello，观察 SNI 明文
tcpdump -i any -A 'tcp port 443 and tcp[((tcp[12] & 0xf0) >> 2)] = 0x16' -c 20
```

输出里 `\x00\x00` 后紧跟的域名就是 SNI。若你的客户端未启用 ECH（Encrypted Client Hello）或未做 TLS 分片，这个字段在链路上裸奔。

### 1.2 中间人劫持的三种落地形态

| 形态 | 技术手段 | 用户可感知症状 |
|---|---|---|
| 证书替换 | 服务端下发自签/伪造 CA 证书 | 浏览器"证书不受信任"警告 |
| DNS 劫持 | 节点侧 DNS 返回污染 IP | 访问正常站点跳到广告/钓鱼页 |
| 流量镜像 | 服务端 `tcpdump` 落盘后离线分析 | 无感知，事后账号被盗 |

第三种最危险，因为它零症状。免费节点运营者在服务端跑一条 `tcpdump -w /data/$(date).pcap 'tcp port 80'`，所有走 HTTP 的明文请求（含部分 App 的内嵌 WebView 登录）全部落盘。这就是为什么安全基线要求：**任何不可信链路上一律强制 HTTPS + HSTS，且绝不在此类节点上登录网银、邮箱主账号**。

### 1.3 免费节点的 DNS 泄漏放大效应

免费节点常配 `8.8.8.8` 这类公共 DNS 且不做加密，你的 DNS 查询在本地 ISP 侧完全可见。用 `dig +trace` 或在线 DNSLeakTest 可验证。泄漏意味着：即便流量走了代理，你访问了哪些域名依然被本地运营商记录。付费专线机场的标准做法是节点侧内置 DoH/DoT 并强制劫持 53 端口，这一点在第六节的客户端调优里会给出具体配置。

## 二、IEPL/IPLC 专线到底"专"在哪：物理层与拥塞控制的差异

公网中转与专线中转的核心差异不在"加密强度"（两者都可以是 VLESS+TLS），而在**跨境那一段走的是不是运营商内网**。

```
公网 BGP 中转（免费/低价机场常见）：
[终端] -> [国内入口] -> [公网国际出口] -> [GFW 检测点] -> [海外公网] -> [落地]
                          ↑ 拥塞、丢包、被 QoS 限速

IEPL 物理专线（付费专线机场）：
[终端] -> [国内多线BGP入口] -> [物理IEPL内网隧道(0丢包不过GFW)] -> [香港/日本原生机房落地出口]
                                        ↑ 运营商点对点专线，独立带宽
```

IEPL（International Ethernet Private Line）是运营商提供的二层点对点专线，物理上与企业内网同级，**不经过公网国际出口的拥塞队列，也不进入 GFW 的检测路径**。这带来两个可量化收益：

**其一，抖动（jitter）差异。** 公网中转在晚高峰（20:00–23:00）因国际出口带宽争抢，RTT 抖动可达 40–120ms，表现为视频缓冲、SSH 卡顿。IEPL 专线抖动通常 < 5ms。用 `mtr` 对比一目了然：

```bash
# 观察跨境段每一跳的丢包与抖动
mtr -rwzbc 100 目标落地IP
```

公网线路会在国际出口跳出现 5%~20% 丢包，专线线路全程 0%。

**其二，拥塞控制算法的实际表现。** 跨境长肥管道（Long Fat Network，BDP 大）上，Cubic 在丢包后窗口收缩激进，恢复慢；BBR 基于带宽时延积建模，抗丢包能力强。专线机场普遍在落地机开启 BBR，这是"同样带宽专线更快"的底层原因之一。落地机内核参数基线：

```bash
# /etc/sysctl.d/99-network-tuning.conf
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
net.core.rmem_max = 67108864
net.core.wmem_max = 67108864
net.ipv4.tcp_rmem = 4096 87380 33554432
net.ipv4.tcp_wmem = 4096 65536 33554432
net.ipv4.tcp_mtu_probing = 1
net.ipv4.tcp_fastopen = 3
```

`tcp_mtu_probing=1` 专门解决 MTU/MSS 分片黑洞——跨境隧道封装（如 VLESS over TLS over TCP）会额外吃掉 40~60 字节头部，若路径 MTU 探测失败，大包被静默丢弃，表现为"能打开网页但传大文件卡死"。这是免费节点最常见的隐形故障之一。

**其三，UDP QoS 限速。** 公网中转对 UDP（QUIC、游戏、语音）常做 QoS 降级甚至直接丢包，因为 UDP 无拥塞控制、易被滥用。IEPL 专线内网对 UDP 一视同仁，这是外服游戏和视频会议在专线上体验断层的直接原因。

## 五、全平台客户端调优实战

无论选哪家专线，客户端配置不当都会把专线的优势吃掉。以下按平台给出关键动作。

### 5.1 Windows / macOS：Clash Verge Rev

1. 从官网下载 Clash Verge Rev，导入订阅链接（机场后台复制 Clash 订阅）。
2. **开启 TUN 模式**：设置 → TUN 模式 → 打开。TUN 虚拟网卡接管全部流量，解决部分 App 不走系统代理的问题（尤其是游戏和部分 Electron 应用）。
3. **DNS 防污染**：设置 → DNS → 开启 `DNS Over HTTPS`，填入 `https://1.1.1.1/dns-query` 或 `https://dns.google/dns-query`；开启 `Fake-IP` 模式加速解析并防泄漏。
4. **规则模式**：日常用"规则"模式，需要全量代理时切"全局"，排障时先切全局确认节点本身通不通。

Windows 若用 v2rayN，可参考站内 [v2rayN Windows 客户端配置与排障完整教程](/v2rayn/)。

### 5.2 iOS：Shadowrocket 小火箭

1. App Store 外区账号购买下载，扫码或粘贴订阅链接导入。
2. 全局路由选"配置"（规则分流），需要时切"代理"。
3. **DNS 设置**：设置 → DNS → 覆盖为 `https://1.1.1.1/dns-query`，防止本地 DNS 泄漏。
4. 开启"始终开启 VPN"避免断连回落到直连泄漏真实 IP。

详细分流规则见 [Shadowrocket 小火箭 iOS 安装与分流教程](/shadowrocket/)。

### 5.3 Android：Sing-box / v2rayNG

Sing-box 是当前协议兼容性最好的客户端，配置示例与路由规则见站内 [Sing-box 全能通用配置与路由规则教程](/tutorials/sing-box-config/)。关键点：

- 开启 TUN 入站（`"auto_route": true`），接管全流量。
- DNS 配置 `"strategy": "prefer_ipv4"` 并启用 DoH，防污染。
- 路由规则里把国内域名/IP 走 `direct`，其余走 `proxy`，避免全局代理拖慢国内访问。

v2rayNG 用户注意：设置里开启"开启本地 DNS"并指定 DoH，关闭"允许不安全连接"。

> 新手若对上述概念陌生，先读 [科学上网新手入门使用全指南](/tizi/how-to-use/) 打底。

## 六、深度排障 FAQ

### Q1：节点全部超时变红，怎么办？

排查分支：
1. **先确认订阅是否过期/流量耗尽**——登录机场后台看剩余流量与到期日，这是最高频原因。
2. **本地网络问题**：`ping 1.1.1.1` 通不通？不通是本地断网。`curl -I https://www.baidu.com` 验证基础连通。
3. **订阅链接失效**：手动在浏览器打开订阅链接，能下载到 yaml 说明链接正常，客户端更新订阅即可。
4. **系统时间偏差**：TLS 握手依赖时间，系统时间偏差 > 5 分钟会导致证书校验失败，全节点超时。校准系统时间。
5. **端口被封**：换协议/换端口，或联系机场客服。

完整分支见 [梯子节点超时全红与连接失败排障指南](/tizi/nodes-timeout/)。

### Q2：能打开国内网站，但国外全打不开？

这是典型的"代理未生效"或"规则误判"。先切全局模式测试：全局能通说明规则分流把国外域名误判成 direct，检查规则集是否过期。全局也不通则是节点问题，回到 Q1。另检查 TUN/系统代理是否真的开启——很多用户以为开了，实际系统代理开关是关的。

### Q3：ChatGPT 报 1020 错误 / 无限人机验证？

1020 是 Cloudflare 对来源 IP 的风控拦截，本质是节点 IP 被标记为数据中心/滥用 IP。解决路径：换到原生 IP 落地节点（光速云、无忧链接的原生解锁节点专治此症），或换非香港节点（部分地区风控更严）。免费节点几乎必然触发 1020，因为共享 IP 早被拉黑。

### Q4：DNS 泄漏怎么自查与修复？

访问 DNSLeakTest 类站点，若显示的 DNS 服务器是你本地 ISP 而非节点侧，即为泄漏。修复：客户端内强制 DoH/DoT 并劫持 53 端口；Clash 系开启 Fake-IP；确认 TUN 模式下 DNS 走代理。修复后再测，DNS 应显示为节点侧或 DoH 提供商。

## 七、结语：把安全基线钉在协议层

免费节点的风险不是"可能慢"，而是"链路中间有人能看、能改、能存"。付费 IEPL/IPLC 专线的价值也不止于快，而在于跨境段走物理内网、不经过公网检测点，从架构上消除了中间人落点。选型上，追求原生 AI 解锁看光速云，追求低延迟游戏看星岛梦，追求大流量看唯兔云，预算敏感看飞猫云与微风网络，全终端省心看无忧链接。无论选哪家，把 TUN、DoH、强制 HTTPS 这三条基线做扎实，才是真正的隐私防线。更多横向数据见 [2026 翻墙机场推荐与专线节点排行榜速查](/recommend/airport/)。

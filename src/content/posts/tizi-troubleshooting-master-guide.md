## 二、节点与订阅类故障分诊（不可上网的首要原因）

```text
 1. 【节点全部标红 Timeout】：
    - 快速判断：如果所有节点在同一秒全部超时，99% 是本地物理断网、系统时间误差超过 60 秒（导致 TLS 握手校验失败），或者机场订阅已欠费到期；
    - 专项指南：参考 [《梯子节点全部超时怎么办？》](/tizi/nodes-timeout/)。

 2. 【订阅更新失败】：
    - 快速判断：如果旧节点依然能用，但点击“更新订阅”报错，说明订阅托管服务器被本地网络阻断；临时开启代理或在浏览器中下载配置文件本地导入即可；
    - 专项指南：参考 [《梯子订阅更新失败怎么办？》](/tizi/subscription-update-failed/)。
```

## 三、流量入口类故障分诊（System Proxy 与 TUN 模式）

```text
 1. 【开启系统代理后没有任何效果】：
    - 快速判断：检查 Windows/macOS 系统的“网络和代理设置”，确认代理开关是否真正被写入；某些杀毒软件会强行锁定系统注册表禁止修改代理；
    - 机制详解：参考 [《梯子System Proxy是什么？系统代理与浏览器代理说明》](/tizi/system-proxy/)。

 2. 【开启 TUN 模式后电脑直接断网】：
    - 快速判断：TUN 虚拟网卡驱动未正确配置默认路由，或者本机的防火墙拦截了 Wintun 适配器的数据包；重启客户端或重新安装 TUN 驱动即可；
    - 机制详解：参考 [《梯子TUN模式是什么？虚拟网卡与全局代理说明》](/tizi/tun/)。
```

## 四、DNS 与域名解析类故障分诊（看到 198.18 与打不开网页）

```text
 1. 【提示 NXDOMAIN 或 Could not resolve host】：
    - 快速判断：优先检查客户端设置中的【Bootstrap DNS (引导 DNS)】是否配置了可用的国内明文地址（如 `223.5.5.5`），避免 DoH 陷入无法解析自身的死锁；
    - 专项指南：参考 [《梯子DNS解析失败怎么办？NXDOMAIN与DoH排查》](/tizi/dns-resolution-failed/)。

 2. 【ping 域名返回 198.18.x.x 虚拟地址】：
    - 快速判断：这是 [Fake-IP 模式](/tizi/fake-ip/) 的底层标准设计，绝非电脑中毒或 DNS 报错；只要网页能打开，无需进行任何干预。
```

## 五、分流规则与策略组类故障分诊（Global 能用 Rule 不能用）

```text
 1. 【Global 模式秒开，切回 Rule 模式打不开】：
    - 快速判断：100% 排除节点故障。进入【连接 (Connections)】监控面板，刷新网页看请求是否被 `GEOIP,CN` 或 `GEOSITE,cn` 误判定为了 Direct 直连；
    - 专项指南：参考 [《梯子规则模式失效怎么办？Global能用Rule不能用排查》](/tizi/rule-mode-not-working/)。

 2. 【策略组选错节点导致断网】：
    - 快速判断：URL-Test 延迟测试只会测量初次握手时间，极易误选丢包率高但 Ping 低的故障节点；在策略组中改用手动 `Select` 固定节点即可。
```

## 六、局域网、NAS 与多设备发现类故障分诊

```text
 1. 【开启梯子后 192.168.1.1 路由器后台打不开】：
    - 快速判断：TUN 虚拟网卡错误劫持了私有 IP 段。在客户端设置中勾选【Bypass LAN】并将私网网段置顶 Direct 直连；
    - 专项指南：参考 [《梯子局域网为什么打不开？NAS与TUN冲突排查》](/tizi/lan-tun-conflict/)。

 2. 【Allow LAN 与 Bypass LAN 致命误区】：
    - 核心真相：`Allow LAN` 是让别的设备连接你，`Bypass LAN` 才是让你的电脑正常访问 NAS，两者完全相反。
```

## 七、通用 5 分钟极速排障标准流程（SOP / HowTo）

遇到任何梯子网络故障时，切忌慌乱改动几十个参数，请严格按以下 6 步标准顺序排查：

```text
 Step 1: 判定物理网络状态 ──► 退出梯子软件，测试本地宽带是否能正常打开国内网页（排除欠费与断网）
    ↓
 Step 2: 验证海外节点通道 ──► 开启客户端并切为 [Global 全局模式](/tizi/rule-global-direct/)，测试能否打开 Google（区分节点问题与规则问题）
    ↓
 Step 3: 查看实时连接日志 ──► 打开客户端【连接 (Connections)】监控，观察故障请求是否进入 Core、显示 Direct 还是 Proxy
    ↓
 Step 4: 检查流量接管入口 ──► 浏览器正常但 App 异常时，开启 [TUN 模式](/tizi/tun/)；局域网打不开时开启 Bypass LAN
    ↓
 Step 5: 刷新系统与软件缓存 ──► 在终端运行 `ipconfig /flushdns` 并点击客户端内的【清空 Fake-IP 缓存】
    ↓
 Step 6: 单一变量还原对比 ──► 若依然异常，切换手机热点测试（排除运营商本地 QoS 与路由器策略）
```

## 八、关于梯子故障排查的 20 大核心认知误区

```text
 ❌ 误区 1：只要网页打不开，第一反应立刻把客户端卸载重装。(错！重装只会丢失配置，99% 是节点或规则问题)
 ❌ 误区 2：节点测速全红就代表买的机场彻底跑路了。(错！多为本地系统时间不同步或家庭宽带突发断网)
 ❌ 误区 3：节点测速延迟显示绿色数字，就代表电脑上的所有软件都能上网了。(错！测速仅代表内核到节点通畅)
 ❌ 误区 4：平时上网应该永远无脑开着 Global 全局模式。(错！Global 会让国内微信淘宝全绕远变卡且极耗流量)
 ❌ 误区 5：遇到网络打不开，直接把电脑防火墙和杀毒软件彻底卸载。(错！防火墙很少拦截正常代理，反而引狼入室)
 ❌ 误区 6：把公共 DNS 随意修改为 8.8.8.8 就能解决所有翻墙问题。(错！在梯子环境下公共 DNS 极易遭遇污染)
 ❌ 误区 7：在 Fake-IP 模式下 ping 域名看到 198.18 虚拟 IP 说明电脑被劫持了。(错！属于 Fake-IP 的标准工作机制)
 ❌ 误区 8：TUN 模式开启后就能一劳永逸解决游戏加速与防封。(错！玩外服网游还需节点低丢包与优质专线支持)
 ❌ 误区 9：只要在手机上能用，电脑上不能用就说明电脑网卡物理损坏。(错！移动端与桌面端的应用网络栈截然不同)
 ❌ 误区 10：为了解决局域网打不开，必须把电脑上的 IPv6 彻底永久禁用。(错！在客户端中规范 IPv6 路由即可)
 ❌ 误区 11：在两台电脑上同时开启两个不同的代理客户端能实现网速翻倍。(错！虚拟网卡与路由表会发生致命冲突)
 ❌ 误区 12：分流规则库里的规则数量越多（如 20 万行），翻墙速度就越快。(错！过大规则库会大幅拖慢内核匹配效率)
 ❌ 误区 13：同一个网页加载时有些图片显示日本 IP 有些显示香港 IP 是严重泄露。(错！不同 CDN 资源正常分流)
 ❌ 误区 14：企业内网屏蔽的软件只要开启梯子就能自动连上。(错！企业网关防火墙具备严密的边界安全管控)
 ❌ 误区 15：只要把代理端口从 7890 改成 8080，所有断网问题就会自动消失。(错！端口号与底层网络路由表无关)
 ❌ 误区 16：退出梯子后电脑打不开网页是系统中毒。(错！只需重新打开梯子并正常点击退出，复原系统代理即可)
 ❌ 误区 17：遇到网速慢只要频繁在几个节点之间切来切去就会变快。(错！盲目切换会导致现有 TCP 长连接反复重连)
 ❌ 误区 18：只要买了最贵的专线机场，就绝对永远不可能发生掉线。(错！国际海缆突发故障同样会引发断流)
 ❌ 误区 19：在公司电脑上使用梯子可以神不知鬼不觉规避所有监控。(错！企业安全审计设备可记录底层出口流量)
 ❌ 误区 20：所有的梯子故障都必须联系机场客服才能解决。(错！80% 以上的问题属于本地客户端与系统配置冲突)
```

## 九、常见问题解答 (FAQ)

### Q1：梯子突然连不上了，最先应该排查什么？
**答**：首先确认本地家庭宽带是否欠费断网，然后检查系统时间是否精准同步；若时间正常，临时切换为 [Global 全局模式](/tizi/rule-global-direct/) 观察节点连通性，即可秒级锁定是本地网络、节点故障还是分流规则问题。

### Q2：为什么节点测速全是绿色，但浏览器就是打不开任何网页？
**答**：测速绿仅代表代理内核与海外服务器握手成功。网页打不开通常是因为操作系统的【系统代理 (System Proxy)】未正常启用，导致浏览器的流量根本没有送入代理内核；检查客户端系统代理开关即可。

### Q3：为什么 Global 模式能用，切回 Rule 模式就打不开海外网站？
**答**：这 100% 证实节点完好。问题出在分流规则库中：该网站域名被漏收录导致误判为了国内直连，或规则所指向的策略组选到了超时节点；参考 [《Rule模式失效排查指南》](/tizi/rule-mode-not-working/) 即可修复。

### Q4：为什么电脑上的浏览器能正常翻墙，但 Steam 游戏和 Git 命令行连不上？
**答**：因为游戏和命令行工具不读取桌面的应用层系统代理。必须在客户端中开启 [TUN 虚拟网卡模式](/tizi/tun/) 强制接管底层裸 Socket 与 UDP 数据包，或在命令行中手动配置 `HTTP_PROXY` 环境变量。

### Q5：提示“DNS 解析失败 (DNS lookup failed)”怎么解决？
**答**：进入 Chrome 或 Firefox 设置，关闭其内置的【安全 DNS (DoH)】，并在代理客户端设置中点击【清空 Fake-IP 缓存】；若仍报错，检查客户端的 Bootstrap DNS 配置。

### Q6：开启梯子后，为什么无法打开路由器管理后台 (192.168.1.1) 或 NAS？
**答**：这是因为开启了 TUN 全局接管但未放行局域网私有网段。在客户端设置中勾选【Bypass LAN (绕过局域网)】，并在自定义规则中添加 `IP-CIDR,192.168.0.0/16,DIRECT` 即可。

### Q7：手机（iPhone/Android）开梯子比电脑更稳定吗？
**答**：手机端代理客户端通过系统底层的 VPNService / NetworkExtension 框架运行，天然接管了全系统所有应用的数据包；而电脑端若未开启 TUN 模式，仅接管浏览器流量，因此手机端体验通常更一体化。

### Q8：为什么退出梯子软件后，电脑上的所有网页全部连不上网了？
**答**：这是因为软件异常关闭时，未自动复原操作系统的【系统代理端口】。重新打开代理软件，在托盘右键菜单中正常点击【退出】，或在 Windows 设置中手动关闭“使用代理服务器”即可秒级恢复。
